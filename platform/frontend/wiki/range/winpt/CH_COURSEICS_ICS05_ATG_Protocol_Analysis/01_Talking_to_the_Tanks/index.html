    Background: Automatic Tank Gauges and the TLS-350 Protocol

    What Is an ATG?

    An Automatic Tank Gauge (ATG) is a device that continuously monitors underground storage tanks (USTs) at fuel stations, petroleum terminals, and chemical storage facilities. ATGs measure:

    • Product level: how much fuel is in the tank (gallons or liters)
    • Water level: water contamination at the bottom of the tank
    • Temperature: used to calculate net volume (fuel expands with heat)
    • Ullage: the empty space remaining in the tank
    • Delivery detection: automatic logging when a fuel truck fills the tank
    • Leak detection: statistical analysis of level changes to detect underground leaks

    ATGs are critical for environmental compliance. The US EPA requires continuous leak monitoring for underground fuel tanks. A leaking tank that goes undetected contaminates groundwater with benzene and other carcinogens.

    The Veeder-Root TLS-350

    The Veeder-Root TLS-350 is the most widely deployed ATG in North America. It communicates using a proprietary serial protocol that was later adapted for TCP/IP on port 10001. The protocol uses ASCII commands prefixed with the Start of Header character ^A (SOH, 0x01) followed by a function code.

    Protocol Format

    TLS-350 commands follow the pattern: <SOH>Ixxxxx where <SOH> is the ASCII SOH character (Ctrl-A), I indicates an inventory/report command, and xxxxx is the function code. In practice, sending ^AI20100 from a terminal emulator or piping it through netcat works because most ATG implementations accept the literal two-character sequence ^A as well.

    Common TLS-350 Commands

    Command Function Description
    ^AI20100 Tank Inventory Current levels, volumes, temperatures for all tanks
    ^AI20200 Delivery Report Recent fuel deliveries with timestamps and volumes
    ^AI20300 Leak Test Results Most recent leak detection test outcomes
    ^AI20400 Shift Report Volume changes during operator shifts
    ^AI20500 Pressure Line Leak Pressure line test results
    ^AI20600 Temperature Report Detailed temperature readings per tank

    Internet-Exposed ATGs: A Brief History

    In January 2015, security researcher HD Moore (creator of Metasploit) published research showing that over 5,300 ATGs were directly accessible from the internet on port 10001 with no authentication. These devices responded to inventory queries from any IP address, revealing:

    • Gas station names and locations (from tank product labels)
    • Current fuel levels and capacity (useful for theft planning)
    • Alarm status (indicating which stations had maintenance issues)
    • Tank configuration (number of tanks, products stored)

    Still Exposed Today

    A Shodan search for port:10001 "IN-TANK INVENTORY" still returns hundreds of ATGs connected directly to the internet. The protocol has no authentication mechanism: if you can reach port 10001, you can query (and in some cases configure) the device.

    Why ATGs Matter for Security

    ATGs are interesting targets because:

    1. No authentication: the protocol was designed for serial connections and never added security
    2. Environmental data: leak test results and tank levels are regulated data under EPA rules
    3. Operational intelligence: delivery schedules reveal supply chain patterns
    4. Potential for manipulation: some ATG commands can modify tank labels, alarm thresholds, or calibration data
    5. Pivot point: ATGs sit on OT networks alongside PLCs, RTUs, and HMIs

    Walkthrough

    Step 1: Connect to the ATG Port with Netcat

    The tank simulator exposes the TLS-350 service on port 10001. Start by verifying connectivity.

    nc -zv sim.hexpoint.local 10001
    Expected Output 
    Connection to sim.hexpoint.local 10001 port [tcp/*] succeeded!

    Now open an interactive session. The ATG will not send a banner: it waits for you to issue a command.

    echo -ne '\x01I20100' | nc -w 5 sim.hexpoint.local 10001

    SOH Character

    The \x01 is the ASCII SOH (Start of Header) character. Some ATG implementations also accept the literal text ^A. If the hex escape does not work, try: echo -e '^AI20100' | nc -w 5 sim.hexpoint.local 10001. The -w 5 flag tells netcat to wait 5 seconds for the response before closing.

    Flag Captured!

    Submit the flag found in the Tank 1 name field.

    The flag is embedded in the Tank 1 name field. In a real-world scenario, this field contains the tank label or location identifier (e.g., "UST-1 PREMIUM"). Here it has been replaced with the flag token. The substitution demonstrates that ATG responses leak operational data: including identifiers that could reveal site names, addresses, or internal asset labels.

    Step 2: Parse the Inventory Response

    Take a closer look at each field in the inventory response:

    Field Value Meaning
    VOLUME 8245 GALLONS Current product volume in the tank
    ULLAGE 3755 GALLONS Remaining empty space (capacity minus volume)
    HEIGHT 52.3 INCHES Product height measured by the float probe
    WATER 0.2 INCHES Water level at the bottom (contamination indicator)
    TEMP 62.4 DEG F Product temperature (affects volume calculations)

    Capacity Calculation

    Volume + Ullage = Total Capacity. Tank 1: 8245 + 3755 = 12,000 gallons. Tank 2: 5120 + 6880 = 12,000 gallons. Both tanks have identical capacity, which is typical for standardized UST installations.

    Environmental compliance depends on regular leak detection tests. Query the most recent results.

    Leak Test Interpretation

    The test measures volume change rate over a quiet period (usually overnight). A rate within +/- 0.20 GAL/HR is a PASS. Negative rates may indicate a small leak; positive rates may indicate thermal expansion. Both tanks passed, meaning no detectable leaks, but an attacker who could modify this data could hide a real leak or trigger a false alarm that shuts down operations.

    Step 6: Compare TLS-350 with Modbus

    You have now interacted with two different protocols that expose the same physical process. Consider the similarities and differences:

    Aspect Modbus (TCP/502) TLS-350 (TCP/10001)
    Authentication None None
    Data Format Binary (16-bit registers) ASCII text (human-readable)
    Read Access Function codes 01-04 ^AI2xxxx commands
    Write Access Function codes 05, 06, 15, 16 Configuration commands (vendor-specific)
    Designed For PLC/RTU communication Serial tank gauge reporting
    Encryption None None
    Discovery Shodan dork: port:502 Shodan dork: port:10001 "IN-TANK"

    Two Protocols, Zero Security

    Both protocols were designed for isolated serial networks where physical access was the only security boundary. Neither was intended for TCP/IP networks, yet both have been adapted for Ethernet without adding any security. An attacker on the OT network has two independent paths to the same process data.

    Analysis Questions

    1. How many ATGs are estimated to be exposed on the internet today, and what risks does this create?

    Reveal Answer

    As of recent Shodan scans, several hundred to over a thousand ATGs remain directly accessible on the internet. The number fluctuates as ISPs and operators gradually remediate exposure. Risks include: reconnaissance of fuel station operations, environmental data manipulation (hiding leaks or triggering false alarms), operational disruption (modifying alarm thresholds), and using ATGs as pivot points into connected OT networks. In 2015 HD Moore documented over 5,300; the number has decreased but the problem persists.

    2. What is the fundamental difference between the Modbus and TLS-350 security models?

    Reveal Answer

    There is no fundamental difference: both have no security model at all. Neither protocol implements authentication, authorization, encryption, or integrity checking. The only practical difference is the data format: Modbus uses binary encoding requiring a client library to interpret, while TLS-350 uses ASCII text that is human-readable with netcat. Both are equally vulnerable to eavesdropping, replay, and injection attacks. The "security" of both protocols relies entirely on network-level controls (firewalls, segmentation) that were never part of the protocol specification.

    3. What could an attacker accomplish with write access to an ATG?

    Reveal Answer

    ATG write commands (which vary by vendor and model) could allow an attacker to: (1) modify tank labels to confuse operators; (2) change alarm thresholds so high-level alarms never trigger, enabling overflow; (3) alter calibration data so reported volumes are inaccurate, hiding theft or masking leaks; (4) disable leak detection to allow environmental contamination to go undetected; (5) trigger false alarms to force unnecessary shutdowns and inspection costs. In a worst case, suppressing high-level alarms during a delivery could cause a tank overflow and fuel spill.

    Defensive Recommendations

    Finding Risk Mitigation
    TLS-350 service accessible on the network without authentication High Isolate ATG on a dedicated monitoring VLAN; restrict access to authorized management stations only
    Port 10001 reachable from any host on the OT network High Firewall rules limiting ATG access to the historian and HMI subnets only
    No encryption on ATG communications Medium Deploy a TLS-terminating proxy or VPN tunnel for ATG data if remote monitoring is required
    ATG exposes operational data (volumes, delivery schedules, leak tests) Medium Treat ATG data as sensitive OT intelligence; apply need-to-know access controls
    ATG firmware may support write/configuration commands High Verify vendor documentation for available write commands; disable any unused remote configuration features
    Dual-protocol exposure (Modbus + TLS-350) on same device High Segment each protocol onto separate network interfaces or VLANs with independent access controls

    Key Takeaways

    • Automatic Tank Gauges are critical environmental monitoring devices that use the unauthenticated TLS-350 protocol on TCP port 10001
    • HD Moore's 2015 research revealed thousands of internet-exposed ATGs, and hundreds remain accessible today
    • TLS-350 commands are human-readable ASCII strings that can be sent with nothing more than netcat: no special tools required
    • ATG responses leak operational intelligence including fuel levels, delivery schedules, leak test results, and site identifiers
    • Two protocols, zero security: the same terminal exposes both Modbus (binary, port 502) and TLS-350 (ASCII, port 10001), neither with authentication
    • Defense requires network controls because the protocols themselves have no built-in security; firewalls, segmentation, and monitoring are the only options
