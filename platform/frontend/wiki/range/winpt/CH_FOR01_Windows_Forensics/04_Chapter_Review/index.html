    Chapter F1: Review

    What You Learned

    Over three labs, you built a complete Windows forensics workflow; from external network reconnaissance through SMB credential discovery to full incident investigation on a compromised host. You can now scan Windows targets, enumerate shares and users, connect via RDP, and investigate a breach using native Windows forensic artifacts.

    Each lab introduced new tools and techniques, but the investigative methodology stayed consistent:

    1. Identify what is exposed; services, shares, accounts.
    2. Determine what is accessible; null sessions, weak permissions, found credentials.
    3. Investigate what happened; event logs, persistence mechanisms, attacker artifacts.
    4. Document everything; timelines, IOCs, evidence locations.

    By the final lab, you were applying all four steps simultaneously across multiple artifact categories in a single investigation.

    Windows Forensic Investigation Checklist

    Use this checklist as a step-by-step guide when investigating any compromised Windows system. The checklist generalizes the methodology you practiced in Exercise 1.3 for any incident.

    Phase 1: Initial Assessment

    • Document the date, time, and reason for investigation
    • Record the system hostname, IP address, and OS version
    • Note the current logged-in users
    • Take a screenshot of the desktop for documentation

    Phase 2: Event Log Analysis

    • Open Event Viewer and review the Security log
    • Filter for Event ID 4625 (failed logons); look for brute-force patterns
    • Filter for Event ID 4624 (successful logons); identify suspicious sessions
    • Filter for Event ID 4720 (account creation); find unauthorized accounts
    • Filter for Event ID 4732 (group membership changes); detect privilege escalation
    • Check for Event ID 1102 (log cleared); anti-forensic activity
    • Review the System log for Event ID 7045 (new services installed)
    • Check the Application log for custom or unusual event sources

    Phase 3: Account Investigation

    • Run net user and compare against known-good account list
    • Run net localgroup Administrators: verify every member is authorized
    • For each suspicious account: net user <name>: check creation date, description, last logon
    • Look for accounts mimicking service names (svc_, admin., backup*)

    Phase 4: Persistence Mechanisms

    • Check scheduled tasks: schtasks /query /fo LIST /v
    • Check HKLM Run key: reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
    • Check HKCU Run key: reg query "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
    • Check services: sc query type= all state= all (look for unusual entries)
    • Check startup folders: dir "%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup"
    • Decode any Base64-encoded payloads found in tasks or registry values

    Phase 5: File System Artifacts

    • Check C:\Windows\Temp\ for attacker tools and output files
    • Check user profile temp directories: C:\Users\*\AppData\Local\Temp\
    • Review PowerShell history: ConsoleHost_history.txt in each user profile
    • Look for recently modified files in unusual locations
    • Check the Recycle Bin for deleted evidence

    Phase 6: Documentation

    • Construct a complete attack timeline with timestamps
    • List all IOCs (IPs, domains, filenames, account names, hashes)
    • Document all persistence mechanisms found
    • Record all evidence locations and file paths
    • Recommend remediation actions

    Self-Assessment

    Answer these questions without looking at the answer key below. If you can answer all six confidently, you have internalized the core skills of this chapter.

    1. You run nmap -sS against a Windows machine and see ports 135, 139, 445, 3389, and 5985 open. What service runs on each port? (Exercise 1.1)

    2. What is a null session, and what information can you extract through one? (Exercise 1.2)

    3. You find a file called old_credentials.txt on a public SMB share. What should you do with the credentials inside? (Exercise 1.2)

    4. Event ID 4625 appears 50 times in 2 minutes from the same source IP. What attack is this? (Exercise 1.3)

    5. You find a scheduled task that runs powershell.exe -EncodedCommand <base64>. How do you decode it? (Exercise 1.3)

    6. Why should you check both scheduled tasks AND registry Run keys during an investigation? (Exercise 1.3)

    Self-Assessment Answer Key

    1. Port 135 is RPC Endpoint Mapper, 139 is NetBIOS Session Service, 445 is SMB (file sharing), 3389 is RDP (Remote Desktop), and 5985 is WinRM (remote PowerShell management). Together, these form the standard Windows service profile visible from the network.

    2. A null session is an unauthenticated SMB connection to IPC$. Through null sessions, you can enumerate share names, user accounts, group memberships, and password policies without providing any credentials. Anonymous access works because of legacy Windows compatibility settings that allow unauthenticated connections to the IPC$ share.

    3. Test them against every authenticated service on the target: SMB, RDP, WinRM, and any web applications. Credentials found on one system often work on others due to password reuse. In this exercise, the credentials from IT_Docs granted access to the restricted Backups share.

    4. A brute-force attack. Fifty failed logon attempts in two minutes from a single source IP is a clear pattern of automated password guessing. Filter for Event ID 4624 from the same source to determine if any attempt eventually succeeded.

    5. Use PowerShell: [System.Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('<base64_string>')). The -EncodedCommand parameter accepts UTF-16LE-encoded Base64 strings, so you must decode using Unicode (UTF-16LE), not ASCII or UTF-8.

    6. Attackers use multiple persistence mechanisms for redundancy. If you find and remove a scheduled task but miss the registry Run key, the attacker's payload still executes at next logon. A thorough investigation checks all known persistence locations; scheduled tasks, Run keys, services, startup folders, and WMI event subscriptions; to ensure complete remediation.
