    Exercise WS-1.4: SMB Domain Identification

    Before You Begin

    Exercises WS-1.1 through WS-1.3 focused on DNS-based reconnaissance. Exercise WS-1.4 shifts to a different protocol; SMB (Server Message Block) on port 445; which your port scan in Exercise WS-1.1 confirmed is open on dc01. SMB can reveal domain information and file shares without requiring credentials.

    Prerequisites:

    • Exercises WS-1.1 through WS-1.3 completed (you have a network map and know dc01's services)
    • Active VPN connection to the Open Cyber Range
    • The smbclient command available on your Kali Linux attack box

    Scenario

    Your port scan in Exercise WS-1.1 revealed that SMB (port 445) is open on dc01. SMB is the protocol Windows uses for file sharing, printer sharing, and inter-process communication. When queried without credentials (a "null session"), SMB can still reveal the domain name, the computer name, and sometimes a list of available file shares. Your task is to extract as much information as possible from the SMB service using anonymous access.

    Your Objectives

    1. Use SMB to identify the domain name and the DC hostname
    2. List all SMB shares available on dc01
    3. Access the Public share anonymously and examine its contents
    4. Retrieve the flag from a file on the Public share

    Background: SMB and Null Sessions

    SMB is a network file-sharing protocol that runs on port 445 in modern Windows environments. Beyond file sharing, SMB is also the transport for named pipes used in Remote Procedure Calls (RPC), Windows Management Instrumentation (WMI), and other administrative interfaces. On a Domain Controller, SMB hosts the SYSVOL and NETLOGON shares that distribute Group Policy Objects (GPOs) and logon scripts to domain-joined machines.

    A null session occurs when a client connects to SMB without providing a username or password. Older versions of Windows allowed extensive enumeration through null sessions; listing users, groups, shares, and policies. Modern Windows Server versions (2016 and later) restrict null session access significantly, but share listing and access to explicitly shared folders may still be permitted depending on the server's configuration.

    Even when null sessions are restricted, the SMB protocol's negotiation phase reveals the server's NetBIOS name (computer name) and domain name in cleartext. These values are part of the protocol handshake and cannot be hidden without disabling SMB entirely.

    Tool Primer: smbclient

    The smbclient tool is part of the Samba suite and provides an FTP-like interface for interacting with SMB shares. The tool supports listing shares, connecting to shares, browsing directories, and downloading files.

    Listing shares on a server (null session):

    smbclient -L <target> -N
    Flag Purpose
    -L List available shares on the target
    -N Use a null session (no username or password)

    Connecting to a specific share:

    smbclient //<target>/<share> -N

    Once connected, you have an interactive prompt similar to FTP. Common commands include:

    Command Purpose
    ls List files and directories in the current location
    cd <dir> Change to a different directory
    get <file> Download a file to your local machine
    get <file> - Download a file and print its contents to the terminal
    exit Disconnect from the share

    You can also pass commands directly on the command line using the -c flag, which avoids entering the interactive prompt:

    smbclient //<target>/<share> -N -c 'ls'

    The -c flag is useful for scripting and for performing quick lookups without entering the interactive session.

    Walkthrough

    Step 1: List Available Shares

    List SMB shares with a null session

    Run the following command to list all SMB shares on dc01 using a null session.

    smbclient -L dc01 -N

    The output contains two sections of information. The first section (the header) shows the protocol negotiation results, including the server's name and domain. The second section lists the available shares with their type (Disk, IPC, or Printer) and an optional comment.

    Review the share list carefully. You should see standard DC shares like SYSVOL and NETLOGON, along with any custom shares the administrator has created. Look for a share named Public: shares with generic names like "Public" or "Shared" are often configured to allow anonymous access.

    A typical share listing looks similar to the following:

        Sharename       Type      Comment
    ---------       ----      -------
    NETLOGON        Disk      Logon server share
    SYSVOL          Disk      Logon server share
    ...
(additional shares may be listed; check your own output)

    Step 2: Note the Domain and Server Information

    Examine the output header from the smbclient -L command. The SMB negotiation phase reveals the following information:

    • Server name: The NetBIOS name of the host (e.g., DC01)
    • Domain name: The NetBIOS domain name (e.g., CORP)

    These values appear in the protocol negotiation output even when the null session cannot enumerate additional information. Record both values; the domain name confirms the AD domain you identified through DNS in earlier labs.

    Step 3: Access the Public Share

    Access the Public share and list its contents

    Connect to the Public share using a null session and list its contents.

    smbclient //dc01/Public -N -c 'ls'

    The ls output shows files and directories on the share, along with their size and modification date. Look for any files that might contain useful information; text files, configuration files, scripts, or documents.

    Examine the files listed on the share for anything that might contain the flag.

    Step 4: Retrieve the Flag File

    Retrieve the flag file to the terminal

    Download the contents of flag.txt directly to your terminal.

    smbclient //dc01/Public -N -c 'get flag.txt -'

    The get flag.txt - command downloads the file and prints its contents to standard output (the terminal) instead of saving the file to disk. The output contains the flag for this exercise.

    Save the flag file to disk instead

    If you prefer to save the file locally instead, you can omit the trailing dash:

    smbclient //dc01/Public -N -c 'get flag.txt'

    The file will be saved to your current working directory.

    File Name Size

    Step 5: Interpret the Results

    Review your SMB findings and consider the following:

    • The domain name obtained via SMB should match what you found through DNS in Exercises WS-1.1 and WS-1.2. Cross-referencing information from multiple protocols increases your confidence in the findings.
    • The SYSVOL and NETLOGON shares are standard on every Domain Controller. Authenticated users can access SYSVOL to read Group Policy settings, which can contain credentials, scripts, and configuration details. Anonymous access to SYSVOL is blocked by default, but the share's presence confirms the DC role.
    • A Public share with anonymous access is a misconfiguration. Any files placed on an anonymously accessible share are available to every user on the network, including attackers with no credentials.

    Step 6: Find and Submit the Flag

    The flag for this exercise was in flag.txt on the Public share. Enter the flag value in OCR{...} format on the submission page.

    Analysis Questions

    1. What is a null session, and why is anonymous SMB access a security concern?

    Reveal Answer

    A null session is an SMB connection established without providing a username or password. Anonymous SMB access is a security concern because the attacker can enumerate share names, access files on poorly configured shares, and extract the domain name and server name from the protocol negotiation. On older Windows versions, null sessions could also enumerate user accounts and group memberships. Even on modern systems, any data exposed through null sessions is available to unauthenticated attackers.

    2. Why do the SYSVOL and NETLOGON shares exist on a Domain Controller, and what risks do they present?

    Reveal Answer

    SYSVOL stores Group Policy Objects (GPOs), logon scripts, and other domain configuration data that must be accessible to all authenticated domain members. NETLOGON hosts scripts that run during user logon. These shares present a risk because GPOs in SYSVOL can contain embedded credentials (such as passwords set through Group Policy Preferences, a well-known misconfiguration), and logon scripts may reference internal server paths, database connection strings, or service account names. Authenticated attackers routinely search SYSVOL for credential artifacts.

    3. How does the information gained from SMB complement the DNS reconnaissance performed in Exercises WS-1.1 through WS-1.3?

    Reveal Answer

    DNS reveals hostnames, IP addresses, and service locations. SMB adds the NetBIOS domain name, the server's NetBIOS hostname, the list of shared folders, and access to any files on anonymously accessible shares. Together, the two protocols provide a complete view: DNS maps the network infrastructure, while SMB reveals the server's identity within the Windows domain and any data exposed through file shares.

    4. An attacker finds the ADMIN$ and C$ shares listed but cannot connect to them with a null session. Why do those shares still appear in the listing?

    Reveal Answer

    ADMIN$ and C$ are default administrative shares that Windows creates automatically. The server includes them in the share listing because the listing operation and the access control check are separate actions. The server lists all shares that exist, but enforces access permissions when a client attempts to connect. Administrative shares require local administrator credentials, so null session connections are denied at the access control stage.

    Key Takeaways

    • SMB protocol negotiation reveals the server's NetBIOS hostname and domain name automatically, even when null session enumeration is restricted.
    • Null sessions (smbclient -N) allow share listing and, when misconfigured, file access without any credentials.
    • SYSVOL and NETLOGON are standard DC shares that hold Group Policy and logon script data; high-value targets for authenticated attackers.
    • Anonymously accessible shares are a misconfiguration. Any data on these shares should be considered public to all network users.
    • The smbclient -c flag allows you to run commands without entering an interactive session, which is useful for quick lookups and scripting.
    • You have now confirmed the DC through port scanning (Exercise WS-1.1), mapped DNS forward and reverse records (Exercises WS-1.2 and WS-1.3), and extracted domain information via SMB (Exercise WS-1.4). Exercise WS-1.5 will query the final unauthenticated protocol: LDAP on port 389.
