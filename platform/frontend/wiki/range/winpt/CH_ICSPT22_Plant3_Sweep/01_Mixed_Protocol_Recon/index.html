    Exercise ICSPT-5.4: Plant 3 Sweep

    Engagement Status

    Client Masa Foods, Inc. (fictional)
    Role OT Security Engineer, Plant 3
    Phase Discovery Protocol Literacy (CIP + DNP3) Assessment (full plant sweep) Reporting

    What you know so far: Exercises 5.1 through 5.3 taught you CIP tag enumeration, anomaly detection via polling, and DNP3 integrity polling. You have spoken both protocols that Plant 3 uses. Reyna Alvarado now wants a single, consolidated asset report that covers both the packaging PLC (CIP) and the warehouse power RTU (DNP3). Exercise 5.4 is an independent assessment with no step-by-step walkthrough. You choose the approach.

    Environment Checklist

    Exercise 5.4 reaches both Plant 3 targets. If you completed the environment setup in Exercises 5.1 and 5.3, verify connectivity to both and continue.

    Kali

    nc -zv plc-packaging.masa.local 44818
nc -zv dnp3-rtu.masa.local 20000

    Both must report succeeded!. If either fails, return to the Environment Checklist in Exercise 5.1 (for the CIP PLC) or Exercise 5.3 (for the DNP3 RTU) and repeat the setup steps.

    Scenario

    Reyna Alvarado has scheduled a Plant 3 security review meeting with the plant manager next week. Reyna needs a single-page asset report that answers two questions: how many CIP tags does the packaging PLC expose, and how many binary inputs does the warehouse power RTU report? The report must include the exact tag names from CIP and the breaker states from DNP3. The flag encodes both counts: the number of CIP tags and the number of DNP3 binary inputs.

    Why this matters

    Real OT security assessments rarely cover a single protocol. A plant network runs multiple vendors, multiple protocols, and multiple generations of equipment. The assessor must produce a unified inventory that maps every addressable data point, regardless of protocol. Exercise 5.4 tests your ability to combine the CIP and DNP3 skills from Exercises 5.1 through 5.3 into one coherent sweep. The flag format forces you to count accurately across both targets. Counting is the job: a report that says "several tags" or "some breakers" is useless. An asset report must be exact.

    Background: Multi-Protocol Asset Inventory

    An OT asset inventory maps every addressable data point on a network segment. For Plant 3, the inventory covers two protocols:

    Target Protocol Port Data points
    plc-packaging.masa.local CIP / EtherNet/IP TCP/44818 Tags (named, typed)
    dnp3-rtu.masa.local DNP3 TCP/20000 Binary inputs, analog inputs, counters

    The CIP tag count comes from get_tag_list(). The DNP3 binary input count comes from the Group 1 object header in the integrity poll response. Both counts must be exact integers.

    Flag format

    The flag encodes both counts:

    OCR{plant3_cip<N>_dnp3_<M>}

    Replace <N> with the number of CIP tags and <M> with the number of DNP3 binary inputs. For example, if the PLC exposed 5 tags and the RTU reported 3 binary inputs, the flag would be OCR{________}.

    Tools You Will Need

    Tool Purpose
    pycomm3 CIP tag enumeration on the packaging PLC
    Python socket + struct Raw DNP3 integrity poll on the warehouse RTU
    nmap -n Optional port verification scan

    Suggested Methodology

    Exercise 5.4 is an independent exercise. No step-by-step walkthrough is provided. Instead, here are the stages a methodical assessor would follow. You may execute them in any order.

    Stage 1: CIP Tag Enumeration

    Connect to the packaging PLC with LogixDriver, call get_tag_list(), and count the tags. Record each tag name and type for the asset report.

    Stage 2: DNP3 Integrity Poll

    Connect to the warehouse RTU on TCP/20000, build a Class 0 Read frame (reuse the code from Exercise 5.3), send it, parse the response, and count the binary input points from the Group 1 object header.

    Stage 3: Assemble the Flag

    Combine the CIP tag count and the DNP3 binary input count into the flag format. Double-check both numbers before submitting.

    Stage 4: Asset Report (Optional)

    For practice, write a short console summary that lists all CIP tags with their current values and all DNP3 data points with their current readings. A production report would include timestamps, network addresses, firmware versions, and risk ratings. The console summary is a stripped-down version of that deliverable.

    Output Interpretation

    • The CIP tag count should match what you found in Exercise 5.1. If the count differs, check whether the exercise is running in normal mode (not phantom mode from Exercise 5.2)
    • The DNP3 binary input count comes from the Group 1 object header's range or count field. Count only binary inputs (Group 1), not analog inputs (Group 30) or counters (Group 20)
    • If the flag is rejected, verify that you are using the correct format: OCR{plant3_cip<N>_dnp3_<M>} with no spaces

    Analysis Questions

    1. Plant 3 uses two completely different protocols (CIP and DNP3). What challenge does that create for an OT IDS deployment?

    Reveal answer

    Each protocol requires its own set of IDS dissectors and signature rules. A CIP-aware IDS cannot parse DNP3 frames and vice versa. Plant 3 needs either two specialized IDS deployments or a single platform (Zeek, Nozomi, Claroty) that ships with both CIP and DNP3 parsers. Signature tuning, baseline traffic models, and alert thresholds must be configured independently for each protocol. The operational cost of multi-protocol monitoring is roughly proportional to the number of distinct protocols on the segment.

    2. The packaging PLC uses CIP (name-based tags) and the RTU uses DNP3 (group/index addressing). Which approach gives an attacker more information from the wire?

    Reveal answer

    CIP name-based tags are self-documenting. An attacker who enumerates the tag list learns ConveyorSpeed, PalletCount, and LineState without any external documentation. DNP3 group and index numbers (Group 1 index 0, Group 30 index 2) are meaningful only if the attacker has the outstation's point map. CIP therefore leaks more operational context to an unauthenticated network observer. The trade-off is that DNP3's obscurity is not a security control; it merely raises the effort required for the attacker to understand what each data point controls.

    3. The flag format requires exact counts. Why is precision important in an OT asset inventory?

    Reveal answer

    An OT asset inventory is a security baseline. If the inventory says the PLC has 9 tags and a later audit finds 10, the 10th tag is either a new legitimate addition or an injected artifact (as in Exercise 5.2). Imprecise counts ("about 9" or "several") make change detection impossible. Every data point in the inventory must have an exact count, an exact name, and an exact data type so that deviations are detectable in future audits.

    4. An assessor could scan Plant 3 with nmap before enumerating protocols. What additional information would a port scan provide beyond what Exercises 5.1 and 5.3 already revealed?

    Reveal answer

    A port scan (nmap -n -sS plc-packaging.masa.local dnp3-rtu.masa.local) would confirm which TCP ports are open and whether any unexpected services are listening (HTTP management interfaces, Telnet, FTP, or SNMP). Exercises 5.1 and 5.3 assumed the ports and protocols. A scan removes that assumption and may reveal additional attack surface that the protocol-specific exercises did not cover. In a real engagement, the port scan comes first.

    Defensive Recommendations to Masa

    Finding Risk Mitigation
    Plant 3 runs two unauthenticated protocols (CIP and DNP3) on the same OT LAN Critical Segment CIP and DNP3 traffic into separate VLANs with a firewall between them, limiting lateral movement from one protocol domain to the other
    No unified OT asset inventory exists for Plant 3 High Establish a configuration management database (CMDB) that records every CIP tag and every DNP3 data point, with quarterly reconciliation audits
    Multi-protocol monitoring requires two distinct IDS rulesets Medium Deploy a multi-protocol OT monitoring platform (Nozomi, Claroty, or Dragos) that covers both CIP and DNP3 from a single sensor
    CIP tag names expose process semantics that DNP3 indexes do not Medium Restrict CIP network access more aggressively than DNP3 access because CIP leaks more actionable intelligence to an attacker

    Key Takeaways

    • A real OT assessment covers multiple protocols on the same network segment. Plant 3 uses CIP (TCP/44818) and DNP3 (TCP/20000)
    • CIP tag enumeration and DNP3 integrity polling are complementary skills. Both produce structured data point inventories
    • Exact counts matter. An asset report that says "9 CIP tags and 4 binary inputs" is useful. A report that says "some tags and some inputs" is not
    • Multi-protocol environments require multi-protocol monitoring. A CIP IDS cannot detect DNP3 anomalies
    • The assessor's job is to unify data from different protocols into a single coherent asset inventory that the plant manager can act on
