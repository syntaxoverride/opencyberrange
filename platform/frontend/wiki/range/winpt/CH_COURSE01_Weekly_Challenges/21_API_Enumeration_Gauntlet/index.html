    Challenge 5B: API Enumeration Gauntlet

    Before You Begin

    Challenge 5B is an unguided reinforcement exercise that builds on Challenge 5 (Insecure API Endpoints). Complete that exercise first. Your VPN must be connected and your terminal ready.

    Scenario

    Stonebridge Capital, a wealth management firm in Boston, Massachusetts, launched a client-facing REST API for portfolio tracking. The development team shipped version 2 of the API alongside the documented version 1; but forgot to apply the same access controls.

    Your point of contact, Marcus Webb (CTO), authorized the assessment: "We documented our v1 API and put authentication on every endpoint. But I just learned the team deployed a v2 internally for mobile app development. I need to know if v2 is exposed and what it leaks."

    The assessment spans the API server and a backend database. Tokens are distributed across both systems. You must discover the unprotected API version, extract authentication tokens, use them to access administrative endpoints, and connect to the database to retrieve the final token.

    Your Objectives

    • Enumerate API versions and discover unprotected endpoints
    • Extract authentication tokens from user profile data
    • Use discovered tokens to access administrative API endpoints
    • Discover database credentials from the admin configuration
    • Connect to the backend database and extract the assessment token
    • Assemble and submit the flag

    Flag Format

    Assemble the flag using the tokens in the order you discovered them:

    OCR{________}

    Where token1 is from the API v2 bearer token discovery, and token2 is from the MySQL database query.

    Assembled flag:

    OCR{_____}

    Analysis Questions

    1. Why is API versioning a common source of security vulnerabilities in production environments?

     

     

    2. How does an authorization token extracted from one endpoint enable access to others, and what OWASP category does this fall under?

     

     

    Key Takeaways

    • API version enumeration (/v1/, /v2/, /v3/) is a standard reconnaissance technique; legacy or internal API versions frequently lack production security controls.
    • Bearer token reuse across endpoints means a single leaked token can unlock administrative functionality.
    • Database credential exposure through API configuration endpoints bridges web application compromise to direct database access.
