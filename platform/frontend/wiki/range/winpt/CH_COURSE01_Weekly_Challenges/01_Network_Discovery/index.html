    Exercise 1: Network Discovery

    Before You Begin

    The course begins with a hands-on engagement that mirrors the very first task a security analyst would perform: discovering what services a target machine is exposing to the network. Your VPN (Virtual Private Network) must be connected before you start the lab, because the target machine lives on an isolated network that your browser cannot reach directly. If you have not yet configured your VPN client, review the VPN Setup Guide before continuing.

    Scenario

    Orion TechWorks, a small IT managed services provider based in Boise, Idaho, has hired your firm to perform an external network assessment. The engagement is limited to a single host sitting in the company's DMZ (Demilitarized Zone); a network segment that separates public-facing servers from the internal corporate network.

    Your point of contact is Jake Morrison, the company's Network Administrator. Jake provided the target IP address and a clear directive: "We want to know exactly what is exposed. Scan the server, identify every service, and tell us what an attacker could learn from each one." Jake believes the server runs only SSH (Secure Shell) and a web server, but he admits he has not audited the machine recently.

    Your job is to prove; or disprove; Jake's assumptions. Three security tokens have been placed across the services for you to collect. Combine them to form the final flag and submit it.

    Your Objectives

    • Use Nmap to perform a full TCP (Transmission Control Protocol) port scan against the target host
    • Identify all running services and their version information
    • Interact with each discovered service to extract tokens
    • Discover services running on non-standard ports
    • Combine the tokens and submit the flag

    Background: Port Scanning and Service Interaction

    Port scanning is the process of sending packets to a range of port numbers on a target machine and observing the responses. Every network service; whether it is a web server, a file transfer server, or a remote login daemon; listens on a specific port number. A machine has 65,535 TCP ports available, and any number of them could be running a service. The scanner's job is to find which ports are open and report back.

    Discovering an open port is only the first step. The real value comes from interacting with each service to learn what it reveals. A web server might expose application details in its HTML (HyperText Markup Language) source code. An FTP (File Transfer Protocol) server might allow anonymous logins and serve files to anyone who connects. A custom service on an unusual port might broadcast a banner message the moment a client connects. Each piece of information adds to the picture of the target's exposure.

    Security professionals call the combination of scanning and service interaction enumeration. Enumeration answers the question "what can an outsider learn about the target without any credentials or special access?" The answer often surprises system administrators; as Jake Morrison may be about to find out.

    Tool Primer: Nmap, curl, ftp, and nc

    The primary tool for port scanning is Nmap (Network Mapper). A basic Nmap scan checks the 1,000 most common ports, but that default range can miss services running on higher or non-standard ports. For a thorough assessment, you should specify a wider port range and enable service version detection.

    Full-range scan with version detection

    The command below scans a wide port range and identifies the software behind each open port. You will run the live version of this scan in the walkthrough.

    nmap -sV -p 1-10000 <target_ip>

    Each flag in the command serves a specific purpose:

    • -sV: probe open ports to determine the service name and version number. Without this flag, Nmap guesses the service based on the port number alone. With it, Nmap sends additional requests to confirm what is actually running.
    • -p 1-10000: scan ports 1 through 10,000 instead of the default 1,000. Expanding the range increases the chance of finding services on non-standard ports, such as a custom application listening on port 8888.

    Sample output:

    Starting Nmap 7.94 ( https://nmap.org )
Nmap scan report for 10.100.5.15
Host is up (0.003s latency).
Not shown: 9996 closed ports
PORT     STATE SERVICE     VERSION
21/tcp   open  ftp         vsftpd 3.0.5
22/tcp   open  ssh         OpenSSH 8.9
80/tcp   open  http        nginx 1.18.0
8888/tcp open  unknown

    Reading the columns:

    • PORT: the port number and protocol (TCP in these exercises)
    • STATE: whether the port is open, closed, or filtered
    • SERVICE: what Nmap believes the service to be
    • VERSION: the software name and version number, populated when -sV is used

    Three additional tools help you interact with discovered services:

    curl: make an HTTP request

    curl is a command-line tool for making HTTP requests. Use it to retrieve a web page's content, including HTML source code that may contain hidden information.

    curl http://<target_ip>/

    ftp: connect to an FTP server

    ftp is a command-line FTP client. Use it to connect to an FTP server and browse or download files. Many FTP servers allow anonymous access, meaning you can log in with the username anonymous and any password.

    ftp <target_ip>

    nc: read a service banner

    nc (netcat) is a general-purpose network tool that can connect to any TCP port and display whatever the service sends back. Use it to read banners from unknown or custom services.

    nc <target_ip> 8888

    Walkthrough

    Step 1: Launch the Exercise

    The lab environment runs inside containers on the platform's server. Launching the lab creates a dedicated target machine and assigns it an IP address on your VPN subnet. You need a running lab before any scanning or service interaction will work.

    • Navigate to Exercises and locate the Week 1 challenge
    • Click Launch on "Network Discovery"
    • Wait for the status to change to Running
    • Note the target IP displayed in the Active Lab View

    Step 2: Verify VPN Connectivity

    Verify connectivity to the target

    Before scanning, confirm that your VPN tunnel is active and can reach the target. A failed scan often has nothing to do with the target; the VPN connection may have dropped.

    ping -c 3 <target_ip>

    Replace <target_ip> with the IP shown in the Active Lab View. You should see three replies with round-trip times. If the ping times out, reconnect your VPN before continuing.

    Step 3: Run a Full Port Scan

    Run a full port scan with version detection

    Now run a scan that covers ports 1 through 10,000 with service version detection enabled. The default 1,000-port scan would miss any service running on a non-standard port, so expanding the range is essential for a thorough assessment.

    nmap -sV -p 1-10000 <target_ip>

    The scan may take 30 to 60 seconds to complete. Watch the terminal for the results table. You should discover four open ports: 21 (FTP), 22 (SSH), 80 (HTTP), and 8888 (an unknown or custom service). If you see fewer than four, widen the port range or verify that your VPN connection is stable.

    Step 4: Interact with the HTTP Service

    Retrieve the HTTP page source

    Port 80 is running an HTTP web server. Use curl to retrieve the web page and examine its HTML source for hidden information. Web developers and administrators sometimes leave comments, debug output, or internal references in the page source that are not visible in a browser's normal rendering.

    curl http://<target_ip>/

    Look through the output carefully. Somewhere in the HTML source, you will find a token value. Record the token; you will need it later to assemble the flag.

    Filter the page source for the token

    If the output is long, you can pipe it through grep to search for the word "Token":

    curl -s http://<target_ip>/ | grep -i token

    The matching line isolates the token without scrolling through the full page source.

    Step 5: Interact with the FTP Service

    Connect to the FTP service anonymously

    Port 21 is running an FTP server. Many FTP servers are configured to allow anonymous access, meaning anyone can log in without a real account. Connect to the FTP service and attempt an anonymous login.

    ftp <target_ip>

    When prompted for a username, type anonymous. When prompted for a password, press Enter or type any value; anonymous FTP servers typically accept anything. Once logged in, list the available files:

    ls

    Look for a file that might contain a token (such as token.txt). Download it using the get command:

    get token.txt

    Type bye to disconnect from the FTP server.

    Read the downloaded FTP file

    Read the downloaded file on your local machine.

    cat token.txt

    Record the token value you find inside.

    Step 6: Interact with the Custom Service on Port 8888

    Port 8888 is running an unknown or custom service. Nmap could not identify it by name, which means you need to connect manually and see what it sends back. Many custom services display a banner: a text message sent to any client that connects.

    Grab the banner from the custom service

    Use netcat to connect to port 8888.

    nc <target_ip> 8888

    Read the banner message that appears. The service will display a token as part of its output. Record the token and then press Ctrl+C to disconnect.

    Record Your Findings

    Copy your full Nmap output from Step 3 and paste it below.

    Step 7: Interpret the Results

    Review your findings and consider what they reveal about the target. Four services were exposed on the Orion TechWorks server, but Jake Morrison believed only SSH and a web server were running.

    • Port 22 (SSH): a remote login service. SSH is encrypted and generally considered secure when properly configured. Finding SSH open is expected on a Linux server.
    • Port 80 (HTTP): a web server powered by nginx. The HTML source contained a token. Page source can reveal information not visible in the rendered page.
    • Port 21 (FTP): a file transfer service configured for anonymous access. Anyone on the network could connect and download files without credentials. Jake did not know FTP was running, which means no one was monitoring or maintaining it.
    • Port 8888 (Custom Service): an unidentified service broadcasting a banner with sensitive information. A service on a non-standard port that Jake did not mention is a significant finding.

    Two of the four services; FTP and the custom service on port 8888; were unknown to the system administrator. Unauthorized or forgotten services are among the most common findings in real penetration tests.

    Flag Format

    Assemble the flag using the tokens in the order you discovered them:

    OCR{________}

    Where http is the token from the HTTP page source (Step 4), ftp is the token from the FTP file (Step 5), and banner is the token from the port 8888 banner (Step 6).

    Step 8: Find and Submit the Flag

    You have now collected three tokens: one from the HTTP page source, one from the FTP server, and one from the port 8888 banner. Combine the three tokens to form the complete flag in OCR{...} format.

    Paste the assembled flag into the Submit Flag form on the platform and click Submit. A green confirmation message indicates a correct submission.

    Analysis Questions

    Consider these questions carefully. They reinforce the concepts from the lab and prepare you for more advanced scanning techniques.

    1. Jake believed only SSH and a web server were running. Why is it dangerous to rely on assumptions instead of scanning?

    Reveal Answer

    Services can be installed and started without the administrator's knowledge; by automated scripts, package dependencies, or other team members. A port scan provides objective evidence of what is actually listening on the network. Relying on memory or documentation alone leaves blind spots that attackers will find.

    2. The FTP server allowed anonymous login. Why is anonymous FTP access a security concern, even if the files seem harmless?

    Reveal Answer

    Anonymous FTP means anyone on the network can connect and browse files without authentication. Even if the current files appear harmless, the server could be used to host malicious content, leak sensitive data added later, or serve as a pivot point for further attacks. The lack of authentication also means there is no audit trail connecting downloads to a specific user.

    3. Why did scanning only the default 1,000 ports risk missing the service on port 8888?

    Reveal Answer

    Nmap's default port list contains the 1,000 most commonly used port numbers, and port 8888 is not among them. Services running on non-standard or high-numbered ports are invisible to a default scan. Expanding the port range; or scanning all 65,535 ports; ensures that no listening service goes undetected, though the scan takes longer to complete.

    Key Takeaways

    • Port scanning reveals which services a machine exposes to the network, and scanning beyond the default 1,000 ports is necessary to find services on non-standard ports
    • Service version detection (-sV) confirms what software is actually running on each port, replacing guesses with verified information
    • Anonymous FTP access is a common misconfiguration that allows anyone to connect and browse files without credentials; a finding worth reporting in any assessment
    • Banner grabbing with netcat (nc) lets you read the initial message from any TCP service, including custom or unidentified applications
    • Enumeration: the process of scanning and interacting with services; is the foundation of every penetration test and the skill you will build on throughout this course. Week 2 expands on these techniques with targeted service analysis
