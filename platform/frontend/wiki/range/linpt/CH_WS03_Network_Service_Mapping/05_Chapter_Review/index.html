    Chapter WS03: Review

    What You Learned

    Across four labs, you built a network service mapping methodology that goes beyond individual protocol queries to produce a correlated view of an Active Directory (AD) environment. Each lab added a new data source and a new perspective on the corp.ocr-range.lab infrastructure.

    You started by querying DNS SRV records to discover the standard services AD advertises; Kerberos, LDAP (Lightweight Directory Access Protocol), and Global Catalog (GC). Following a non-standard SRV record to its target revealed infrastructure that port scanning would never find. Conditional forwarder detection exposed a trust relationship with a partner domain, showing that DNS configuration leaks organizational relationships. DHCP scope enumeration revealed network addressing, gateways, and the WPAD (Web Proxy Auto-Discovery) option that creates man-in-the-middle attack opportunities. The final lab tied everything together by correlating DNS, DHCP, and LDAP data into a topology map. Thorough assessment requires multi-protocol analysis.

    The corp.ocr-range.lab assessment demonstrated a methodology that applies to any Windows Server environment. Real penetration tests follow the same progression: enumerate DNS infrastructure, check for cross-domain relationships, profile network addressing, and correlate findings across protocols. The tools change as environments grow in complexity, but the approach remains consistent.

    Key Concepts Revisited

    • SRV records: DNS Service Location records that map a service name to a host, port, priority, and weight. AD creates SRV records automatically for Kerberos, LDAP, and GC. Non-standard SRV records reveal custom or undocumented services.
    • Conditional forwarders: DNS server configurations that route queries for a specific domain to a designated external DNS server. Each forwarder indicates an organizational relationship and a potential trust path.
    • Zone transfers (AXFR): Requests for a complete copy of a DNS zone. Successful transfers provide every record in the zone. Denied transfers indicate the server restricts replication to authorized recipients.
    • DHCP scopes: Address ranges and configuration options that a DHCP server distributes to clients. Scopes reveal subnets, gateways, DNS servers, and custom options like WPAD.
    • WPAD (option 252): A DHCP option that pushes a proxy auto-configuration URL to clients. Historically abused for man-in-the-middle attacks through DHCP spoofing or DNS poisoning.
    • Cross-protocol correlation: Combining data from DNS, LDAP, and DHCP to build a topology map. Inconsistencies between sources reveal misconfigurations, stale objects, and shadow infrastructure.

    Command Cheat Sheet

    The following table summarizes the key commands used across all four labs in this chapter. Use it as a quick reference during assessments or when reviewing for exams.

    Command Purpose
    dig SRV _kerberos._tcp.domain @ns Query Kerberos SRV records
    dig SRV _ldap._tcp.domain @ns Query LDAP SRV records
    dig SRV _gc._tcp.domain @ns Query Global Catalog SRV records
    dig AXFR domain @ns Attempt a full DNS zone transfer
    dig ANY name @ns Query all record types for a name
    dig TXT name @ns Query TXT records for a name
    dig +short TXT name @ns Query TXT records (answer only)
    nmap -sU -p 67 target Scan for DHCP server on UDP port 67
    nmap --script dhcp-discover -sU -p 67 target Targeted DHCP scope enumeration
    nmap --script broadcast-dhcp-discover Broadcast DHCP discovery on local segment
    ldapsearch -x -H ldap://dc -b "base" "(filter)" attrs LDAP query with anonymous bind
    ldapsearch -x -H ldap://dc -b "base" "(objectClass=computer)" cn dNSHostName Enumerate computer objects

    Connect the Dots: What Comes Next

    You now know how to map network infrastructure by correlating DNS, DHCP, and LDAP data. The next chapter; CH_WS04: builds on this foundation by moving from passive mapping to active exploitation of the services you discovered. Understanding where services live and how the network is structured is the prerequisite for targeting those services effectively.

    The DNS SRV records you enumerated in WS-3.1 point to the exact hosts and ports where Kerberos and LDAP accept connections. The conditional forwarder you discovered in WS-3.2 identifies a trust path to a partner domain. The DHCP scope from WS-3.3 defines the network addressing that every client receives. All of this data becomes targeting information when you shift from reconnaissance to exploitation.

    Consider reviewing the command cheat sheet above until you can recall each command and its purpose without looking. Fluency with network mapping tools allows you to focus on analysis rather than syntax during time-limited assessments.

    Self-Assessment Answer Key

    1. Active Directory creates SRV records for _kerberos._tcp (Kerberos authentication on port 88), _ldap._tcp (LDAP directory services on port 389), and _gc._tcp (Global Catalog on port 3268).

    2. The AXFR query type requests a full zone transfer, returning every record in the DNS zone.

    3. A standard forwarder sends all unresolvable queries to a single upstream DNS server. A conditional forwarder routes queries for a specific domain to a designated server, leaving other queries to follow the normal resolution path.

    4. The DHCP server listens on UDP port 67. DHCP clients send requests from UDP port 68.

    5. Option 252 is the WPAD (Web Proxy Auto-Discovery) URL that pushes a proxy auto-configuration script to clients.

    6. The dhcp-discover script sends a targeted DHCP query to a specific server. The broadcast-dhcp-discover script sends a broadcast to discover all DHCP servers on the local network segment.

    7. The dNSHostName attribute on a computer object contains the fully qualified DNS hostname, linking the LDAP object to its DNS A record.

    8. A computer object without a DNS A record may represent a decommissioned machine that was never removed from the directory. Stale computer accounts retain passwords and Service Principal Names (SPNs) in AD. An attacker who can impersonate or reset a stale account may gain domain access with that machine's identity.

    9. The +short flag causes dig to display only the answer data without the question, authority, or additional sections.

    10. The -x flag enables simple authentication, which allows anonymous bind when no credentials are provided.
