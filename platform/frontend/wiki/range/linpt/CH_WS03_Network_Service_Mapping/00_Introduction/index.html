    Chapter WS03: Network Service Mapping

    Why Network Service Mapping Matters

    Active Directory (AD) environments depend on a web of interconnected services to function. Domain Name System (DNS) records advertise where Domain Controllers (DCs), Kerberos servers, and Global Catalog (GC) servers live. Dynamic Host Configuration Protocol (DHCP) scopes define network addressing. Lightweight Directory Access Protocol (LDAP) stores computer objects that represent every machine joined to the domain. A penetration tester who examines only one of these sources sees a fragment of the picture. Correlating all three reveals the full network topology; subnets, trust relationships, and services that administrators may not realize are exposed.

    Chapters WS01 and WS02 introduced you to DNS queries and LDAP enumeration as isolated skills. WS03 raises the bar by combining those skills with new techniques; SRV record analysis, conditional forwarder detection, and DHCP scope reconnaissance; to map infrastructure that no single tool can uncover alone. The exercises in this chapter do not require credentials for DNS and DHCP work. You will perform unauthenticated queries against dc01 and correlate results across protocols.

    In real engagements, incomplete mapping leads to missed attack paths. A conditional forwarder pointing to a partner domain reveals a trust relationship. A non-standard SRV record exposes an undocumented service. A DHCP option containing a Web Proxy Auto-Discovery (WPAD) URL creates a man-in-the-middle opportunity. The four exercises ahead teach you to find all of these.

    What You Will Learn

    The four exercises in this chapter progress from DNS-specific techniques to full network correlation:

    • Discover SRV records that AD uses to advertise services, including non-standard entries that reveal hidden infrastructure
    • Detect DNS conditional forwarders that expose trust relationships and partner domain resolution paths
    • Enumerate DHCP scopes to extract network addressing, gateway assignments, and custom options like WPAD
    • Correlate DNS, DHCP, and LDAP data to build a complete network topology map

    By the end of this chapter, you will have a repeatable methodology for mapping any Windows Server environment from the network layer up.

    How AD Services Interconnect

    Active Directory does not function through a single protocol. Domain-joined clients rely on DNS to locate services, DHCP to obtain addressing, and LDAP to query the directory. Understanding how these protocols interact is essential to mapping the environment.

    The Tools You Will Use

    Each exercise introduces or builds on a specific tool. The table below summarizes what you need.

    Exercise Primary Tool Purpose
    WS-3.1 dig Query DNS SRV and TXT records
    WS-3.2 dig Zone transfer attempts and forwarder detection
    WS-3.3 nmap (NSE) DHCP service discovery and option enumeration
    WS-3.4 dig, ldapsearch Cross-protocol correlation and topology mapping

    The dig command is a DNS lookup tool pre-installed on Kali Linux. Nmap's DHCP discovery scripts send crafted UDP packets to enumerate DHCP responses. The ldapsearch command queries LDAP directories. All three tools are available on your Kali attack machine without additional installation.

    You can verify each tool is ready:

    dig -v
nmap --version
ldapsearch -VV

    Before You Start

    Confirm the following before launching your first exercise:

    • VPN connection to the lab environment is active
    • Terminal open and ready for commands
    • dig installed and accessible (type dig -v to confirm)
    • Nmap installed and accessible (type nmap --version to confirm)
    • ldapsearch available (type ldapsearch -VV to confirm)
    • Notebook or text editor ready for recording findings
    • Access to the OCR platform at the provided URL

    Each lab takes approximately 45 minutes. Work through them in order; Exercise WS-3.4 requires data gathered in the earlier labs.
