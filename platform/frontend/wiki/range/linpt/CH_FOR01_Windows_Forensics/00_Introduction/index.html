    Chapter F1: Windows Forensics

    Why Windows Forensics Matters

    Windows dominates the enterprise landscape. Over 75% of corporate desktops and a significant share of servers run some version of Windows, making it the primary operating system that incident responders encounter during investigations. When an organization suffers a breach, the compromised endpoints are almost always Windows machines. Understanding how Windows stores evidence; in event logs, the registry, scheduled tasks, file system artifacts, and PowerShell history; is not optional for a security professional. It is foundational.

    Attackers know this landscape intimately. They exploit Windows-specific services like SMB and RDP, create persistence through scheduled tasks and registry Run keys, and hide their tracks by clearing event logs. A defender who cannot navigate these artifacts will miss critical indicators of compromise. These three labs take you from external reconnaissance of a Windows target through SMB enumeration and credential discovery to a full incident investigation on a compromised machine ; the same progression you would follow in a real engagement.

    What You Will Learn

    Three labs in this chapter build your Windows forensics skillset. You will:

    • Perform network reconnaissance against a live Windows 10 target using nmap
    • Identify Windows-specific services (SMB, RPC, RDP, WinRM) and understand their security implications
    • Enumerate SMB shares and discover exposed credentials through null session access
    • Use discovered credentials to access restricted file shares
    • Investigate a simulated breach using Windows Event Viewer, scheduled tasks, registry keys, and PowerShell history
    • Decode Base64-encoded attacker payloads
    • Reconstruct an attack timeline from forensic artifacts
    • Assemble a multi-part flag from evidence scattered across the system

    How the Labs Work

    These labs target a shared live Windows 10 machine. Unlike container-based labs where each student gets an isolated environment, all students interact with the same Windows target. The target IP address is displayed in the Active Lab panel when you start the exercise. Exercises 1.1 and 1.2 are performed entirely from your Kali machine using command-line tools (nmap, smbclient, enum4linux). Exercise 1.3 requires an RDP session to the Windows machine for hands-on forensic investigation using native Windows tools.

    Note: These labs target a real Windows 10 machine running on the range. The machine has been deliberately configured with security weaknesses and simulated attack artifacts for educational purposes. Do not attempt to modify the target system configuration, create new user accounts, or delete files; this will disrupt the lab for other students.

    The Meridian Technologies Scenario

    Meridian Technologies is a mid-sized financial services firm with 2,000 employees across three offices. Their IT environment runs primarily on Windows; Active Directory for authentication, Windows 10 desktops, Windows Server 2019 for file shares and applications. After a series of phishing attempts targeting their finance department, Meridian's CISO has engaged your security team to perform a thorough assessment.

    Your engagement begins with external reconnaissance: what can you learn about their Windows infrastructure from the network? You then move to enumeration, probing SMB shares for misconfigurations and exposed data. Finally, Meridian's SOC detects signs of an active breach on one of their workstations, and you pivot from assessment to incident response; investigating the compromised machine to determine what the attacker did, how they persisted, and what data they accessed.

    Over three exercises, you progress from passive observation to active investigation, building the skills that define a competent Windows incident responder.

    Before You Start

    Confirm the following before beginning any lab in this chapter:

    • Your Kali machine is connected to the lab network (VPN active or RangeBox session running)
    • You have terminal access on your Kali machine
    • Target IP noted from the Active Lab panel
    • nmap is installed: nmap --version
    • smbclient is installed: smbclient --version
    • enum4linux is installed: enum4linux (shows usage)
    • xfreerdp is installed: xfreerdp --version (needed for Exercise 1.3)

    Proceed to Exercise 1.1; Windows Reconnaissance when you are ready.
