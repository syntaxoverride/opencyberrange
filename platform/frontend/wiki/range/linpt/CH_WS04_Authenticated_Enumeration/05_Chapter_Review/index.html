    Chapter WS04: Review

    What You Accomplished

    Chapter WS04 shifted the attack perspective from anonymous reconnaissance to authenticated enumeration. Using a single set of low-privilege domain credentials (guest.user / Guest2024#), you accessed information that anonymous connections cannot reach. The four labs demonstrated four distinct categories of data that any authenticated domain user can extract from Active Directory (AD).

    Each lab built on the same credential set while exploring a different attack surface:

    Exercise Technique Key Finding
    WS-4.1 Authenticated SMB share listing Custom shares (IT-Tools) and domain shares (NETLOGON, SYSVOL) hidden from anonymous access
    WS-4.2 GPO template and metadata enumeration SYSVOL file structure, GPO display names, and descriptions via LDAP
    WS-4.3 SPN discovery via LDAP Service accounts vulnerable to Kerberoasting
    WS-4.4 AD ACL analysis Weak DACL granting GenericAll to a low-privilege user

    Core Concepts

    Anonymous vs. Authenticated Access

    The central theme of this chapter is the information gap between unauthenticated and authenticated access. Anonymous enumeration in previous chapters revealed ports, DNS records, and limited Lightweight Directory Access Protocol (LDAP) data. Authenticated enumeration exposed the full share inventory, Group Policy infrastructure, service account landscape, and object-level permissions; all from the same low-privilege account.

    Active Directory is designed to be readable by authenticated users. Domain-joined machines need to read Group Policy Object (GPO) templates from SYSVOL, query Service Principal Names (SPNs) for Kerberos ticket requests, and evaluate Discretionary Access Control Lists (DACLs) for permission enforcement. Penetration testers and attackers take advantage of these design requirements.

    The Value of a Low-Privilege Account

    The guest.user account used throughout this chapter holds no special group memberships and no administrative rights. Despite that limited standing, the account provided access to:

    • All non-administrative SMB shares on the domain controller
    • Every GPO template and its LDAP metadata
    • All SPN registrations in the domain
    • Object attributes on any AD object where permissions allow read access

    Defending against authenticated enumeration requires rethinking the default AD permission model, not patching software vulnerabilities.

    Key Terminology

    The following terms were introduced or used extensively in this chapter. Each definition reflects the term's meaning in the context of AD security assessments.

    Term Definition
    ACE Access Control Entry; a single permission grant or denial within a DACL
    ACL Access Control List; the complete set of permission entries on an AD object
    DACL Discretionary Access Control List; the portion of the security descriptor that defines who can access the object
    GenericAll Full control permission in AD; allows reading, writing, deleting, and modifying permissions
    GPO Group Policy Object; a policy configuration applied to users and computers in AD
    GPP Group Policy Preferences; an extension of GPOs that historically stored encrypted (and recoverable) passwords
    GUID Globally Unique Identifier; a hexadecimal string that uniquely names a GPO folder in SYSVOL
    Kerberoasting An attack that requests Kerberos service tickets and cracks them offline to recover service account passwords
    OU Organizational Unit; a container in AD used to organize objects and delegate permissions
    SPN Service Principal Name; an identifier linking a service instance to a logon account for Kerberos authentication
    SYSVOL A domain controller share that stores GPO templates, scripts, and policy files
    TGS Ticket Granting Service; the Kerberos component that issues service tickets

    Self-Assessment Questions

    Test your understanding of the concepts covered in this chapter. Answer each question before reading the provided explanation.

    1. A colleague says "We found a low-privilege domain account, but there is nothing useful we can do with it." How would you respond?

    A low-privilege domain account grants access to far more information than anonymous access. Authenticated users can enumerate all SMB shares (including custom and hidden shares), read SYSVOL for GPO templates and scripts, query LDAP for SPNs (enabling Kerberoasting), and discover ACL misconfigurations that create privilege escalation paths. Every one of these techniques was demonstrated in this chapter using credentials with no special group memberships.

    2. Explain the relationship between SYSVOL, GPOs, and LDAP in three sentences.

    GPOs consist of two components: a Group Policy Container stored in AD (queryable via LDAP) and a Group Policy Template stored on the SYSVOL share. LDAP provides the metadata; the GPO's display name, description, version, and link information; while SYSVOL provides the files: scripts, preference XML files, and registry policy definitions. Complete GPO enumeration requires querying both sources and cross-referencing the GUID-based folder names with the LDAP display names.

    3. Why is Kerberoasting considered a low-risk, high-reward attack technique?

    Kerberoasting is low-risk because the service ticket request is a normal Kerberos operation that generates no failed logon events and triggers no account lockouts. The password cracking happens offline on the attacker's own hardware, completely invisible to the target organization's monitoring. The reward is potentially high because service accounts often run with elevated privileges and use passwords that are weaker and older than regular user passwords, making them more susceptible to offline cracking.

    4. How does GenericAll on an OU differ from GenericAll on a single user object?

    GenericAll on a single user object grants full control over that one account; the ability to reset its password, modify its attributes, and change its group memberships. GenericAll on an OU grants those same capabilities over every object inside the OU through permission inheritance. A single misconfigured ACL on an OU can compromise dozens or hundreds of accounts, making OU-level permissions far more dangerous than individual object permissions.

    What Comes Next

    The authenticated enumeration techniques in this chapter provide the reconnaissance foundation for active exploitation. Kerberoasting targets identified through SPN discovery can be attacked to obtain service account passwords. Weak DACLs can be exploited to reset passwords and escalate privileges. Files discovered in SMB shares and SYSVOL may contain credentials that unlock additional systems. The progression from passive enumeration to active exploitation is the next phase of the Windows Server attack path.
