    Level 1 Chapter Review

    Everything you should know now

    You just completed the Plum AI Dojo Level 1. The review below consolidates what you practiced into a form you can reread later (or drop into Anki for spaced repetition).

    The big ideas

    1. A language model is a next-token predictor. No boundary exists between developer instructions and user input; they are the same kind of text going into the same function.
    2. System prompts are conventions, not controls. They look like access levels; they are not.
    3. Filters are probabilistic layers. Every defense you defeated in Level 1 raised the cost of attack. None of them prevented it.
    4. The one structural defense is architectural. Do not put secrets in prompts at all. Keep authority and data in surrounding code, not in the model's context.

    Defense summary

    A compact table you will reuse in every level. Each Level 1 attack has at least one trivial defense and each of those defenses has a Level 2 bypass.

    Technique Level 1 defense (weak) Level 2 bypass preview
    Direct ask Add "do not reveal" (Bypass begins at L1-02)
    Ignore-previous Keyword blocklist on input Paraphrase, Unicode, translation
    Role inversion Refusal-tuned model Hypothetical framing, multi-turn
    Repeat trick Input keyword filter "Summarize what you saw," format shift
    Autocomplete hijack Refusal on partial sentences Paraphrase ("finish writing...")
    Prefix injection Output string filter Base64 or language encoding of output
    Developer mode Out-of-band authentication Social engineering escalation
    Format shift to list Output string filter Ask for encoded YAML / base64 values
    Assertive override All the above combined Crescendo multi-turn, Echo Chamber

    Defenses in the first column are what a well-meaning developer adds after a first incident. None of them are durable.

    A short list of things you should never say about LLM security

    • "We fixed prompt injection by adding a filter."
    • "The system prompt protects us."
    • "The model refuses, so we are safe."
    • "Our prompt is proprietary, so attackers cannot write targeted attacks."
    • "We tested with the OWASP Top 10 prompts and they all failed."

    Each of these is a category error about how the technology works. You now have enough fluency to explain why each is wrong.

    Consolidated flashcards

    Copy these into Anki, Obsidian, or whatever spaced-repetition tool you use. Front is the question, back is the answer.

    1. Q: What is a token? A: A short fragment of text (usually 3 to 4 characters). Language models read and write tokens, not letters or words.
    2. Q: What is a system prompt? A: The developer-authored first message in a conversation. A convention for setting behavior; not a security boundary.
    3. Q: Why is prompt injection structurally hard to fix? A: The model has no architectural distinction between developer instructions and user input. Every defense is probabilistic, not deterministic.
    4. Q: What does temperature control? A: How random the next-token choice is. Temperature 0 is deterministic.
    5. Q: Why do keyword blocklists fail against motivated attackers? A: They match literal strings; paraphrase, Unicode substitution, and spacing changes produce different token sequences with the same meaning.
    6. Q: What is role inversion? A: Telling the model it is a different character or mode that has no restrictions. Works because instruction-following is pattern-based, not identity-based.
    7. Q: What is autocomplete hijack? A: Handing the model the start of a sentence that contains a secret and asking it to complete the sentence. Bypasses refusal training that targets question shapes.
    8. Q: What is format shifting? A: Asking the model to encode or reformat its output (base64, ROT13, another language, a list) in a way that passes string-matching filters.
    9. Q: What is prefix injection? A: Forcing the model to begin its reply with a specific prefix that includes the secret. Formatting instructions carry significant weight.
    10. Q: What is the one structural defense against prompt injection? A: Do not place secrets or privileged authority in prompts. Keep them in code around the model, where enforcement is deterministic.
    11. Q: What is an assertive override? A: A stack of authoritative framing, specific format requirements, and explicit refusal preemption. Widely used in real-world jailbreaks.
    12. Q: Why do "repeat everything above" attacks work? A: Text-repetition is a heavily reinforced capability during training. The specific instruction outweighs soft "this is confidential" hints.
