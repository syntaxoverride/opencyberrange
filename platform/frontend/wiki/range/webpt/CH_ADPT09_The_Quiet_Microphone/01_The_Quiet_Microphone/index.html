    Exercise 3.1: The Quiet Microphone

    Before You Begin

    LLMNR (Link-Local Multicast Name Resolution) and NBT-NS (NetBIOS Name Service) are the protocols Windows falls back to when DNS does not resolve a name. A workstation that types \\filesharee (note the typo) into Explorer will: ask DNS, fail, broadcast WHO IS filesharee? over LLMNR/NBT-NS, and authenticate to whoever answers. An attacker on the same broadcast segment running Responder answers, and the workstation hands over a Net-NTLMv2 challenge-response that the attacker can crack offline.

    LLMNR/NBT-NS poisoning is the single most common credential-capture technique in modern internal pentests. Defenders disable LLMNR and NBT-NS via Group Policy. Most don't.

    Tools required: responder, hashcat, john (alternative cracker), pre-installed on Kali.

    Scenario

    Marcus Bell: "LLMNR is the protocol that asks the network 'does anyone know who SHARED-DRIVE is?' If nobody answers, an attacker on the segment can. The Nordport workstation VLAN has a half-broken file server pointer that users mistype every day. Catch one with Responder, crack the hash, and the recovered password is your flag."

    Your scope token is exposed as OCR_SCOPE_TOKEN. The simulated user on the segment is n.morton_<token>; whatever password you crack from their hash is the literal flag string you submit.

    Credentials:

    Username Password
    j.chen Welcome2026#

    (You will not actually use j.chen for the attack; it's only there as your starting foothold.)

    Your Objectives

    • Run Responder on your Kali interface attached to the lab segment
    • Wait for the simulated victim to broadcast a mistyped lookup
    • Capture the Net-NTLMv2 hash for n.morton_<token>
    • Crack the hash with rockyou.txt + best64
    • Submit the recovered plaintext as the flag

    Background: The LLMNR/NBT-NS Fallback Chain

    Windows name resolution is layered. Each layer is tried in order, and any answer wins. The default chain on a domain-joined workstation:

    1. HOSTS file -- C:\Windows\System32\drivers\etc\hosts
    2. DNS; the configured DNS server (the DC, in a domain environment)
    3. LLMNR; multicast UDP/5355 on the local link
    4. NBT-NS; broadcast UDP/137 on the local subnet

    Only DNS is centrally controlled. LLMNR and NBT-NS rely on the link layer: anyone on the same subnet (NBT-NS) or local link (LLMNR) can answer. There is no authentication; the first answer wins.

    What happens when a user mistypes

    User opens File Explorer and types \\filesharee\Public (extra e). Explorer asks the resolver for filesharee. DNS does not have a record (no such host). Explorer falls back:

    LLMNR multicast (UDP 5355) -> ANY: who is "filesharee"?
NBT-NS broadcast (UDP 137) -> ANY: who is "FILESHAREE"?

    Responder, running on an attacker's machine on the same segment, replies:

    LLMNR/NBT-NS reply -> "filesharee is at <attacker_ip>"

    The Windows SMB client connects to <attacker_ip>. The first packets establish the SMB session, including an NTLM challenge-response authentication. The user's credentials are sent in the form of a Net-NTLMv2 hash:

    n.morton::CORP:<server_challenge>:<HMAC_response>:<NTLMv2 client blob>

    That hash is crackable offline against rockyou.txt (or any wordlist) with hashcat mode 5600. If the password is weak, you have it within minutes.

    What Responder does

    Responder runs three things in parallel: 1. Poisoners: LLMNR, NBT-NS, mDNS replies pointing at attacker IP 2. Servers: SMB, HTTP, FTP, IMAP, POP3, MSSQL, LDAP, DNS, AUTH listeners that accept the inbound auth and log the captured hashes 3. Logging: per-protocol logs in /usr/share/responder/logs/

    By default Responder writes captured hashes to /usr/share/responder/logs/Responder-Session.log and per-protocol files like SMB-NTLMv2-SSP-<src_ip>.txt.

    Tool Primer

    Responder basic invocation

    sudo responder -I <interface> -wrf
    Flag Effect
    -I <iface> interface to listen on (typically eth0 in the lab)
    -w start the rogue WPAD proxy server
    -r enable answers for NBT-NS NB queries on the wire
    -f fingerprint OS of host querying

    Optional but useful: - -A analyze mode; listen but do not poison (useful for observation) - -d enable DHCP poisoning - -v verbose

    Responder configuration toggles

    /etc/responder/Responder.conf has switches: - SMB = On/Off - HTTP = On/Off - Challenge = 1122334455667788; fixed challenge for hash cracking compatibility

    The default challenge is fine. The default servers are fine. Change them only when you need to disable a service that conflicts with another local listener.

    Net-NTLMv2 hash format

    n.morton::CORP:1122334455667788:8a4b...:01010000000000...

    Five colon-separated fields: 1. Username 2. (empty; legacy field for domain in NTLMv1) 3. Domain (NetBIOS) 4. Server challenge (fixed 8 bytes) 5. HMAC-MD5 response 6. NTLMv2 client blob

    The first colon-separated chunk on either side of :: is username::domain; that's how you visually identify a Net-NTLMv2 hash on disk.

    hashcat mode 5600

    hashcat -m 5600 hash.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule

    -m 5600 is the Net-NTLMv2 mode. best64.rule is the canonical "small ruleset that covers most password mutations" file. For tougher hashes, escalate to -r rockyou-30000.rule or -a 3 ?u?l?l?l?l?l?d?d (mask attack).

    Walkthrough

    Step 1: Identify Your Interface

    Responder must bind to the interface attached to the victim's broadcast domain. Bind to the wrong interface (for example a separate management VLAN) and your poisoners send replies onto a segment with no listeners. List the interfaces and pick the one with a lab-subnet IP.

    Kali - Find your lab interface

    ip -4 addr show | grep -E '^[0-9]+:|inet '
    Token Effect
    ip -4 addr show List all interfaces with their IPv4 configuration.
    grep -E '^[0-9]+:\|inet ' Show only interface header lines and inet (IPv4) lines; suppress link/MAC details.

    The lab interface is the one with the lab-subnet address (typically 10.100.x.y). Note the name; common values are eth0, ens33, enp0s3. Use whatever your distribution shows.

    Step 2: Confirm the Victim Host Is Reachable

    If you cannot reach the victim's NBT-NS port directly, your poisoning may still work over LLMNR multicast, but it is worth a 5-second sanity probe to confirm you are on the right segment. NetBIOS-over-TCP (TCP 139) is the easiest single-port test.

    Kali - Probe the victim host

    nc -w 5 <victim_ip> 139 </dev/null && echo "NBT-NS port open"
    Token Effect
    -w 5 Five-second connection timeout; do not hang on a dead host.
