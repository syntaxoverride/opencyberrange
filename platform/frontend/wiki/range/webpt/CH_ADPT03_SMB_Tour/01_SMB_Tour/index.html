    Exercise 1.3: SMB Tour

    Before You Begin

    The least glamorous attack in offensive AD is reading files. Operators leak credentials, network diagrams, deploy scripts, and configuration files onto SMB shares constantly. Defenders almost never audit them. Exercise 1.3 asks you to do what every senior pentester does in the first hour of an engagement: tour every reachable share, classify what is in it, and find the document with your scope token in its filename.

    Tools required: netexec, smbclient, manspider, plus optional GUI helper smbmap. All are pre-installed on Kali.

    Scenario

    Marcus Bell: "Half of the breaches I have done in the last five years started by reading a file someone left on a share. Engineering at Nordport keeps a quarterly handover folder that everyone forgets to clean up. Find the document with your scope token in its filename. Open it. Submit the flag inside."

    Your scope token is a four-character lowercase hex string assigned to you by the platform. You see it on the lab dashboard ("Your scope: a7f3") and your Kali workstation has it set as the environment variable OCR_SCOPE_TOKEN.

    Credentials:

    Username Password
    j.chen Welcome2026#

    Your Objectives

    • Enumerate shares on corp-dc01 and corp-dc01
    • Identify shares with read access for j.chen
    • Recursively spider the readable shares
    • Locate the handover document whose filename contains your scope token
    • Read the file, extract the flag, and submit it

    Lab Topology

    All shares for this exercise live on corp-dc01. You attack from Kali; the DC exposes both replicated shares (SYSVOL, NETLOGON) and the department shares (Engineering, Public, Backup-Old).

    flowchart LR
    Kali["Kali Workstation"]
    DC["corp-dc01<br/>SYSVOL, NETLOGON, Engineering, Public, Backup-Old"]
    Kali -- "SMB :445" --> DC

    How Effective Access is Computed

    Two ACLs gate every share read. The effective answer is the AND of both. The flowchart below mirrors the decision the file server makes for every request.

    flowchart TD
    Q["SMB request from j.chen"]
    Q --> S{"Share-level ACL<br/>permits action?"}
    S -- "No" --> D1["Deny<br/>NT_STATUS_ACCESS_DENIED"]
    S -- "Yes" --> N{"NTFS ACL on<br/>file/folder permits?"}
    N -- "No" --> D2["Deny<br/>NT_STATUS_ACCESS_DENIED"]
    N -- "Yes" --> A["Allow<br/>read returns data"]

    Background: SMB Shares and Access Masks

    A share is a named directory exposed over SMB. Every share has two layers of permissions:

    1. Share-level permissions (configured on the share itself: Full, Change, Read, None)
    2. NTFS permissions on the underlying directory (the file-system ACLs)

    The effective permission is the most restrictive of the two. If the share grants Full but NTFS only allows Read, you get Read.

    For enumeration, you mostly care about whether you have any read access at all. netexec --shares reports the share-level masks; smbclient will fail with NT_STATUS_ACCESS_DENIED if NTFS denies you regardless of share permission.

    Common share names and meanings

    Share name Meaning
    ADMIN$ Hidden admin share, mapped to C:\Windows. Requires admin to access.
    C$, D$, etc. Hidden drive shares. Admin-only.
    IPC$ Inter-process communication endpoint. Always present, used for null sessions.
    NETLOGON Replicated logon scripts. Read-only to domain users. Often readable.
    SYSVOL Replicated GPOs and scripts. Read-only to domain users. Often readable.
    Public, Common, Departmental Custom org shares. Usually readable by Domain Users.
    Backup-Old, Archives, Legacy Stale shares. Most credential leaks live here.

    The pattern: read everything once, filter forever

    The first sweep should pull every readable file to local disk. Once everything is local, grep and pattern-matching make finding interesting strings near-instant. Reading files individually over SMB is slow and rate-limited.

    Tool Primer

    netexec for share inventory

    netexec smb <host> -u j.chen -p 'Welcome2026#' -d corp.nordport.local --shares

    Output shows a table:

    SMB    10.x.x.10    445   CORP-DC01     [+] corp.nordport.local\j.chen:Welcome2026#
SMB    10.x.x.10    445   CORP-DC01     [*] Enumerated shares
SMB    10.x.x.10    445   CORP-DC01     Share         Permissions     Remark
SMB    10.x.x.10    445   CORP-DC01     -----         -----------     ------
SMB    10.x.x.10    445   CORP-DC01     ADMIN$                        Remote Admin
SMB    10.x.x.10    445   CORP-DC01     C$                            Default share
SMB    10.x.x.10    445   CORP-DC01     IPC$          READ            Remote IPC
SMB    10.x.x.10    445   CORP-DC01     Engineering   READ            Engineering team share
SMB    10.x.x.10    445   CORP-DC01     Public        READ            Company-wide bulletin board

    A blank Permissions column means access denied. READ means you can list and download. READ,WRITE means you can also drop files (rare on production shares but huge if you find it).

    smbclient interactive mode

    smbclient //corp-dc01/Engineering -U "CORP\j.chen%Welcome2026#"

    At the smb: \> prompt:

    Command Effect
    ls List current directory
    cd <path> Change directory
    recurse on Toggle recursive operations
    prompt off Disable per-file confirmation
    mget * Download all files in current directory
    get <file> Download a single file
    more <file> View a file inline
    exit Quit

    The combination recurse on; prompt off; mget * mirrors a share to your current local directory.

    manspider for content scanning

    manspider recursively spiders shares and greps file contents for arbitrary patterns. Useful for hunting credentials at scale.

    manspider <host> -u j.chen -p 'Welcome2026#' -d corp.nordport.local \
  --content "OCR\{" -e txt,docx,xml,ini,xls,xlsx
    Flag Effect
    --content "OCR\{" regex to match in file contents
    -e txt,docx,xml,ini,xls,xlsx only search these file extensions
    -d domain
    - Hits print the file path and the matching line

    Walkthrough

    Step 1: Note Your Scope Token

    The platform injects your scope token into your Kali container's environment as OCR_SCOPE_TOKEN. Workbook commands reference ${OCR_SCOPE_TOKEN} directly so the same paste works for any student. Confirm the variable is set before you start so a missing token does not waste 20 minutes of attempts.

    Kali - Print scope token

    echo "$OCR_SCOPE_TOKEN"

    What this does:

    • echo prints its arguments. With variable expansion (the $VAR form), bash substitutes the value before echo sees it.
    • Quoted with double-quotes so an empty variable produces an empty (but visible) output rather than a parse error.

    The output should be a four-character lowercase string (example: a7f3, j001, or fsat). If the variable is empty, find your token in the lab dashboard banner ("Your scope: ...") and export it manually with export OCR_SCOPE_TOKEN=<your_token>.

    Step 2: Inventory Shares on Both Hosts

    SMB share enumeration is the first step of any share-credential hunt. The goal is a list of every reachable share with the access mask the authenticating user has on each. netexec --shares gets you the table in one call.

    Kali - Enumerate shares on the DC

    netexec smb <dc_ip> -u j.chen -p 'Welcome2026#' -d corp.nordport.local --shares

    What each option does:

    Flag Effect
    smb Module: speaks SMB on port 445.
    <dc_ip> Target. Accepts a single IP, a CIDR (10.0.0.0/24), or a host file (-t hosts.txt).
    -u j.chen Username for the bind.
    -p 'Welcome2026#' Password. Quote so # and ! survive bash.
    -d corp.nordport.local Domain realm.
    --shares Issue an SRVSVC NetShareEnumAll RPC and parse the results.

    What the columns mean in the output:

    • Share: the share name as registered on the host (e.g. IPC$, Engineering, Public).
    • Permissions: what the authenticated user can do on the share. Possible values: blank (denied), READ, READ,WRITE, or Admin (rare, only for service accounts that are local admin).
    • Remark: the description set by the share's creator. Sometimes useful (helpdesk staff put notes here).

    Note every share where Permissions is non-blank. Skip the standard hidden shares (ADMIN$, C$, D$, IPC$) unless the access shows you have unexpected rights on them.

    Kali - Enumerate shares on corp-dc01

    netexec smb <fileserver_ip> -u j.chen -p 'Welcome2026#' -d corp.nordport.local --shares

    Same flags, different host. The DC and corp-dc01 expose different share sets because the DC has SYSVOL and NETLOGON (replicated GPO content) while corp-dc01 has the actual user-accessible department shares like Engineering, Finance, IT-Tools, and Public. The Engineering share on corp-dc01 is the target for this exercise.

    Step 3: Walk the Engineering Share

    netexec told us WHICH shares are reachable; smbclient lets us browse them interactively. The interactive shell is faster than running 20 separate commands when you are exploring a directory tree.

    Kali - Browse the Engineering share

    smbclient //corp-dc01/Engineering -U "CORP\j.chen%Welcome2026#"

    What each piece does:

    • //corp-dc01/Engineering UNC path: //<host>/<share>. NetBIOS name resolution comes from the lab's DNS (the DC), so corp-dc01 resolves to the right IP if your /etc/resolv.conf points at it; otherwise use the literal IP.
    • -U "CORP\j.chen%Welcome2026#" credential bundle. Format: DOMAIN\user%password. The backslash needs no escaping inside double quotes for bash.

    Once connected, you land at the smb: \> prompt. Useful built-in commands:

    Command Effect
    ls List the current directory.
    cd <path> Change directory. Use forward slashes; backslashes work too.
    recurse on Toggle recursive operations for subsequent ls/mget.
    prompt off Disable per-file confirmation on bulk operations.
    mget * Download every file in current directory to local CWD.
    more <file> Page a file inline without downloading.
    exit or quit Leave the prompt.

    Walk the directory tree:

    ls
cd Handovers
ls

    The Handovers directory holds the per-quarter notes engineering teams typically forget to clean up. One file in there has your token in its filename.

    Step 4: Filter to Your Token

    Walking the entire directory tree by hand is fine for a small share. For a real engagement with hundreds of files, use the non-interactive form of smbclient and let glob matching do the filtering.

    Kali - Find your file with one smbclient command

    smbclient //corp-dc01/Engineering -U "CORP\j.chen%Welcome2026#" \
  -c "cd Handovers; ls *${OCR_SCOPE_TOKEN}*"

    What is new on this invocation:

    • -c "..." non-interactive command string. smbclient runs the semicolon-separated commands and exits, instead of dropping into the interactive prompt. Same shell built-ins as the interactive mode work.
    • ls *${OCR_SCOPE_TOKEN}* shell-glob filter. The * wildcards match any chars; the variable is expanded by BASH (not by smbclient) before the command is sent. So if your token is j001, the literal command sent is ls *j001*.

    The output shows exactly one matching file: engineering_handover_<token>.txt.

    Step 5: Download and Read

    Same non-interactive smbclient pattern, but this time use get to pull the file to local disk, then cat it.

    Kali - Get the file

    smbclient //corp-dc01/Engineering -U "CORP\j.chen%Welcome2026#" \
  -c "cd Handovers; get engineering_handover_${OCR_SCOPE_TOKEN}.txt"
cat engineering_handover_${OCR_SCOPE_TOKEN}.txt

    What each piece does:

    • get <remote-name> download a file from the share to your current local directory. To save under a different name use get <remote> <local>.
    • The variable expansion happens in the BASH layer, not the SMB layer; if OCR_SCOPE_TOKEN is unset, the path becomes engineering_handover_.txt and get will return NT_STATUS_OBJECT_NAME_NOT_FOUND.
    • cat is the standard Unix file printer; nothing SMB-specific.

    The flag string appears inside the file. Submit it on the platform. The flag has the form OCR{<shares_as_directory_listings_theme>} for this exercise, distinct from any other exercise's flag.

    Step 6: Try the Mass-Spider Approach (Bonus)

    When you do not know the filename pattern (which is the realistic case in a fresh engagement), grep file CONTENTS instead of names. manspider is purpose-built for this: it spiders every reachable share, opens supported file types, and runs your regex against the content.

    Kali - Mass content search across the Engineering share

    manspider <fileserver_ip> -u j.chen -p 'Welcome2026#' -d corp.nordport.local \
  --content "OCR\{smb_${OCR_SCOPE_TOKEN}" -e txt

    What each option does:

    Flag Effect
    <fileserver_ip> Target host. Accepts CIDR for multi-host sweeps.
    -u, -p, -d Same credentials as smbclient/netexec.
    --content "<regex>" Regex to match file contents. Supports the full Python re syntax.
    -e txt Restrict to .txt extension. Add more with comma: -e txt,docx,xlsx,csv,ini.

    Other flags worth knowing:

    • -d corp.nordport.local: the domain (already shown above; included in the comparison only if you confuse it with the manspider -d for "search depth").
    • --depth 5: limit recursion depth. Default is unlimited; for very deep shares this prevents runaway scans.
    • --exclude-shares ADMIN$,C$,IPC$: skip the noisy admin shares. Default behaviour skips IPC$ already.

    Manspider returns the file path that contains the matching string. Both approaches (filename glob in step 4, content regex here) reach the same answer; the second one scales when you do not yet know the filename pattern.

    Blue Team Perspective

    Share enumeration and bulk file reads are noisy at the file-server log level even though they look benign on the wire. A SOC pulling the Security log can spot a wide spider in minutes. The mapping below shows what each step lights up.

    Activity Event ID Source
    Connect to share 5140 File server Security log
    File access (object access auditing) 4663 File server Security log
    Detailed file access 5145 File server Security log
    Failed share access 5140 + 4625 File server Security log

    Why a manspider sweep stands out

    A manspider against a single share generates one 5140 per file plus a 4663 burst. On a healthy share with 5,000 files the audit log gains ~10,000 entries in under a minute, which is the same volume a backup agent generates over four hours. SOCs that baseline events per identity per minute on file servers catch the burst.

    Hardening Note

    Defenders cannot disable SMB without breaking file services, but they can shrink the attack surface significantly. The list below is the practical checklist.

    What would have stopped this exercise

    • Scope Domain Users off the Engineering share; replace with Engineering_All.
    • Enforce Object Access auditing on file servers and ship 4663/5140/5145 to the SIEM.
    • Run quarterly internal manspider against all readable shares with a credential-pattern regex; remove or quarantine matches.
    • Disable SMB1 entirely (Set-SmbServerConfiguration -EnableSMB1Protocol $false).
    • Require SMB signing on all servers and enforce it via Group Policy.
    • Tag stale shares with a 30-day archival lifecycle so Backup-Old and Archives cannot accumulate forever.

    Analysis Questions

    1. The Engineering share allows read for Domain Users. From a defender's perspective, what makes that configuration risky, and what is the standard mitigation?

    Reveal Answer

    Granting read on a department share to all Domain Users means every authenticated user in the company, including freshly hired junior staff, contractors, and any compromised account, can read every file. Engineering teams routinely place onboarding docs, deploy scripts, vendor lists, and partial credentials on those shares. The standard mitigation is least-privileged share scoping: each share is restricted to a department-specific group (Engineering_All) rather than Domain Users, NTFS permissions match, and the share contents are audited periodically with tools like manspider against a regex of common credential patterns. A defender who ran manspider --content "password" against their own shares quarterly would catch most of these leaks.

    2. manspider matches against file contents, including binary files like .docx and .xlsx. How does it read inside those compressed Office formats?

    Reveal Answer

    .docx, .xlsx, .pptx are zip archives containing XML files (word/document.xml, xl/sharedStrings.xml, etc.). Manspider unzips each file in memory, concatenates the XML content, and runs the regex against the concatenated text. Older .doc and .xls formats use a binary OLE container, for which manspider relies on a converter (olefile or antiword style libraries). PDFs are extracted with pdftotext under the hood. Encrypted Office documents will not match because the inner XML is encrypted at rest; manspider cannot search them without a known password.

    3. You have read access on the IT-Tools share. Name three patterns to grep for that frequently surface credentials.

    Reveal Answer

    password\s*=, password:\s*, pwd:; match config files and shell scripts. cpassword; the Group Policy Preferences AES-encrypted password attribute (legacy, but still found). connectionString= and DSN=; ODBC and ADO.NET connection strings often embed plaintext passwords. Bonus targets: BEGIN OPENSSH PRIVATE KEY, aws_secret_access_key, client_secret, Authorization: Basic. Combine with manspider's --content flag in a regex alternation: --content "password\s*=|cpassword|connectionString=|client_secret".

    Key Takeaways

    • SMB share enumeration is the highest-yield activity in the first hour of an AD engagement.
    • netexec --shares gives a clean inventory; smbclient browses interactively; manspider greps at scale.
    • Two permission layers (share + NTFS) determine effective access; the most restrictive wins.
    • recurse on; prompt off; mget * is the smbclient idiom to mirror a share to local disk.
    • Tools that grep inside .docx and .xlsx work because those formats are zipped XML.

    Cheat Sheet Recap

    The four operations below are the SMB tour, condensed. Run them on every host that exposes 445 in the first 30 minutes of any AD engagement.

    Goal Command
    Inventory shares with permission masks netexec smb <host> -u <user> -p '<pw>' -d <domain> --shares
    Browse a share interactively smbclient //<host>/<share> -U "<DOMAIN>\<user>%<pw>"
    Mirror a share to local disk smbclient //<host>/<share> -U "..." -c "recurse on; prompt off; mget *"
    Grep file contents at scale manspider <host> -u <user> -p '<pw>' -d <domain> --content "<regex>" -e txt,ini,xml,docx,xlsx

    Spaced Repetition

    Card 1: netexec Share Enumeration

    Q: Write the netexec command to list shares on 10.10.10.10 for corp.local as j.smith / Pass#.

    Answer 
    netexec smb 10.10.10.10 -u j.smith -p 'Pass#' -d corp.local --shares

    Add --filter-shares READ,WRITE to show only shares with at least read access.

    Card 2: smbclient One-Liner Mirror

    Q: Write the smbclient command that recursively downloads all files from \\srv01\Backup-Old using corp.local\j.smith / Pass# to your current directory.

    Answer 
    smbclient //srv01/Backup-Old -U "CORP\j.smith%Pass#" \
  -c "recurse on; prompt off; mget *"

    recurse on enables descent into subdirectories. prompt off skips the per-file confirmation. mget * downloads everything in the current remote directory.

    Card 3: manspider for Credential Hunt

    Q: Write the manspider command to search every reachable share on 10.10.10.10 for the substring "password=" inside .txt, .ini, .xml, and .config files.

    Answer 
    manspider 10.10.10.10 -u j.smith -p 'Pass#' -d corp.local \
  --content "password=" -e txt,ini,xml,config

    Add multiple patterns with |: --content "password=|cpassword|client_secret".

    Card 4: Effective Permission Rule

    Q: A share grants Full Control to Domain Users but the underlying NTFS permission grants only Read. What can a domain user do?

    Answer

    Read only. The effective permission is the most restrictive of share and NTFS. The share-level permission gates SMB-layer access; the NTFS permission gates filesystem-layer access. Both must permit an action for it to succeed. Defenders often leave share-level permissions wide (Full Control to Everyone) and rely on NTFS to do the gating, which works but is harder to audit.
