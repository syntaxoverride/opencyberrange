    Exercise WS-2.4: Computer Account Discovery

    Before You Begin

    Exercise WS-2.3 mapped security groups and their members, identifying which users hold elevated privileges across the domain. Exercise WS-2.4 shifts focus from people to machines; querying the directory for computer objects that represent every domain-joined system. You will need the same Kali Linux machine with anonymous Lightweight Directory Access Protocol (LDAP) access to dc01.

    Prerequisites

    • Exercise WS-2.3 completed (group memberships mapped)
    • VPN active and dc01 reachable
    • ldapsearch available (ldap-utils package)
    • Your user and group membership notes from Exercises WS-2.2 and WS-2.3

    Scenario

    Computer accounts represent every domain-joined machine in the corp.ocr-range.lab environment. Each computer object stores the machine's operating system version, DNS hostname, last logon timestamp, and optional metadata in its attributes. Enumerating computer accounts lets you map the organization's infrastructure, identify the domain controller's computer object, and spot systems running older or potentially vulnerable operating systems.

    Your Objectives

    • Query LDAP for all computer objects in the domain
    • Extract operating system information, DNS hostnames, and descriptions for each machine
    • Identify the domain controller's computer object and confirm its role
    • Locate the lab flag stored in the description attribute of the domain controller's computer account

    Background: Computer Objects in Active Directory

    When a Windows machine joins an Active Directory (AD) domain, the join process creates a computer object in the directory. The computer object stores machine-specific attributes that the domain uses for authentication, policy application, and management. Computer objects belong to the computer objectClass, which is a subclass of the user objectClass; meaning computer accounts inherit many of the same attributes that user accounts have, including description, memberOf, and password-related fields.

    Several attributes on computer objects are especially valuable for reconnaissance. The operatingSystem attribute records the OS name (for example, "Windows Server 2022 Standard"), and operatingSystemVersion stores the build number. Together these attributes let you identify machines running outdated or unpatched operating systems. The dNSHostName attribute contains the fully qualified domain name (FQDN) of the machine, which you can use for direct network targeting. The description attribute, like the description on user and group objects, is a freeform field that may contain administrator notes.

    Domain controllers are particularly easy to spot among computer objects. Their Distinguished Names (DNs) typically place them in the OU=Domain Controllers container, and their operatingSystem attribute identifies a server-class OS. Confirming which computer object belongs to the domain controller validates the targeting information you gathered during Chapter WS01's port scans and DNS enumeration.

    Tool Primer: ldapsearch for Computer Objects

    The command below queries every computer object in the domain and returns the attributes most relevant to infrastructure mapping.

    ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=computer)" cn operatingSystem operatingSystemVersion description dNSHostName

    A typical computer entry in the output looks like the following.

    # WKS01, Computers, corp.ocr-range.lab
dn: CN=WKS01,OU=Computers,DC=corp,DC=ocr-range,DC=lab
cn: WKS01
operatingSystem: <operating system>
operatingSystemVersion: <version>
dNSHostName: wks01.corp.ocr-range.lab
description: <description if set>

    Note: The example above uses placeholder values. Your lab output will show the actual machines, operating systems, and descriptions present in the environment.

    Each attribute line reports a single value. Computer objects that lack a particular attribute will omit that line from the output.

    Attribute What It Reveals
    cn The machine's NetBIOS name (hostname)
    operatingSystem Full OS name; reveals server vs. workstation, edition, and major version
    operatingSystemVersion Build number; useful for identifying patch level
    description Freeform notes set by administrators
    dNSHostName The machine's FQDN; directly usable for network access

    Walkthrough

    Step 1: Enumerate All Computer Objects

    Enumerate all computer objects

    Run the computer enumeration query and save the results for analysis. Even in a small lab environment, capturing the output to a file prevents loss of data if the terminal buffer wraps.

    ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=computer)" cn operatingSystem operatingSystemVersion description dNSHostName > /tmp/computers.ldif

    Count the returned entries to determine how many domain-joined machines exist.

    grep -c "^dn:" /tmp/computers.ldif

    Record the total count. In the lab environment, expect a modest number of machines; the domain controller, one or more member servers, and possibly workstations.

    Step 2: Catalog Operating Systems

    Catalog operating systems

    Extract the operatingSystem attribute from each entry to build an OS inventory. The following command lists every unique operating system string in the results.

    grep "^operatingSystem:" /tmp/computers.ldif | sort -u

    For each unique OS, note how many machines run it. Server operating systems indicate infrastructure servers; workstation operating systems (like "Windows 10 Enterprise" or "Windows 11 Pro") indicate end-user machines.

    grep "^operatingSystem:" /tmp/computers.ldif | sort | uniq -c | sort -rn

    An OS inventory helps you prioritize targets. Machines running older operating systems or server editions that have reached end of life are more likely to have unpatched vulnerabilities.

    Step 3: Identify the Domain Controller's Computer Object

    Identify the domain controller computer object

    The domain controller's computer object typically resides in the OU=Domain Controllers container. Search for entries whose DN includes that OU.

    grep -A5 "OU=Domain Controllers" /tmp/computers.ldif

    Confirm that the cn value matches DC01 and that the operatingSystem shows a Windows Server edition. The dNSHostName should match the hostname you have been using throughout the chapter. Record the full set of attributes for the domain controller's computer object.

    Step 4: Extract DNS Hostnames

    Extract DNS hostnames

    Build a list of all machine FQDNs from the dNSHostName attribute. The FQDN list is a target inventory for later phases where you will connect directly to specific machines.

    grep "^dNSHostName:" /tmp/computers.ldif | awk '{print $2}'

    Save the hostname list to a file for future reference.

    grep "^dNSHostName:" /tmp/computers.ldif | awk '{print $2}' > /tmp/computer_hostnames.txt

    Step 5: Review Computer Descriptions

    Review computer descriptions

    Search the saved output for description attributes on computer objects. Administrators sometimes annotate computer accounts with location information, purpose notes, or configuration details.

    grep -B3 "^description:" /tmp/computers.ldif

    The -B3 flag shows the three lines before each match, which should include the cn and dn values. Read every description carefully. The flag for this exercise is stored in the description attribute of the domain controller's computer object.

    Step 6: Check for OS Version Details

    Check for OS version details

    The operatingSystemVersion attribute provides the Windows build number, which maps to a specific release and patch level. Extract these values and pair them with the machine names.

    grep -B2 "^operatingSystemVersion:" /tmp/computers.ldif

    For Windows Server 2022, the build number 10.0 (20348) is expected. Older build numbers on other machines may indicate systems that have not been updated. Cross-reference build numbers with Microsoft's published build history to determine approximate patch status.

    Step 7: Build an Infrastructure Map

    Combine the data from the previous steps into an infrastructure summary. The map should include each machine's hostname, OS, build version, OU location, and any description content. A table format works well for this summary.

    | Hostname | OS                        | Build      | OU                  | Description         |
|----------|---------------------------|------------|---------------------|---------------------|
| DC01     | Windows Server 2022 Std   | 10.0(20348)| Domain Controllers  | [from output]       |
| ...      | ...                       | ...        | ...                 | ...                 |

    Fill in the table with the actual values from your enumeration. The infrastructure map, combined with the user and group data from earlier labs, provides a complete view of the domain.

    Step 8: Interpret the Results

    Review your infrastructure map and consider what the computer inventory reveals about the environment. The number and types of machines give you a sense of the organization's scale and technology choices. Machines running older operating systems represent higher-risk targets due to the likelihood of unpatched vulnerabilities. The domain controller's computer object confirms the server you have been querying throughout the chapter and anchors your infrastructure map.

    Combine the computer data with your earlier findings. You now know the OU structure (Exercise WS-2.1), the users (Exercise WS-2.2), the group memberships (Exercise WS-2.3), and the machines (Exercise WS-2.4). The remaining piece; the domain password policy; will complete your reconnaissance picture in Exercise WS-2.5.

    Analysis Questions

    1. Why do computer accounts in Active Directory inherit from the user objectClass, and what security implication does that create?

    Reveal Answer

    AD's schema defines the computer class as a subclass of user, meaning computer accounts have passwords, can authenticate to Kerberos, and carry attributes like description and memberOf. The security implication is that computer accounts can be targeted with many of the same attacks used against user accounts; for example, an attacker can request a Kerberos ticket for a computer account or read its publicly accessible attributes.

    2. An attacker discovers a computer object with operatingSystem: Windows Server 2012 R2. Why is that finding significant?

    Reveal Answer

    Windows Server 2012 R2 reached end of extended support in October 2023 and no longer receives security patches. A machine running an unsupported OS is likely to have multiple unpatched vulnerabilities that an attacker can exploit for initial access or lateral movement.

    3. How does the dNSHostName attribute differ from the cn attribute, and when would you use each?

    Reveal Answer

    The cn attribute holds the machine's NetBIOS name (short hostname), while dNSHostName holds the Fully Qualified Domain Name including the domain suffix. The FQDN is needed for DNS-based connections and for protocols that validate hostnames during authentication (such as Kerberos). The short name may suffice for WINS or NetBIOS-based connections within the same network segment.

    Key Takeaways

    • Computer objects are created automatically when a machine joins the domain, and they store operating system metadata, DNS names, and freeform attributes readable through LDAP.
    • The operatingSystem and operatingSystemVersion attributes provide an instant infrastructure audit, revealing which machines may be running outdated or unsupported software.
    • Domain controller computer objects reside in the OU=Domain Controllers container and can be confirmed by matching their hostname and OS to the server you have been querying.
    • The description attribute pattern continues; for the fourth time in this chapter, a freeform text field has contained data that administrators did not expect to be publicly accessible.
    • With users, groups, and computers mapped, Exercise WS-2.5 will extract the domain password policy; the final piece needed to plan credential attacks and assess the organization's security posture.
