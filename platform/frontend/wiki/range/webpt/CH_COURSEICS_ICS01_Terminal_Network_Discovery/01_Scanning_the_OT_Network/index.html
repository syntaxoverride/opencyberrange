    Your task: Discover all hosts on the OT network, identify their services, and find a flag hidden in an exposed Git repository on the documentation server.

    Objective

    Perform a complete network reconnaissance of the Hex Point Bay Terminal OT network. Identify all live hosts, enumerate their services, and discover sensitive information exposure: including a flag hidden in a carelessly exposed Git repository.

    Difficulty: Beginner Estimated time: 20 minutes

    Background: ICS Network Reconnaissance

    Network reconnaissance on an OT (Operational Technology) network is fundamentally different from scanning a corporate IT environment. Here's why:

    Fragile Devices

    Industrial control systems were designed for reliability and determinism, not security. Many ICS devices run on embedded processors with minimal memory and no tolerance for unexpected network traffic. An aggressive port scan that would barely register on a modern web server can crash a PLC or cause a safety system to fault.

    Real-World Caution

    In a live ICS environment, you would never run an aggressive scan without explicit written authorization and coordination with the operations team. Crashing a PLC that controls a chemical reactor or pipeline valve could have catastrophic consequences. In this lab, all devices are simulated: scan freely.

    Different Protocols, Different Ports

    IT networks run on HTTP, SSH, SMB, and RDP. OT networks speak entirely different languages:

    Protocol Port Purpose Found In
    Modbus TCP 502 Register read/write for PLCs PLCs, RTUs, VFDs
    DNP3 20000 Distributed network protocol Power grid, water systems
    EtherNet/IP 44818 Industrial Ethernet Allen-Bradley PLCs
    BACnet 47808 Building automation HVAC, lighting
    TLS-350 (ATG) 10001 Automatic tank gauging Gas stations, fuel terminals
    OPC UA 4840 Unified architecture Modern SCADA systems
    S7comm 102 Siemens S7 communication Siemens PLCs

    In this lab, you will encounter Modbus TCP (502) and TLS-350 ATG (10001): two of the most common ICS protocols in the petroleum industry.

    No Authentication by Default

    Most legacy ICS protocols were designed for isolated networks with no internet connectivity. As a result, they have no authentication mechanism at all. If you can reach the port, you can read, and often write, process data. The lack of authentication is not a bug; it is how these protocols were designed in the 1970s and 1980s.

    Solution Walkthrough

    Independent Mode

    Want to try this on your own? You have the objective, the network topology, and the tools listed above. Skip the walkthrough and come back if you get stuck.

    Step 1: Identify Your Subnet

    After connecting to the lab via VPN, determine your network interface and subnet:

    ip addr show

    Look for your VPN interface (tun0 or similar). Note the IP address and subnet. The OT network will be on a /24 subnet: giving you addresses .1 through .254 to scan.

    Record your subnet

    Write down your subnet base address (e.g., 10.100.5.0/24). You will use it in every exercise throughout this course.

    Step 2: Discover Live Hosts

    Run a ping sweep to find all devices on the OT network:

    nmap -sn {subnet}/24

    Replace {subnet} with your actual subnet base address.

    The -sn flag performs a ping scan only: no port probing. A ping scan is the safest initial scan for an OT environment because it generates minimal traffic.

    Step 3: Service Scan on Discovered Hosts

    Now enumerate what services each host is running. Perform a full-port service version scan:

    nmap -sV -p- 10.100.5.10-14

    Why -p-?

    The -p- flag scans all 65,535 TCP ports, not just the default top 1,000. ICS protocols like Modbus (502) and TLS-350 (10001) are not in nmap's default scan range. Without -p-, you would miss them entirely.

    The all-ports scan takes longer: expect 1-2 minutes. When it finishes, you will see each host with its open ports, services, and version strings.

    What This Teaches

    Notice the port distribution. The open ports map cleanly onto a textbook OT network:

    • Port 502: Modbus TCP, the most common ICS protocol in the world
    • Port 10001: TLS-350 ATG, used at fuel storage facilities everywhere
    • Port 8080: An HMI web interface for operators
    • Port 5432: A process historian storing operational data
    • Port 8888: An internal documentation server

    None of these services require authentication to connect. Every one of them is a potential attack vector.

    Step 4: Banner Grabbing on Key Services

    Use netcat to grab banners from the non-HTTP services. Start with the ATG simulator:

    echo "I20100" | nc -w 5 10.100.5.11 10001

    The string I20100 is a TLS-350 command that requests inventory data from tank 1. If the ATG is running, it will respond with tank level information.

    Step 5: Discover the Exposed Git Repository

    Web servers sometimes serve their entire project directory: including the .git folder if one exists. Serving that folder is a well-known vulnerability called Git directory exposure. Check if the documentation server has one:

    curl -s http://10.100.5.14:8888/.git/HEAD
    Expected Output 
    ref: refs/heads/main

    If you see ref: refs/heads/main, the .git directory is publicly accessible. Public access exposes the entire source code history of the documentation site to anyone who can reach it.

    Why is .git exposure dangerous?

    A .git directory contains:

    • Every version of every file ever committed
    • Commit messages that may reference internal systems, credentials, or ticket numbers
    • Author names and email addresses of developers
    • Configuration files that may have been removed from the live site but still exist in history
    • Secrets (API keys, passwords) that were accidentally committed and later deleted, but still exist in Git history

    Step 6: Retrieve the Flag

    Analysis Questions

    Test your understanding of what you discovered.

    1. Why didn't Modbus (port 502) and TLS-350 (port 10001) appear in a default nmap scan?

    Reveal Answer

    By default, nmap only scans the top 1,000 most common TCP ports. Modbus TCP (502) is included in this default set, but port 10001 is not. To find all ICS services, you must use -p- (all ports) or explicitly specify the ports you want to scan with -p 502,10001,8080,5432,8888. In ICS assessments, always scan the full port range: ICS protocols use non-standard ports that nmap's defaults will miss.

    2. What makes the .git directory exposure particularly dangerous on an OT network documentation server?

    Reveal Answer

    The documentation server likely contains network diagrams, IP addresses, device configurations, default credentials, and operational procedures for the entire facility. With Git history access, an attacker can recover deleted files: meaning even if sensitive content was removed from the live site, it may still exist in previous commits. On an OT network, this information directly enables targeted attacks against PLCs, HMIs, and safety systems.

    3. You connected to the ATG on port 10001 and received tank inventory data without any credentials. Why is this the norm for ICS protocols rather than an exception?

    Reveal Answer

    Most ICS protocols (Modbus, DNP3, TLS-350, BACnet, EtherNet/IP) were designed in the 1970s-1990s for physically isolated serial networks. Security was provided by physical access control: if you could reach the wire, you were authorized. When these protocols were migrated to TCP/IP and connected to routable networks, no authentication was added. The TLS-350 protocol has no concept of passwords or access tokens. Any TCP connection to port 10001 that sends valid commands will receive responses.

    4. All five OT devices are on the same subnet with no segmentation. What risks does this create?

    Reveal Answer

    A flat OT network means that compromising any single device gives an attacker direct network access to every other device. If an attacker compromises the documentation server (the least critical asset), they can directly reach the PLC (the most critical asset). In a properly segmented network, the PLC would be in a separate zone (Purdue Level 1) with firewall rules restricting which devices can communicate with it. The IEC 62443 standard and Purdue Model both require zone-based segmentation for exactly this reason.

    Key Takeaways

    What You Learned

    1. ICS networks use different protocols and ports. Modbus TCP (502), TLS-350 (10001), and other ICS protocols won't appear in default scans. Always use full-port scanning in OT assessments.

    2. ICS protocols have no authentication. You connected to a PLC and an ATG without any credentials. The lack of authentication is by design: these protocols predate modern security concepts.

    3. Git directory exposure is a critical finding. The .git folder on the documentation server leaks the entire commit history, potentially including removed credentials and internal network details.

    4. Flat OT networks are dangerously common. All five devices on the same subnet means compromising one gives access to all. Network segmentation following the Purdue Model is essential for ICS security.

    5. Documentation servers are high-value targets. Internal docs contain network diagrams, IP addresses, procedures, and credentials: everything an attacker needs to plan targeted ICS attacks.
