    Exercise 6: Full Web-to-Root Compromise

    Before You Begin

    Exercise 6 is a capstone challenge that combines every technique from Weeks 9 and 10. You will not receive step-by-step guidance. The attack chain requires directory enumeration (Exercise 10A), SQL injection (Exercise 10B), database pivoting (Exercises 10A and 10B), lateral movement via SSH (Exercise 9A), and SUID privilege escalation (Exercises 9A and 9B). If you have not completed those exercises, go back and finish them before attempting this challenge.

    Your VPN must be connected and your terminal open. Exercise 6 has a 90-minute time limit and hints are locked for the first 30 minutes. Use the first 30 minutes to work independently.

    Scenario

    MedCore Health Systems is a healthcare IT company based in Portland, Oregon. They operate a clinical data platform that connects regional hospitals and clinics for patient record exchange. The company is preparing for a HITRUST certification audit and has engaged your firm, Blackridge Security, for a full-scope penetration test.

    Your point of contact is Dr. Sarah Okafor, Chief Information Security Officer: "We have a public-facing web portal that our partner clinics use to access patient data. Behind that sits a MySQL database and an internal processing server that handles data transformations. The web portal is the only system exposed to the network; the database and internal server should be completely unreachable from outside our application tier."

    Three target servers make up the engagement scope: a web application exposed on port 80, a database server running MySQL on port 3306, and an internal processing server running SSH on port 22. Four assessment markers are distributed across the infrastructure. Retrieve all four and assemble the final flag to demonstrate full compromise.

    Your Objectives

    • Enumerate the web application and discover hidden administrative endpoints
    • Identify and exploit a SQL injection vulnerability to bypass authentication
    • Extract database credentials from the authenticated dashboard
    • Connect to the backend MySQL database and retrieve assessment tokens
    • Discover SSH credentials stored in the database
    • Pivot laterally to the internal server via SSH
    • Escalate privileges on the internal server using a SUID binary
    • Collect all four assessment markers and assemble the complete flag

    Each token maps to a phase of the attack chain. Collect them in order.

    Analysis Questions

    1. Exercise 6 chains five distinct vulnerability classes into a single attack path. If MedCore could fix only one vulnerability to break the entire chain, which one should they prioritize and why?

     

     

    2. The database server stored SSH credentials for the internal processing server in a configuration table. What is the security principle this violates, and what alternative approach should MedCore use for service-to-service authentication?

     

     

    3. Compare the attack surface of this three-server environment to the two-server environments in Exercises 9A and 10A. How does adding a third server change the defender's challenge?

     

     

    4. The internal processing server had a SUID binary that allowed privilege escalation. How would you detect SUID misconfigurations in a production environment before an attacker exploits them?

     

     

    Key Takeaways

    • Multi-phase attack chains reflect real-world penetration tests where each finding enables the next; a single low-severity vulnerability in isolation can become critical when it links to a chain that achieves full compromise
    • Web-to-infrastructure pivoting is a common pattern: a web application vulnerability provides an initial foothold, leaked credentials bridge to backend systems, and misconfigurations on internal servers grant root access
    • Defense in depth means no single layer can be relied upon; even if the SQL injection is fixed, credentials should not be stored in dashboard configuration panels, SSH passwords should not be stored in database tables, and SUID binaries should be audited regularly
    • Skill integration is the core competency being tested: recognizing which tool and technique to apply at each phase, adapting when one approach fails, and maintaining a methodical kill chain from initial reconnaissance through full compromise
