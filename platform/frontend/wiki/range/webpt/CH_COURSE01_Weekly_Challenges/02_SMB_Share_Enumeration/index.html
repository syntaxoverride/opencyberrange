    Exercise 2: SMB Share Enumeration

    Before You Begin

    In Week 1, you learned how to connect to the lab environment, run basic scans, and navigate the platform interface. Those foundational skills; launching a lab, reading an IP address from the Active Lab View, and using the terminal; carry directly into every lab going forward. Make sure your VPN connection is active and that you can reach the lab network before proceeding.

    Scenario

    Blackwell & Associates is a mid-size law firm in Richmond, Virginia. The firm recently migrated its internal file server to a new Linux-based system running Samba, and the IT contractor who configured the server assured the managing partner that "everything is properly locked down."

    Your firm has been hired to verify that claim. Victoria Blackwell, the managing partner, wants to know whether someone from outside the network can access confidential case files. Client confidentiality is the foundation of her practice, and any exposure would be a serious finding.

    The scope of your assessment covers the file server and all exposed SMB (Server Message Block) shares. Two assessment tokens have been placed on the server; one on a public share and one on a restricted share. Your job is to enumerate the shares, discover any exposed information, and retrieve both tokens.

    Your Objectives

    The following list outlines what you need to accomplish during the assessment. Each objective maps to one or more steps in the walkthrough below.

    • Use SMB enumeration tools to discover available network shares
    • Access a public share and identify sensitive information
    • Discover credentials through information disclosure on the public share
    • Use the discovered credentials to access a restricted share
    • Retrieve the flag from the restricted share and submit it

    Background: SMB and Samba

    SMB (Server Message Block) is a network protocol that allows computers to share files, printers, and other resources over a network. Windows systems have used SMB natively for decades. On Linux systems, a software package called Samba implements the SMB protocol, allowing Linux servers to act as file servers for Windows clients; or for anyone who speaks the SMB protocol.

    An SMB server organizes files into shares. Each share is a named folder that the server exposes to the network. Some shares allow anonymous access, meaning anyone can connect without providing a username or password. Other shares require authenticated access, meaning the server checks a username and password before granting entry. Misconfigured servers sometimes expose shares anonymously when they should require credentials, or they leave sensitive data on public shares that was never intended for outside eyes.

    Enumeration is the process of discovering what shares exist, which ones allow anonymous access, and what files live on each share. A penetration tester starts by listing all available shares, connects to any that allow anonymous access, reviews the files for sensitive information (such as credentials or internal documents), and then uses any discovered credentials to access restricted shares.     Tool Primer: smbclient and enum4linux

    Two tools handle the majority of SMB enumeration work on Linux. You will use both in the walkthrough, so take a moment to understand their syntax and purpose before diving in.

    smbclient

    The smbclient tool works like an FTP client for SMB shares. You can list available shares on a server, connect to a specific share, browse directories, and download files.

    List all shares on a server (anonymous)

    The command below queries the server for every share it exposes, without supplying credentials. You will run the live version in the walkthrough.

    smbclient -L //<target_ip> -N
    Flag Purpose
    -L List mode; show all shares on the target server
    //<target_ip> The IP address of the SMB server, prefixed with //
    -N No password; connect anonymously without a password prompt

    Sample output:

    Sharename       Type      Comment
---------       ----      -------
general         Disk      General company information
hr_data         Disk      HR department files
IPC$            IPC       IPC Service

    Each row shows a share name, its type (Disk means a file share, IPC means inter-process communication), and an optional comment describing the share.

    Connect to a specific share (anonymous)

    The command below opens an interactive session against a named share without credentials.

    smbclient //<target_ip>/general -N

    Once connected, the prompt changes to smb: \>. From there, use ls to list files, get <filename> to download a file, and exit to disconnect.

    Connect to a share with credentials

    Supply a username and password in user%password format to open a share that requires authentication.

    smbclient //<target_ip>/hr_data -U hr_svc%Bl4ckw3ll_HR#
    Flag Purpose
    -U Specify a username and password in user%password format

    enum4linux

    The enum4linux tool automates several SMB enumeration tasks at once. Running a single command can reveal share names, usernames, group memberships, and password policies; all without needing to authenticate.

    Basic share enumeration with enum4linux

    The command below automates share discovery and reports the anonymous access level for each share in one pass.

    enum4linux -S <target_ip>
    Flag Purpose
    -S Enumerate shares on the target

    Sample output:

     =============================
|    Share Enumeration on <target_ip>    |
 =============================

        Sharename       Type      Comment
        ---------       ----      -------
        general         Disk      General company information
        hr_data         Disk      HR department files
        IPC$            IPC       IPC Service

[+] Mapping: general - Mapping: OK, Listing: OK
[+] Mapping: hr_data - Mapping: DENIED, Listing: DENIED

    The "Mapping" and "Listing" lines at the bottom reveal access permissions. "OK" means anonymous access is allowed. "DENIED" means credentials are required. The enum4linux tool saves you the step of testing each share individually; it reports which shares are open and which are locked.

    Walkthrough

    Step 1: Launch the Exercise

    Open the platform in your browser and start the exercise environment. The lab takes about one minute to fully initialize.

    • Navigate to Exercises and select the Weekly Challenges track
    • Click Launch on "SMB Share Enumeration"
    • Wait for the status indicator to change to Running
    • Note the target IP displayed in the Active Lab View; you will use it in every command below

    Step 2: Verify SMB Is Running

    Confirm the SMB port is open

    Before attempting any enumeration, confirm that the target server is listening on the SMB port. Port 445 is the standard port for SMB traffic on modern systems.

    nmap -p 445 <target_ip>

    You should see output similar to:

    PORT    STATE SERVICE
445/tcp open  microsoft-ds

    The open state confirms that the Samba service is running and accepting connections. If the port shows as closed or filtered, wait 30 seconds for the lab environment to finish starting and run the scan again.

    Step 3: Enumerate Shares

    Now that you know SMB is running, discover what shares the server exposes. Run both tools to see how each presents the information.

    Enumerate shares with smbclient

    List every share the server exposes, anonymously.

    smbclient -L //<target_ip> -N

    Enumerate shares with enum4linux

    Run the automated enumerator to also see which shares allow anonymous access.

    enum4linux -S <target_ip>

    Both commands should reveal at least two file shares: general and hr_data. The enum4linux output goes a step further by testing whether each share allows anonymous access. Look for "Mapping: OK" next to the general share and "Mapping: DENIED" next to hr_data. The general share is your starting point.

    Step 4: Access the Public Share and Find Credentials

    Browse the public share and download the notes

    The general share allows anonymous access, so connect to it without providing a password. Browsing public shares for sensitive information is a core enumeration technique.

    smbclient //<target_ip>/general -N

    Once you see the smb: \> prompt, list the files:

    smb: \> ls

    You should see a file called onboarding_notes.txt in the listing. Download it:

    smb: \> get onboarding_notes.txt

    Exit the SMB session:

    smb: \> exit

    Read the downloaded notes

    Now read the file on your local machine.

    cat onboarding_notes.txt

    Look through the contents carefully. The onboarding notes contain a service account username and password intended for the HR department. The credentials are:

    • Username: hr_svc
    • Password: Bl4ckw3ll_HR#

    These credentials were left in a file on a publicly accessible share; a classic example of information disclosure. Anyone who connects to the general share can read them.

    Step 5: Confirm the Discovered Credentials

    Validate the discovered credentials

    Before trying to access the restricted share, verify that the credentials you found are valid. Testing against a known share reduces confusion if something goes wrong later.

    smbclient //<target_ip>/IPC$ -U hr_svc%Bl4ckw3ll_HR# -c 'exit'

    The -c 'exit' flag tells smbclient to connect, run the exit command, and disconnect immediately. If the command completes without an error, the credentials are valid. If you see NT_STATUS_LOGON_FAILURE, double-check the username and password for typos.

    Step 6: Access the Restricted Share

    Access the restricted share and download the token

    With confirmed credentials, connect to the hr_data share that was previously denied to anonymous users.

    smbclient //<target_ip>/hr_data -U hr_svc%Bl4ckw3ll_HR#

    You should see the smb: \> prompt, confirming authenticated access. List the files:

    smb: \> ls

    Look for a file that contains the assessment token. Download it:

    smb: \> get assessment_token.txt

    Exit the session:

    smb: \> exit

    Step 7: Extract the Flag

    Read the downloaded token file

    Read the downloaded token file on your local machine to retrieve the flag.

    cat assessment_token.txt

    The flag is in OCR{...} format. Copy the entire flag string, including the OCR{ prefix and the closing }.

    Step 8: Interpret the Results

    Take a moment to review what you accomplished and what each finding means for the client.

    The general share allowed anonymous access. Anyone on the network; or anyone who can reach port 445; can connect and browse its contents without any credentials. On its own, a public share is not always a vulnerability. Some organizations intentionally share non-sensitive documents. The problem here is that the general share contained credentials for a privileged account.

    The onboarding_notes.txt file disclosed the hr_svc service account credentials in plain text. Storing passwords in shared files is a common misconfiguration, especially when IT teams create "quick reference" documents during server setup and forget to remove them afterward.

    The hr_data share required authentication, which means the server was partially configured correctly. However, the credentials on the public share completely undermined that protection. An attacker who enumerated the general share would gain access to hr_data within minutes; exactly as you did.

    Flag Format

    Assemble the flag using the tokens in the order you discovered them:

    OCR{________}

    Where public is the token from the public share (Step 4), and restricted is the token from the restricted share (Step 6).

    Step 9: Submit the Flag

    Navigate to the lab page on the platform. Paste the OCR{...} flag value into the Submit Flag field and click Submit. The platform will confirm whether the flag is correct.

    Analysis Questions

    These questions reinforce the concepts from the walkthrough. Think through each one before reading the answer.

    1. The hr_data share required authentication, but you still accessed it. What was the root cause of the exposure; the share permissions or the information disclosure?

    Reveal Answer

    The root cause was the information disclosure. The hr_data share permissions were configured correctly; anonymous users could not access it. The breakdown occurred because valid credentials were stored in plain text on a share that allowed anonymous access. Fixing the share permissions on hr_data alone would not have solved the problem. The credentials needed to be removed from the general share (or the general share needed authentication as well).

    2. Why is enum4linux useful even though smbclient can also list shares?

    Reveal Answer

    The enum4linux tool tests each share for anonymous access automatically. With smbclient -L, you get a list of share names, but you do not know which ones allow anonymous connections until you try each one manually. The enum4linux tool saves time by reporting the access level for every share in a single command. On a server with dozens of shares, that difference matters.

    3. The credentials used the format hr_svc / Bl4ckw3ll_HR#; a service account with a company-themed password. Why are service account credentials particularly dangerous when exposed?

    Reveal Answer

    Service accounts often have broader access than individual user accounts because they are designed to run automated processes across multiple systems. They also tend to have passwords that rarely change, since changing them could break the services that depend on them. An attacker with service account credentials may be able to access multiple shares, databases, or systems; not a single user's files. The combination of broad access and infrequent password rotation makes service account exposure a high-severity finding.

    Key Takeaways

    • SMB enumeration starts with discovering shares (smbclient -L or enum4linux -S) and identifying which ones allow anonymous access; always check before attempting authentication
    • Information disclosure on public shares is one of the most common ways attackers discover credentials in real assessments; files like onboarding guides, setup notes, and configuration backups frequently contain passwords
    • Service accounts with static, company-themed passwords represent a high-risk finding because they typically have broad access and rarely rotate credentials
    • Layered access controls only work if every layer holds; a locked share is meaningless when the key is sitting on a public share next door
    • Week 3 builds on these skills by introducing credential brute-forcing, where you will test multiple username and password combinations automatically instead of relying on manually discovered credentials
