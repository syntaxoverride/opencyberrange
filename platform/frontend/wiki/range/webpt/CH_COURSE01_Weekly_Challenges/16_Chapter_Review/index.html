    Weekly Challenge Labs: Chapter Review

    What You Learned

    Over 15 weeks, you built a complete offensive security skill set; starting from basic TCP port scanning in Week 1 and ending with a multi-server red team engagement in Week 15. The course followed a deliberate progression: each week introduced one new technique while requiring you to recall and apply techniques from previous weeks. By Week 9, you had already combined enumeration, web exploitation, and privilege escalation into a single attack chain.

    The first four weeks focused on enumeration; the art of discovering what exists on a target network before attempting any exploitation. You learned to scan TCP and UDP ports, enumerate SMB (Server Message Block) shares, extract data through SNMP (Simple Network Management Protocol) community strings, and exploit directory traversal vulnerabilities. These reconnaissance skills formed the foundation for every engagement that followed.

    Weeks 5 through 8 shifted to active exploitation and privilege escalation. You attacked insecure API (Application Programming Interface) endpoints, injected operating system commands through web applications, abused SUID binaries to escalate from a low-privilege user to root, and cracked password hashes offline using John the Ripper. The full penetration test in Week 9 tested whether you could chain all of these skills together without step-by-step guidance.

    The second half of the course expanded into lateral movement, post-exploitation, and defensive analysis. You discovered hidden login pages, pivoted between servers using credentials found in configuration files, harvested encoded data from compromised systems, analyzed packet captures for attack indicators, and wrote IDS (Intrusion Detection System) rules to detect the very attacks you had learned to perform. The capstone in Week 15 combined all three phases into a full red team exercise spanning three servers.

    15 Full red team across multiple servers (capstone) Chains every technique from the course into a realistic multi-server engagement

    Connect the Dots

    Real penetration tests never rely on a single technique. Every engagement follows a pattern: enumerate the target, identify a vulnerability, exploit it, escalate privileges, and then move laterally to reach the actual objective. The 15 weeks of the course mirror exactly the pattern that professional red teams follow on every assessment.

    Consider how the full penetration test in Week 9 demonstrated the power of chaining. You started with an Nmap scan to find open services, identified a vulnerable web application, used command injection or path traversal to gain initial access, and then escalated privileges through SUID abuse or hash cracking. No single technique would have been enough; the attack succeeded because each step provided the information or access needed for the next step.

    The capstone in Week 15 raised the complexity by spanning three servers. Credentials discovered on the first server unlocked access to the second, and data harvested from the second server revealed the path to the third. Lateral movement and post-exploitation skills from Weeks 11 and 12 proved essential, as did the enumeration fundamentals from Weeks 1 through 3. Attackers who can only perform one technique hit a dead end quickly; attackers who can chain techniques reach objectives that defenders assumed were protected by network segmentation.

    Defensive skills from Weeks 13 and 14 complete the picture. Understanding how IDS rules detect command injection, path traversal, and credential reuse helps penetration testers anticipate which actions will trigger alerts. Professional red teams modify their techniques to avoid detection, and that awareness only comes from studying both sides; the attack and the defense. The full course progression, from a basic Nmap scan to writing Suricata rules, gives you the foundation for both offensive and defensive security work.

    Self-Assessment Answer Key

    1. TCP scanning uses a three-way handshake (SYN, SYN-ACK, ACK) to reliably determine whether a port is open, closed, or filtered. UDP scanning is slower because UDP is connectionless; there is no handshake, so Nmap must wait for ICMP "port unreachable" responses (or a lack of any response) to infer port state, and retransmissions add significant delay.

    2. Anonymous SMB access allows anyone on the network to browse shared folders without providing credentials. Misconfigured shares often contain sensitive documents, backup files, configuration files with embedded passwords, and internal network information that an attacker can use to deepen the compromise.

    3. SNMP community strings act as passwords for reading device configuration data, yet many devices ship with the default string "public" and administrators never change it. An attacker who guesses or discovers the community string can extract system details, network interface information, running processes, and installed software; all without authentication.

    4. Path traversal uses ../ sequences in a URL or input field to navigate up the directory tree beyond the intended web root. The web server resolves the relative path and returns files like /etc/passwd or application configuration files that the developer never intended to expose to users.

    5. Authentication verifies who the user is; confirming identity through credentials such as a username and password or an API token. Authorization determines what that authenticated user is allowed to do; an API that authenticates a user but fails to check whether that user has permission to access a specific resource has a broken access control vulnerability.

    6. Command injection gives the attacker direct access to the server's operating system, allowing arbitrary command execution with the privileges of the web application process. XSS (Cross-Site Scripting) executes code in a victim's browser, which limits the attacker to the user's session context rather than granting server-level access.

    7. The SUID (Set User ID) bit causes a binary to execute with the file owner's privileges rather than the privileges of the user who runs it. When a root-owned SUID binary can be manipulated to spawn a shell or read arbitrary files, the attacker gains root-level access. The command find / -perm -4000 2>/dev/null searches the entire file system for files with the SUID bit set.

    8. Offline cracking works against a copy of the password hash file, so the attacker can make billions of guesses per second without any network communication or account lockout mechanism interfering. Weak passwords using common words, short lengths, or predictable patterns fall within minutes because tools like John the Ripper test dictionary words and common mutations first.

    9. Lateral movement allows an attacker to pivot from a compromised system to other systems on the network, often by reusing credentials found in configuration files, databases, or memory. A single compromised web server might seem low-impact on its own, but lateral movement can turn that foothold into access to database servers, domain controllers, or other high-value targets.

    10. IDS rules detect specific attack patterns in network traffic, such as path traversal sequences, SQL injection strings, or command injection payloads. Penetration testers who understand detection logic can anticipate which techniques will trigger alerts and modify their approach to test whether defenses actually catch real-world attacks; making both the testing and the defensive posture stronger.
