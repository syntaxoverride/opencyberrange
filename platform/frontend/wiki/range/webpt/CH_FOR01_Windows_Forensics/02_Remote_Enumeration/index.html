    Exercise 1.2: Remote Enumeration & Data Discovery

    Before You Begin

    this exercise builds directly on Exercise 1.1. You identified SMB (port 445) as an open service on the Windows target. Now you will probe that service to enumerate shares, discover user accounts, and search for exposed credentials. All commands run from your Kali machine; you do not need RDP access for this exercise.

    Make sure you have:

    • Completed Exercise 1.1 (Windows Reconnaissance)
    • Your Kali machine connected to the lab network (VPN active or RangeBox session running)
    • smbclient installed (smbclient --version)
    • enum4linux installed (enum4linux shows usage)
    • Target IP noted from the Active Lab panel; replace <target-ip> in the commands below

    Scenario

    Your reconnaissance in Exercise 1.1 confirmed that the Meridian Technologies workstation exposes SMB on port 445. The assessment lead wants you to determine what data is accessible through SMB; both anonymously and with any credentials you can discover. In enterprise environments, misconfigured SMB shares are one of the most common sources of data exposure. Sensitive files; credentials, network diagrams, configuration backups; are routinely left on shares with overly permissive access controls. Your task is to find out exactly what Meridian has exposed.

    Your Objectives

    • List all SMB shares available on the target
    • Enumerate local user accounts using null session access
    • Access publicly readable shares and examine their contents
    • Discover exposed credentials in accessible files
    • Use found credentials to access restricted shares
    • Retrieve the flag from a protected share

    Background: SMB Protocol and Share Permissions

    SMB (Server Message Block) is the protocol Windows uses for file and printer sharing. When you open \\server\share in Windows Explorer, you are using SMB. The protocol handles authentication, authorization, and data transfer.

    Null Sessions

    A null session is an unauthenticated SMB connection; the client connects without providing a username or password. On older or misconfigured Windows systems, null sessions can enumerate shares, list user accounts, and even read certain shares. Null session access persists because of a legacy Windows feature that allowed anonymous access to IPC$ (Inter-Process Communication) for network browsing.

    Modern Windows versions (10/11, Server 2016+) restrict null sessions by default, but administrators often relax these restrictions for compatibility with legacy applications, monitoring tools, or backup systems.

    Share Types

    Share Type Example Description
    Custom shares Public, IT_Docs Created by administrators for specific purposes. Permissions vary widely.
    Administrative shares ADMIN$, C$ Hidden shares that map to system directories. Require administrator credentials. The $ suffix hides them from casual browsing.
    IPC$ IPC$ Inter-Process Communication share. Used for null sessions, named pipes, and RPC. Not a file share; you cannot browse files on IPC$.

    How Credentials Flow

    When you connect to an SMB share, Windows uses NTLM or Kerberos authentication. The client sends credentials (or a null session request), the server validates them against its local Security Account Manager (SAM) database or Active Directory, and grants or denies access based on the share permissions and NTFS permissions combined.

    The weakest link in this chain is almost always the share permissions. Administrators set NTFS permissions carefully but forget that the share itself also has a permission layer. A share set to "Everyone: Full Control" with restrictive NTFS permissions still allows enumeration of the share contents; and if the NTFS permissions are also misconfigured, full read/write access.

    Tool Primer: SMB Enumeration Tools

    Tool Purpose Key Options
    smbclient Interactive SMB client (like FTP for SMB). Lists shares, browses directories, downloads files. -N (null session, no password), -L (list shares), -U user%pass (authenticate)
    enum4linux Automated Windows/SMB enumeration. Extracts users, groups, shares, password policy, and OS info from null sessions. -U (users), -S (shares), -a (all), -r (RID cycling for users)
    smbmap Maps SMB share permissions. Shows read/write access for each share at a glance. -H (host), -u/-p (credentials), --no-banner
    crackmapexec Multi-protocol offensive tool. Tests credentials across multiple hosts, enumerates shares, and executes commands. smb (protocol), --shares (list shares), -u/-p (credentials)

    For this exercise, you will primarily use smbclient and enum4linux. These tools are pre-installed on most penetration testing distributions including Kali Linux.

    Walkthrough

    Step 1: List Available Shares

    List SMB shares via null session

    Use smbclient to list all SMB shares on the target using a null session (no credentials). The -N flag uses a null session with no password prompt, and -L requests a share listing.

    smbclient -N -L //<target-ip>

    Review the output, which should show both custom and default shares:

    Share Type Description
    Public Disk Public file share
    IT_Docs Disk IT documentation
    Backups Disk System backups
    IPC$ IPC IPC Service
    ADMIN$ Disk Remote Admin
    C$ Disk Default share

    The custom shares (Public, IT_Docs, Backups) are the ones worth investigating. The administrative shares (ADMIN$, C$) require administrator credentials and will be inaccessible with null or low-privilege sessions. IPC$ is not a file share but confirms that null session access is allowed, which means other enumeration tools will also work.

    • Total shares listed: ___
    • Custom shares found: ___
    • Administrative shares: ___
    • Null session to IPC$ allowed (yes/no): ___

    Step 2: Enumerate User Accounts

    Enumerate local user accounts

    Use enum4linux to extract the list of local user accounts via null session. The -U flag requests user enumeration; enum4linux queries the target's SAM database through the IPC$ null session and returns a list of local accounts.

    enum4linux -U <target-ip>

    You should see output similar to:

    user:[Administrator] rid:[0x1f4]
user:[LabUser] rid:[0x3e8]
user:[admin.backup] rid:[0x3e9]
user:[svc_scanner] rid:[0x3ea]
user:[svc_updater] rid:[0x3eb]

    Analyze the account names:

    • Administrator: Built-in admin account. Expected on every Windows system.
    • LabUser: The standard lab account. You will use this account for RDP in Exercise 1.3.
    • admin.backup: Naming convention suggests a backup administrator account. Service accounts with "admin" in the name often have elevated privileges.
    • svc_scanner: A service account, likely for a vulnerability scanner or monitoring tool.
    • svc_updater: Another service account. Service accounts are frequently targeted because they often have weak passwords and broad permissions.

    In a real assessment, this user list would feed directly into a password attack. Knowing valid usernames eliminates half the guesswork in a brute-force attempt.

    • Account names: ___
    • Which accounts appear to be service accounts? ___
    • Which account names suggest elevated privileges? ___

    Step 3: Access the Public Share

    Browse the Public share

    Connect to the Public share using a null session and explore its contents. The -N flag keeps the session anonymous.

    smbclient //<target-ip>/Public -N

    You are now in an interactive SMB session. Use standard commands to list and download files:

    smb: \> ls
smb: \> get readme.txt
smb: \> get network_diagram.txt
smb: \> exit

    The get commands copy each file to your Kali working directory before you exit the session.

    Read the downloaded files

    After downloading the files, examine their contents on your Kali machine.

    cat readme.txt
cat network_diagram.txt

    The readme.txt file contains a welcome message and basic instructions for Meridian employees. The network_diagram.txt contains an ASCII network diagram showing internal subnets, server names, and IP addresses. In a real engagement, network diagrams found on public shares are extremely valuable; they map the entire internal environment without any scanning.

    Record Your Findings

    • Files found on Public share: ___
    • Useful information in readme.txt: ___
    • Network information discovered in network_diagram.txt: ___

    Step 4: Access the IT_Docs Share

    Browse the IT_Docs share

    Connect to the IT_Docs share using a null session, then list and download any files you find.

    smbclient //<target-ip>/IT_Docs -N

    From the interactive prompt, pull down the documents:

    smb: \> ls
smb: \> get old_credentials.txt
smb: \> exit

    The old_credentials.txt filename is an immediate red flag; credentials stored on a readable share are a common real-world exposure.

    Read the exposed credential file

    Examine the downloaded file on your Kali machine.

    cat old_credentials.txt

    The file old_credentials.txt contains credentials for the admin.backup account:

    admin.backup / B@ckup2024#

    The admin.backup credential is a critical finding. An IT documentation share accessible via null session contains plaintext credentials for a backup administrator account. Credential exposure of this kind is alarmingly common in real environments; IT teams store passwords in text files on shared drives for convenience, and those shares are often readable by far more people (or systems) than intended.

    The account name admin.backup combined with a password containing "Backup" and the current year follows a predictable pattern. In a real assessment, you would test these credentials against every service that accepts authentication: SMB, RDP, WinRM, and any web applications.

    • Files found on IT_Docs share: ___
    • Credentials discovered: ___
    • Account name: ___
    • Password: ___

    Step 5: Access the Restricted Share with Found Credentials

    Access the Backups share with found credentials

    The Backups share was listed in Step 1 but likely requires authentication. Test the credentials you discovered in Step 4. The -U user%password syntax provides credentials inline.

    smbclient //<target-ip>/Backups -U admin.backup%'B@ckup2024#'

    If authentication succeeds, you will see the smb: \> prompt. Browse and download the flag:

    smb: \> ls
smb: \> get flag-part.txt
smb: \> exit

    Reaching the prompt confirms the discovered credentials are valid against the protected share.

    Read the flag file

    Read the flag on your Kali machine.

    cat flag-part.txt

    The file contains a token in the form:

    OCR{...}

    The flag confirms that you successfully progressed from anonymous share listing to credential discovery to authenticated access; the exact attack chain that real adversaries follow when targeting Windows file shares.

    Analysis Questions

    1. What is a null session, and why is it dangerous?

    Reveal Answer

    A null session is an unauthenticated SMB connection where the client provides no username and no password. It exploits the IPC$ share, which Windows uses for inter-process communication. When null sessions are allowed, an attacker can enumerate share names, user accounts, group memberships, and password policies ; all without any credentials. The enumerated data feeds directly into targeted attacks: knowing valid usernames enables password spraying, knowing share names reveals where sensitive data is stored, and knowing the password policy tells the attacker exactly what complexity requirements they need to meet. Null sessions should be disabled on all modern Windows systems by setting RestrictAnonymous = 1 in the registry.

    2. How could Meridian have prevented the credential exposure you discovered?

    Reveal Answer

    Multiple layers of defense were missing. First, the IT_Docs share should not have been accessible via null session; requiring authentication would have prevented anonymous access. Second, plaintext credentials should never be stored in files on network shares. Password managers or vault solutions (like CyberArk, HashiCorp Vault, or even KeePass) should be used instead. Third, the admin.backup account password should follow a strong, unique pattern rather than a predictable format like B@ckup2024#. Finally, regular access reviews and file audits would identify sensitive files stored in inappropriate locations before an attacker finds them.

    3. You found credentials on one share and used them to access another. How does this reflect real-world attacks?

    This is a textbook example of credential reuse and privilege escalation through information gathering. Real attackers routinely chain together small findings ; a username from one source, a password from another, a share name from a third ; to build access incrementally. The MITRE ATT&CK framework catalogs this under T1552 (Unsecured Credentials) and T1021.002 (Remote Services: SMB/Windows Admin Shares). In many real breaches, the initial foothold comes not from a sophisticated exploit but from credentials found in a readable file share, a wiki page, a code repository, or a sticky note in a screenshot. Defending against this requires treating credential storage as a security-critical function, not a convenience shortcut.

    Key Takeaways

    • SMB null sessions can expose share listings, user accounts, group memberships, and password policies without any authentication; always test for null session access during a Windows assessment
    • Credential exposure on file shares is one of the most common and impactful findings in real penetration tests; IT teams routinely store passwords in plaintext on network shares
    • The progression from anonymous enumeration to credential discovery to authenticated access is a realistic attack chain that defenders must anticipate
    • Tools like smbclient and enum4linux make SMB enumeration straightforward, but understanding what the results mean is more important than knowing the commands
    • Every user account discovered is a potential target for password attacks; service accounts (svc_*) and backup accounts (admin.backup) are high-value targets because they often have weak passwords and elevated privileges
