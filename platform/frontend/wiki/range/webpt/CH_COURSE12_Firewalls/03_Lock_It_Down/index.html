    Exercise: Lock It Down

    Before You Begin

    You have completed two guided firewall exercises. In Exercise 1 you blocked a single port. In Exercise 2 you built a multi-rule firewall with scanning, logging, and rule management. Now you will apply those skills independently.

    No UFW commands are provided in this walkthrough. You have the policy, the credentials, and the target. The rest is up to you.

    Scenario

    Meridian Property Group is a commercial real estate firm in Houston with 40 employees. Last Friday, the CISO distributed a new Network Hardening Policy after a penetration test found the firm's main Ubuntu server exposing 10 services to the corporate network. The pentest report called it "an open buffet."

    You are Meridian's firewall administrator. Your manager, James Whitfield (Director of IT Operations), forwarded you the policy memo this morning with one line: "Implement Section 4.2 by end of day. Only SSH, HTTP, and HTTPS survive. Everything else gets blocked. No exceptions."

    Policy Memo: Section 4.2

    All internet-facing servers shall run a default-deny inbound firewall policy. Only services with a documented business justification and current security review shall be permitted. The following services are approved for the Meridian primary server: SSH (port 22) for remote administration, HTTP (port 80) and HTTPS (port 443) for the client property portal. All other inbound services must be disabled or blocked at the firewall layer. Compliance verification scans will be conducted weekly by the security team.

    Credentials for the Meridian server:

    Username Password Access
    fwadmin Meridian2026# SSH, sudo (no password required)

    Analysis Questions

    1. MySQL (port 3306) is blocked from the network, but the client property portal on port 80 still works. How is the web application accessing the database?

    Reveal Answer

    The web application connects to MySQL over localhost (127.0.0.1), not over the network. UFW only filters traffic arriving from external interfaces. Connections between processes on the same machine use the loopback interface, which UFW allows by default. Blocking port 3306 externally prevents remote attackers from connecting to the database directly, while the local web application continues to function normally.

    2. The pentest report flagged RDP (port 3389) as a "critical finding." Why is an open RDP port considered more dangerous than an open FTP port?

    Reveal Answer

    RDP provides full graphical desktop access to the server. An attacker who brute-forces or guesses RDP credentials gains interactive control of the entire machine: they can browse files, install software, pivot to other systems, and exfiltrate data. FTP is limited to file access within the FTP root directory. While anonymous FTP is a data leak risk, RDP is a complete compromise vector. RDP is also a frequent target for ransomware operators, who use it as their primary entry point in a large percentage of attacks.

    3. Port 25 (SMTP) was described as an "open relay risk." What could an attacker do with an open SMTP relay, and why does the firm not need it?

    Reveal Answer

    An open SMTP relay allows anyone on the internet to send email through the server, forging the sender address. Attackers use open relays to send spam and phishing emails that appear to come from the victim's domain, damaging the firm's reputation and potentially getting their mail server blacklisted. Meridian uses Microsoft 365 for email, so no mail flows through this server. The Postfix service was likely installed as a dependency or during initial setup and never removed.

    4. You blocked seven ports but only wrote three allow rules. Why didn't you need seven deny rules?

    Reveal Answer

    The default deny incoming policy acts as a catch-all for any traffic that does not match an explicit allow rule. Every port without an allow rule is automatically blocked. Writing individual deny rules for each port would be redundant and harder to maintain. The default-deny approach is more secure because it also blocks any new service that might be installed in the future, without requiring a manual rule update.

    5. James asks you to write a weekly compliance check script. What single command would verify that only ports 22, 80, and 443 are open?

    Reveal Answer 
    nmap -p 20,21,22,25,80,443,3306,3389,8080,8443 <server_ip> | grep open

    The output should show exactly three lines: 22/tcp, 80/tcp, and 443/tcp. Any additional open port indicates a policy violation. In a production environment, this would be wrapped in a cron job that emails the security team if the output changes.

    Key Takeaways

    • Reading a security policy and translating it into firewall rules is a core skill for any network or systems administrator
    • A default-deny policy with targeted allow rules is easier to maintain and more secure than writing individual deny rules for every unwanted port
    • Compliance verification requires scanning from outside the firewall, not just reading the rule list on the server
    • Services like MySQL and Postfix are often installed as dependencies and forgotten, creating unnecessary attack surface
    • RDP and SMTP are high-value targets for attackers and should be blocked unless there is an explicit, documented business need
    • Packet counters provide server-side evidence that the firewall is actively enforcing the policy
