    Chapter WS04: Authenticated Enumeration

    The Shift from Anonymous to Authenticated Access

    Previous chapters focused on what an unauthenticated attacker can see: open ports, DNS records, anonymous LDAP queries, and null-session SMB shares. Those techniques reveal the outline of an Active Directory (AD) environment, but they leave most of the directory hidden behind authentication barriers. Authenticated enumeration changes the equation entirely.

    A single set of low-privilege domain credentials unlocks a vast amount of information that anonymous access cannot reach. Domain users can list every share on a file server, read Group Policy Object (GPO) templates stored on SYSVOL, query Service Principal Names (SPNs) registered in the directory, and inspect Discretionary Access Control Lists (DACLs) on AD objects. None of these actions require administrative privileges; any authenticated domain user can perform them by default.

    Why Low-Privilege Credentials Matter

    In real-world engagements, attackers obtain low-privilege credentials through many paths: password spraying, credential stuffing, phishing, or discovering hardcoded passwords in scripts and configuration files. The guest.user account used throughout this chapter represents exactly that scenario; a basic domain account with no special group memberships or administrative rights.

    The power of authenticated enumeration lies in what Active Directory shares with every domain member by design. Microsoft built AD to be readable by authenticated users so that workstations, applications, and services can function properly. Group policies must be readable so machines can apply them. SPNs must be queryable so Kerberos authentication works. DACLs must be accessible so the operating system can enforce permissions. Penetration testers and attackers take advantage of these design decisions to map the entire domain from a single compromised account.

    What You Will Learn

    By the end of this chapter, you will be able to:

    • Authenticate to SMB shares using domain credentials and compare results against anonymous access
    • Navigate the SYSVOL share to read GPO templates, scripts, and policy settings
    • Query LDAP for accounts with registered SPNs and assess Kerberoasting attack surface
    • Analyze AD object permissions to identify weak DACLs that create privilege escalation paths

    The information gathered in this chapter directly feeds later attack stages. Share contents may reveal credentials or sensitive data. GPO templates may contain scheduled task passwords or logon scripts worth hijacking. SPN accounts become Kerberoasting targets whose password hashes can be cracked offline. Weak DACLs become privilege escalation paths that let a low-privilege user modify high-value objects.

    Tools Used

    The exercises in this chapter rely on tools already installed on your Kali Linux attack machine. No additional software installation is required.

    Tool Purpose
    smbclient SMB share listing, file browsing, and file retrieval
    ldapsearch LDAP queries for GPOs, SPNs, and ACL-related objects

    Both tools support authenticated access using the -U 'user%password' syntax (smbclient) or -D "user@domain" -w "password" syntax (ldapsearch). You will see these authentication flags in every command throughout the chapter.
