    Exercise 1.1: Windows Reconnaissance

    Before You Begin

    Exercise 1.1 is the first exercise in Chapter F1 (Windows Forensics). You will use nmap from your Kali machine to scan a live Windows 10 target and identify the services it exposes. No credentials are needed for this exercise; everything is performed remotely from the network. If you have completed the enumeration chapters (CH01-CH07), the nmap commands will be familiar. this exercise focuses specifically on interpreting scan results in a Windows context.

    Make sure you have:

    • Your Kali machine connected to the lab network (VPN active or RangeBox session running)
    • Terminal access on your Kali machine
    • nmap installed (nmap --version)
    • Target IP noted from the Active Lab panel; replace <target-ip> in the commands below with this address

    Scenario

    Meridian Technologies has engaged your team to assess their Windows infrastructure. Before testing any credentials or accessing any systems, your first task is pure reconnaissance: identify what services the target Windows workstation exposes to the network. The exposed services determine your attack surface and guide the next phase of the assessment. A single Windows machine can expose a dozen services by default; your job is to find them all and understand what each one means.

    Your Objectives

    • Verify network connectivity to the Windows target
    • Perform a SYN scan to identify open ports
    • Run service version detection to fingerprint each service
    • Use OS fingerprinting to confirm the target operating system
    • Extract NetBIOS information (hostname, workgroup, MAC address)
    • Use SMB scripts to discover OS-level details and retrieve the flag

    Background: Windows Network Services

    A default Windows installation exposes significantly more network services than a typical Linux server. Understanding what each service does; and why it exists; is essential for both attackers and defenders.

    Port Service Protocol What It Does
    135 RPC Endpoint Mapper MSRPC Microsoft's inter-process communication broker. Maps RPC services to dynamic high ports. Required for DCOM, WMI, and many Windows management tools.
    139 NetBIOS Session NetBIOS/SMB Legacy Windows networking. Provides name resolution, session management, and datagram services. Predates DNS-based Windows networking.
    445 SMB Direct SMB/CIFS File and printer sharing over TCP. The primary protocol for Windows file access, Active Directory communication, and lateral movement.
    3389 RDP RDP Remote Desktop Protocol. Provides full graphical remote access to the Windows desktop. Frequently targeted by brute-force attacks.
    5985 WinRM HTTP/SOAP Windows Remote Management. Allows remote PowerShell execution and system management over HTTP. The modern replacement for WMI-over-DCOM.

    Why This Matters for Security

    Windows exposes these services because enterprise environments depend on them. SMB enables file sharing and Group Policy distribution. RPC underpins Windows Management Instrumentation (WMI). RDP provides remote administration. But each open port is an attack vector.

    SMB has a particularly notorious history. The EternalBlue exploit (MS17-010), leaked from the NSA in 2017, targeted a vulnerability in SMBv1 and powered the WannaCry ransomware outbreak that crippled hospitals, shipping companies, and government agencies worldwide. Port 445 open on a Windows machine is the single most important finding in any Windows reconnaissance scan.

    RDP is the second most-targeted service. Attackers routinely brute-force RDP credentials, and once they have a valid login, they have full interactive access to the machine; no malware required. The BlueKeep vulnerability (CVE-2019-0708) demonstrated that RDP itself can be exploited for remote code execution without any credentials at all.

    Tool Primer: Nmap for Windows Targets

    The table below lists the nmap options you will use in this exercise. Each flag is explained in the context of scanning Windows systems.

    Flag / Option What It Does
    -sS SYN scan (stealth scan). Sends SYN packets and analyzes responses without completing the TCP handshake. Fast and reliable. Requires root/sudo.
    -sV Service version detection. Probes open ports to determine the service name and version. Essential for identifying Windows-specific services.
    -O OS fingerprinting. Analyzes TCP/IP stack behavior to guess the operating system. Requires root/sudo.
    -p Specify ports to scan. Use -p 135,139,445,3389,5985 to target Windows services directly.
    --script nbstat Runs the NetBIOS statistics script. Extracts the hostname, workgroup/domain, and MAC address from the target.
    --script smb-os-discovery Queries SMB to determine the OS version, computer name, domain, and workgroup. Often reveals details that -O alone misses.
    -Pn Skip host discovery (treat host as online). Useful when ICMP is blocked by Windows Firewall.

    Walkthrough

    Step 1: Verify Connectivity

    Confirm the target is reachable

    Before scanning, confirm that the target is reachable from your Kali machine. Use the target IP shown in the Active Lab panel. The -c 3 flag sends three ICMP echo requests.

    ping -c 3 <target-ip>

    You should receive three replies. If ICMP is blocked (request timed out), the target may still be accessible; Windows Firewall sometimes blocks ping while allowing other traffic. In that case, proceed with the scan using the -Pn flag.

    Record Your Findings

    • Ping successful (yes/no): ___
    • Round-trip time (avg): ___

    Step 2: SYN Scan (Top 1000 Ports)

    Run a SYN scan of the top 1000 ports

    Run a SYN scan against the default top 1000 ports to get a broad view of the target's attack surface. The -sS flag performs a stealth scan that does not complete the TCP handshake and requires sudo.

    sudo nmap -sS <target-ip>

    Review the output carefully. On a Windows 10 machine, you should expect to see several ports open; typically 135, 139, 445, 3389, and 5985. Compare this to a typical Linux server, which might only show port 22 (SSH) and port 80 (HTTP). Windows exposes more services by default because its networking model is built around SMB, RPC, and remote management.

    Note any additional open ports beyond the five listed above. Windows machines in enterprise environments often run additional services; MSSQL (1433), IIS (80/443), or LDAP (389/636); depending on their role.

    Record Your Findings

    Port State Service
    • Total open ports: ___
    • Any unexpected ports? ___

    Step 3: Service Version Detection

    Fingerprint the service versions

    Now probe the open ports to identify the exact service versions running behind them. The -sV flag triggers version detection, and -p restricts the probe to the five Windows ports.

    nmap -sV -p 135,139,445,3389,5985 <target-ip>

    The output shows the service name and version for each port. For Windows services, you will typically see entries like:

    • 135/tcp: Microsoft Windows RPC
    • 139/tcp: Microsoft Windows netbios-ssn
    • 445/tcp: microsoft-ds (Microsoft Directory Services, i.e., SMB)
    • 3389/tcp: ms-wbt-server (Microsoft Windows-Based Terminal, i.e., RDP)
    • 5985/tcp: Microsoft HTTPAPI httpd 2.0 (WinRM running on HTTP.sys)

    The version strings confirm that this is a Windows system. The microsoft-ds label on port 445 is particularly important; it tells you SMB is available for enumeration, which is the focus of the next exercise.

    Record Your Findings

    Port Service Version String
    135
    139
    445
    3389
    5985

    Step 4: OS Fingerprinting

    Fingerprint the operating system

    Use nmap's OS detection to confirm the exact Windows version. The -O flag analyzes TCP/IP stack behavior and requires sudo.

    sudo nmap -O <target-ip>

    The output includes several important fields:

    • OS CPE: A standardized identifier like cpe:/o:microsoft:windows_10 that uniquely identifies the operating system
    • OS guesses: One or more guesses with confidence percentages, such as Microsoft Windows 10 1709 - 1909 (93%)
    • Network Distance: The number of hops to the target

    OS fingerprinting works by analyzing subtle differences in how operating systems implement the TCP/IP stack; window sizes, TTL values, TCP options, and response patterns to unusual packets. Different Windows versions have distinct fingerprints.

    Record Your Findings

    • OS CPE: ___
    • Best OS guess: ___
    • Confidence: ___%
    • Network distance: ___ hops

    Step 5: NetBIOS Information

    Extract NetBIOS information

    Extract the target's NetBIOS name, workgroup, and MAC address using nmap's nbstat script. The --script nbstat option runs the NetBIOS statistics NSE script against the host.

    nmap --script nbstat <target-ip>

    The output reveals:

    • NetBIOS name: The computer's hostname as registered on the network
    • NetBIOS user: The currently logged-in user (if available)
    • Workgroup/Domain: Whether the machine belongs to a workgroup or Active Directory domain
    • MAC address: The physical network adapter address and its vendor

    The NetBIOS data is valuable for mapping the target environment. The hostname often reveals the machine's purpose (e.g., FINANCE-WS01, DC01, FILESERVER). The workgroup or domain name tells you about the network architecture. The MAC address vendor can identify the hardware manufacturer or virtualization platform.

    Record Your Findings

    • NetBIOS name: ___
    • Workgroup/Domain: ___
    • MAC address: ___
    • MAC vendor: ___

    Step 6: SMB OS Discovery (Find the Flag)

    Query SMB for OS details and the flag

    Run the SMB OS discovery script to extract detailed operating system information directly from the SMB service. The --script smb-os-discovery option queries SMB and often reveals more detail than OS fingerprinting alone.

    nmap --script smb-os-discovery <target-ip>

    Examine the output carefully. The script returns:

    • OS: The full Windows version string
    • Computer name: The NetBIOS and DNS hostname
    • Domain/Workgroup: Active Directory domain or workgroup membership
    • System time: The target's current date and time
    • Computer description: A free-text field set by the administrator

    The computer description field contains the flag for this exercise, in the form:

    OCR{...}

    Administrators often set computer descriptions for asset management purposes, but they rarely realize this field is readable by anyone who can reach port 445. In a real assessment, this field sometimes contains internal documentation, IP addresses of other systems, or administrator notes; all of which is useful for further reconnaissance.

    Record Your Findings

    • OS version: ___
    • Computer name: ___
    • Domain/Workgroup: ___
    • Computer description: ___
    • Flag: ___

    Analysis Questions

    1. How does a Windows scan profile differ from a typical Linux scan profile?

    Reveal Answer

    A default Windows machine typically exposes 5 or more services (RPC on 135, NetBIOS on 139, SMB on 445, RDP on 3389, WinRM on 5985), while a hardened Linux server often shows only SSH (22) and the application port (80 or 443). Windows exposes more services because its networking model depends on RPC for management, SMB for file sharing and Group Policy, and RDP for remote administration. Each additional open port increases the attack surface. The expanded surface is why Windows hardening guides emphasize disabling unnecessary services and using host-based firewalls to restrict access to essential ports only.

    2. What is the security significance of port 445 (SMB)?

    Reveal Answer

    Port 445 is the most security-critical port on any Windows machine. SMB has been the target of devastating exploits, most notably EternalBlue (MS17-010), which was exploited by the WannaCry and NotPetya ransomware campaigns in 2017. Beyond remote code execution vulnerabilities, SMB also enables null session enumeration (listing shares, users, and groups without credentials), credential relay attacks (NTLM relay), and lateral movement using tools like PsExec and Impacket. If port 445 is open and accessible, the machine is exposed to a wide range of attacks. Best practice is to block SMB at the perimeter firewall and restrict internal SMB access to only the systems that require it.

    3. Why does Windows expose RPC (port 135) and dynamically assigned high-numbered RPC ports?

    Port 135 is the RPC Endpoint Mapper, a directory service that tells clients which high-numbered port a specific RPC service is listening on. When a client wants to use DCOM (Distributed Component Object Model) or WMI (Windows Management Instrumentation), it first queries port 135 to find the dynamic port assigned to that service, then connects to that port directly. The endpoint-mapper design means that blocking port 135 breaks many Windows management tools, but leaving it open exposes the RPC service directory to anyone on the network. Attackers use RPC enumeration to discover available services, identify the OS version, and find additional attack vectors. In segmented networks, RPC traffic should be restricted to management VLANs.

    Key Takeaways

    • Windows machines expose significantly more network services by default than Linux systems, creating a larger attack surface that must be understood and managed
    • The five core Windows ports (135, 139, 445, 3389, 5985) each serve a distinct function in the Windows networking model, and each represents a potential attack vector
    • SMB (port 445) is the highest-priority finding in any Windows scan due to its history of critical vulnerabilities and its central role in lateral movement
    • Nmap scripts like nbstat and smb-os-discovery extract valuable metadata (hostname, domain, OS version, description) without requiring any credentials
    • OS fingerprinting, service version detection, and NSE scripts provide complementary information; use all three together for the most complete picture of the target
