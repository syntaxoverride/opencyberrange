    Exercise WS-2.5: Password Policy Extraction

    Before You Begin

    Exercises WS-2.1 through WS-2.4 systematically enumerated the directory's structure, user accounts, group memberships, and computer objects. Exercise WS-2.5 completes the reconnaissance picture by extracting the domain-wide password policy; the set of rules that govern credential strength, history, and lockout behavior. You will need the same Kali Linux machine with anonymous Lightweight Directory Access Protocol (LDAP) access to dc01.

    Prerequisites

    • Exercises WS-2.1 through WS-2.4 completed
    • VPN active and dc01 reachable
    • ldapsearch available (ldap-utils package)
    • Your user list and group membership notes from earlier labs

    Scenario

    Before launching any credential attacks against the domain, a careful attacker checks the password policy. The policy dictates the minimum password length, complexity requirements, lockout thresholds, and lockout duration. Attempting too many incorrect passwords without knowing the lockout threshold risks locking out accounts and alerting defenders. Extracting the policy first lets you calibrate your approach; choosing password candidates that meet the minimum length and complexity, and staying below the lockout threshold to avoid detection.

    Your Objectives

    • Query the domain object for password policy attributes using a base-scope LDAP search
    • Extract the minimum password length and understand its impact on credential attacks
    • Determine the account lockout threshold and lockout duration
    • Derive the lab flag from the extracted policy values

    Background: Domain Password Policy in Active Directory

    Active Directory (AD) stores the default password policy as a set of attributes on the domain object itself; the root entry at DC=corp,DC=ocr-range,DC=lab. Unlike OUs, users, and groups, the password policy is not a separate object; the attributes live directly on the domain's top-level entry. Reading the policy requires a base-scope search (-s base) targeting the domain DN, which returns only the domain object and its attributes without descending into child containers.

    Five attributes define the core password policy.

    Attribute Meaning
    minPwdLength Minimum number of characters a password must contain
    maxPwdAge Maximum time a password can be used before it must be changed (stored in 100-nanosecond intervals as a negative value)
    lockoutThreshold Number of consecutive failed logon attempts before the account is locked
    lockoutDuration How long a locked account remains locked (stored in 100-nanosecond intervals as a negative value)
    pwdHistoryLength Number of previous passwords the system remembers, preventing reuse

    The maxPwdAge and lockoutDuration values use a format unique to AD: they are stored as negative 64-bit integers representing intervals of 100 nanoseconds. For example, a maxPwdAge of -36288000000000 equals 42 days. Converting these values to human-readable durations requires dividing the absolute value by 10,000,000 (to get seconds) and then converting seconds to days, hours, or minutes.

    The lockoutThreshold deserves special attention. A threshold of 0 means account lockout is disabled; an attacker can make unlimited password guesses without triggering a lockout. Any non-zero threshold defines the number of failed attempts allowed within the observation window before the account locks. Staying one or two attempts below that threshold is a standard technique during password-spraying attacks.

    Tool Primer: Base-Scope LDAP Search

    The command below retrieves password policy attributes from the domain object using a base-scope search.

    ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" -s base minPwdLength maxPwdAge lockoutThreshold lockoutDuration pwdHistoryLength

    The -s base flag is the key difference from the queries in earlier labs. Instead of searching an entire subtree for matching objects, a base-scope search returns only the single object at the specified base DN. Because the password policy attributes live on the domain object, the base DN and the target object are the same.

    Sample output from a base-scope policy query looks like the following.

    # corp.ocr-range.lab
dn: DC=corp,DC=ocr-range,DC=lab
minPwdLength: <value>
maxPwdAge: <value>
lockoutThreshold: <value>
lockoutDuration: <value>
pwdHistoryLength: <value>

    Note: Your lab values will differ from any examples shown in this walkthrough.

    Each attribute appears on its own line with its value. The minPwdLength and lockoutThreshold values are plain integers. The maxPwdAge and lockoutDuration values require conversion from 100-nanosecond intervals to human-readable time periods.

    Walkthrough

    Step 1: Query the Domain Password Policy

    Query the domain password policy

    Execute the base-scope search against the domain object to retrieve all five password policy attributes.

    ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" -s base minPwdLength maxPwdAge lockoutThreshold lockoutDuration pwdHistoryLength

    Save the output to a file for reference.

    ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" -s base minPwdLength maxPwdAge lockoutThreshold lockoutDuration pwdHistoryLength > /tmp/policy.ldif

    Confirm that all five attributes appear in the output. If any attribute is missing, the domain may not have that policy configured, or the attribute name may have a typo.

    Step 2: Read the Minimum Password Length

    Read the minimum password length

    Locate the minPwdLength line in the output. The value is a plain integer specifying the minimum number of characters.

    grep "^minPwdLength:" /tmp/policy.ldif

    The minPwdLength value tells you the minimum number of characters every password in the domain must contain. When preparing a password list for spraying or brute-force attacks, you would exclude any candidate shorter than the minimum; they cannot be valid.

    Record the minimum password length value. You will need it to construct the flag.

    Step 3: Determine the Lockout Threshold

    Determine the lockout threshold

    Locate the lockoutThreshold line.

    grep "^lockoutThreshold:" /tmp/policy.ldif

    The lockoutThreshold value tells you how many consecutive failed logon attempts are allowed before an account locks. A value of 0 would mean lockout is disabled entirely. Record the lockout threshold value; you will need it for the flag and for calibrating any future credential attacks.

    When planning a password-spraying attack, the standard approach is to attempt no more than lockoutThreshold - 2 guesses per account within the observation window. Subtract 2 from the threshold you found to determine your safe maximum; this constraint shapes the attack strategy.

    Step 4: Convert the Maximum Password Age

    Read the maximum password age

    Locate the maxPwdAge line. The value will be a large negative number in 100-nanosecond intervals.

    grep "^maxPwdAge:" /tmp/policy.ldif

    Convert the absolute value to days using the following formula.

    days = absolute_value / 10,000,000 / 60 / 60 / 24

    For example, if maxPwdAge were -25920000000000 (substitute your actual value):

    25920000000000 / 10,000,000 = 2,592,000 seconds
2,592,000 / 60 = 43,200 minutes
43,200 / 60 = 720 hours
720 / 24 = 30 days

    Apply this same conversion to the maxPwdAge value from your output and record the result in days.

    Step 5: Convert the Lockout Duration

    Read the lockout duration

    Locate the lockoutDuration line and apply the same conversion.

    grep "^lockoutDuration:" /tmp/policy.ldif

    Convert the absolute value to minutes.

    minutes = absolute_value / 10,000,000 / 60

    For example, if lockoutDuration were -12000000000 (substitute your actual value):

    12000000000 / 10,000,000 = 1,200 seconds
1,200 / 60 = 20 minutes

    Apply this same conversion to the lockoutDuration value from your output and record the result in minutes.

    Step 6: Read the Password History Length

    Read the password history length

    Locate the pwdHistoryLength line.

    grep "^pwdHistoryLength:" /tmp/policy.ldif

    The password history length specifies how many previous passwords the system remembers. A value of 24 means a user cannot reuse any of their last 24 passwords. The higher the history length, the harder it is for users to cycle back to a familiar password, which generally improves security.

    Step 7: Summarize the Policy

    Compile all five values into a single policy summary table. Convert the raw AD time values to human-readable formats. The summary should look similar to the following.

    Policy Attribute Raw Value Human-Readable Value
    Minimum Password Length [integer] [integer] characters
    Maximum Password Age [negative integer] [X] days
    Lockout Threshold [integer] [integer] attempts
    Lockout Duration [negative integer] [X] minutes
    Password History Length [integer] [integer] passwords remembered

    Step 8: Interpret the Results

    Consider what the password policy tells you about the organization's security posture. Compare the minimum password length against modern guidance from NIST (National Institute of Standards and Technology), which recommends a minimum of 8 characters, with many organizations requiring 12 or more. Evaluate whether the lockout threshold provides meaningful protection against brute-force attacks or still allows a window for careful password spraying.

    The combination of policy values shapes your attack strategy. The minPwdLength value you found determines the shortest viable password candidate. Subtracting 2 from the lockoutThreshold value gives you the safe number of guesses per account per lockout window. The lockout duration you calculated tells you how long to wait before resuming attempts after a lockout expires.

    Step 9: Find and Submit the Flag

    The flag for this exercise is derived from two policy values: the minimum password length and the lockout threshold. The format is OCR{p0l1cy_3xtr4ct3d_<minPwdLength>_<lockoutThreshold>}. Using the values you extracted, construct the flag.

    The flag follows the standard OCR{...} format. Submit it on the platform to complete the exercise.

    Analysis Questions

    1. Why does extracting the password policy matter before attempting credential attacks?

    Reveal Answer

    Knowing the minimum password length allows an attacker to filter their wordlist to exclude candidates that are too short, improving efficiency. Knowing the lockout threshold prevents the attacker from accidentally locking accounts, which would alert defenders and deny access to legitimate users. Together, the policy values let the attacker calibrate their approach for maximum effectiveness with minimum risk of detection.

    2. The maxPwdAge and lockoutDuration values are stored as negative 100-nanosecond intervals. Why does Active Directory use this format?

    Reveal Answer

    AD inherited its time format from Windows NT, which represents time intervals as 64-bit integers in 100-nanosecond units. Negative values indicate relative durations (how long from now) rather than absolute timestamps. While the format is unintuitive for humans, it provides high precision and is consistent with how the Windows kernel tracks time internally.

    3. A domain has a lockoutThreshold of 0. What does that mean for an attacker, and what does it mean for the defender?

    Reveal Answer

    A threshold of 0 means account lockout is disabled. An attacker can make unlimited password guesses against any account without triggering a lockout. For the defender, the lack of lockout means brute-force and password-spraying attacks face no automatic barrier, making strong passwords and monitoring for high volumes of failed logon events critical compensating controls.

    4. How would a Fine-Grained Password Policy (FGPP) change the results of this exercise?

    Reveal Answer

    Fine-Grained Password Policies allow administrators to define different password policies for different groups of users within the same domain. The default domain policy returned by a base-scope search may not apply to all accounts; privileged accounts might have stricter requirements (longer minimum length, lower lockout threshold). To discover FGPPs, an attacker would need to query the CN=Password Settings Container,CN=System,DC=corp,DC=ocr-range,DC=lab container for msDS-PasswordSettings objects.

    Key Takeaways

    • The domain password policy is stored as attributes on the domain object itself and is readable through a base-scope LDAP search.
    • minPwdLength and lockoutThreshold are the two most operationally relevant values for planning credential attacks; they define the minimum viable password length and the safe number of guesses.
    • AD stores time-based policy values in 100-nanosecond intervals as negative integers; converting them to days, hours, or minutes requires dividing by 10,000,000 and then by the appropriate time factor.
    • A lockout threshold of 0 disables account lockout entirely, removing an important braking mechanism against brute-force attacks.
    • With all five labs complete, you have a complete map of the corp.ocr-range.lab domain: OUs, users, groups, computers, and password policy. The Chapter Review consolidates these findings and prepares you for Chapter WS03.
