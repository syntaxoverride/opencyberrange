    Chapter WS02: Review

    What You Learned

    Chapter WS02 took the anonymous Lightweight Directory Access Protocol (LDAP) access confirmed in Chapter WS01 and used it to systematically enumerate every major category of Active Directory (AD) object. Across five labs you queried the domain controller dc01 for Organizational Units (OUs), user accounts, security groups, computer objects, and the domain password policy. Each lab added a new layer to your understanding of the corp.ocr-range.lab domain.

    The chapter reinforced a single tool; ldapsearch: applied with different filters, scopes, and attribute lists to extract distinct types of information. You learned that LDAP filters select objects by objectClass, that the -s base scope retrieves attributes from a single object, and that freeform text attributes like description and info frequently contain data that administrators did not intend to be publicly visible. You also built practical artifacts; an OU hierarchy, a username list, a group membership map, an infrastructure inventory, and a password policy summary; that feed directly into later attack phases.

    Command Cheat Sheet

    The table below collects every ldapsearch command used across the five labs. Each row shows the lab, the full command, and a brief description of its purpose.

    Exercise Command Purpose
    2.1 ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=organizationalUnit)" dn description Enumerate all OUs and their descriptions
    2.2 ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=user)" sAMAccountName displayName description info memberOf List all user accounts with key attributes
    2.3 ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=group)" cn description member Enumerate all groups and their members
    2.4 ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=computer)" cn operatingSystem operatingSystemVersion description dNSHostName Discover all computer objects and OS info
    2.5 ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" -s base minPwdLength maxPwdAge lockoutThreshold lockoutDuration pwdHistoryLength Extract the domain password policy

    Useful modifiers:

    Modifier Example Purpose
    Save output to file ldapsearch ... > /tmp/output.ldif Preserve results for searching and analysis
    Base-scope search -s base Return only the object at the specified DN
    One-level scope -s one Return only immediate children of the base DN
    Specific base DN -b "OU=IT,DC=corp,DC=ocr-range,DC=lab" Narrow search to a specific OU

    Connect the Dots: What Comes Next

    Chapter WS02 gave you a complete read-only view of the domain through anonymous LDAP queries. You mapped the organizational structure, identified users and their privilege levels, cataloged the infrastructure, and extracted the password policy. The data you collected; especially the username list and the password policy constraints; sets the stage for active credential attacks.

    Chapter WS03 will shift from passive enumeration to authenticated and targeted techniques. Expect to use the artifacts you built in WS02 (username lists, group membership maps, and the password policy) as direct inputs to tools that test for weak credentials, misconfigured service accounts, and exploitable trust relationships. The transition from "what can I read?" to "what can I access?" begins in the next chapter.

    Self-Assessment Answer Key

    1. The -x flag enables simple (anonymous) authentication.

    2. (objectClass=organizationalUnit) returns only OU objects.

    3. The description and info attributes are freeform text fields that may contain sensitive data such as temporary passwords or internal notes.

    4. The member attribute on a group object lists the DNs of its direct members.

    5. The OU=Domain Controllers container typically holds the domain controller's computer object.

    6. A lockoutThreshold of 0 means account lockout is disabled; an attacker can make unlimited password guesses without triggering a lockout.

    7. Divide the absolute value by 10,000,000 (ten million) to convert 100-nanosecond intervals to seconds.

    8. The -s base scope returns attributes from only the single object at the specified base DN.
