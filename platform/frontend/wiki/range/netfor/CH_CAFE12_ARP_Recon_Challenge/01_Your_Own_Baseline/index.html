    Scenario

    The Bean & Byte Cafe has more than one network segment. You've baselined the core infrastructure: gateway, POS, barista workstation, printer, and thermostat. Now a different set of devices needs the same treatment: the security camera DVR, digital menu display, NAS backup server, and a customer laptop, along with the gateway.

    Map this segment. Build the baseline. Find the flag. No walkthrough this time.

    Your Objectives

    • Discover all 5 devices on this network segment
    • Document every device's MAC address, IP address, and vendor OUI
    • Verify MAC-to-IP bindings for each device
    • Capture ARP traffic and identify broadcast patterns and gratuitous ARPs
    • Assemble the flag from tokens found during your reconnaissance

    Flag

    The flag follows the same format as Exercise 11: three tokens assembled from your ARP reconnaissance results.

    Flag format: OCR{________}

    Hint: Each token is prefixed with OCR-SN:, and the token is the part after the prefix. The three sources are:

    • Token 1: the gateway's vendor string in your arp-scan results. The custom OUI database resolves the gateway MAC (00:18:f8:...) to a vendor name that carries the token.
    • Token 2: the gateway's SNMP sysDescr (community string public). The tap ships without SNMP MIBs, so query by numeric OID: snmpget -v2c -c public <gateway-ip> 1.3.6.1.2.1.1.1.0 or walk the system tree with snmpwalk -v2c -c public <gateway-ip> 1.3.6.1.2.1.1.
    • Token 3: the NAS backup server's SMB server string. Read it with smbclient -L //<nas-ip>/ -N or enum4linux -a <nas-ip>.

    Analysis Questions

    1. How does the customer laptop's ARP behavior differ from the always-on infrastructure devices? Why?

    Reveal Answer Transient devices like the customer laptop generate more ARP requests because they need to discover the gateway and other resources each time they connect. They may also send gratuitous ARPs upon joining the network to announce their presence. Infrastructure devices that have been running continuously will have stable, cached ARP entries and generate fewer requests. The customer laptop's ARP cache state is more likely to be STALE or DELAY compared to the REACHABLE state of long-running devices.

    2. The NAS backup server has three services (SSH, SMB, HTTPS). Does having multiple services affect its ARP behavior?

    Reveal Answer No. ARP operates at Layer 2 and maps IP addresses to MAC addresses regardless of what services run on the host. A device with one service and a device with fifty services generate the same ARP traffic: one MAC address, one IP address, one ARP binding. The number of services matters at Layers 3-7 (TCP/UDP ports, protocol behavior), but ARP only cares about the network interface's MAC and IP assignment.

    3. You now have baselines for two cafe network segments. How would you use them together to detect a rogue device?

    Reveal Answer A rogue device would appear as an unknown MAC address in your arp-scan results: one that doesn't match any entry in either baseline table. Cross-referencing both baselines also helps detect MAC spoofing: if a MAC address from Segment A suddenly appears on Segment B claiming a different IP, that's suspicious. Regular automated scans compared against the combined baseline can alert on new devices, changed bindings, or MAC addresses appearing on unexpected segments.

    Defensive Recommendations

    Consider these additional recommendations based on the devices in this segment:

    1. Isolate IoT devices (DVR, menu display) from storage systems (NAS) using VLANs: a compromised camera should not be able to ARP-spoof the backup server
    2. Implement 802.1X port authentication for the customer WiFi segment to prevent unauthorized devices from joining
    3. Monitor for MAC address duplication across segments: the gateway appears on both segments and its MAC should be consistent
    4. Set shorter ARP cache timeouts on critical devices to force more frequent re-verification of bindings

    Key Takeaways

    • Independence validates learning: If you can map a new segment without a walkthrough, you've internalized the methodology
    • Different device types, same protocol: IoT cameras, storage appliances, and laptops all use ARP identically: the reconnaissance approach is universal
    • Transient devices create noise: Customer devices connecting and disconnecting generate ARP traffic that can mask malicious activity
    • Baselines are living documents: Each new segment needs its own baseline, and all baselines should be maintained and compared over time
    • Layer 2 visibility is often neglected: Most network monitoring focuses on Layers 3-7: ARP baselines fill a critical gap in network visibility
