    Exercise 6.1: Section Capstone, Single Domain

    Before You Begin

    Capstone 6.1 is a black-box engagement. You start with VPN access to corp.nordport.local and no credentials. There are three flags at three privilege tiers; reach Domain Admin to collect all three. The exercise is open-ended: there is no walkthrough. You chose the techniques from the Levels 2-4 catalog. Multiple paths work.

    The deliverable is the final flag plus a written attack-chain narrative documenting each step. Treat this like a real engagement.

    Tools required: the entire Kali Active Directory toolkit. Pre-installed.

    Scenario

    Priya Ramanathan, Nordport's CISO, emails:

    "We have approved a one-week internal red team engagement against corp.nordport.local. Black-box. Start with VPN access, no credentials. I want full Domain Admin, three artifacts proving each privilege tier reached, and a written narrative I can hand to the audit committee.

    Treat this like the auditor will see your work. Document every step. We will compare your chain against our internal expectations and against what BloodHound would have predicted."

    Tiers:

    Tier What proves it File location
    Tier 2 (any user) Tier 2 flag \\file01\Public\tier2_flag_<token>.txt
    Tier 1 (server admin / DBA) Tier 1 flag \\mssql01\C$\tier1_flag_<token>.txt
    Tier 0 (Domain Admin) Tier 0 flag (= final flag) \\corp-dc01\C$\tier0_flag_<token>.txt

    Time budget: 4 to 6 hours across multiple sittings.

    Domain: corp.nordport.local

    Recommended Approach

    Phase 0: Engagement Setup (target: ~10 minutes)

    Before any active probing, set yourself up so you can write the report without scrambling at the end.

    Kali - Engagement scaffolding

    mkdir -p ~/work/adpt-capstone-1/{recon,foothold,server,da,evidence}
cd ~/work/adpt-capstone-1
echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) -- engagement start" >> evidence/timeline.txt
ip -4 -o addr show | tee evidence/kali-interfaces.txt
echo "OCR_SCOPE_TOKEN=${OCR_SCOPE_TOKEN}" | tee -a evidence/scope.txt
    Token Effect
    mkdir -p ~/work/adpt-capstone-1/{...} Create per-phase artifact directories.
    evidence/timeline.txt Start the chain-of-custody clock. Every phase boundary appends to this file.
    tee Print and save in one go. Capture interfaces and scope token for the report.

    The five subdirectories mirror the report structure. Drop pcaps, cred lists, BloodHound zips, ccaches, and screenshots into the right one as you produce them. The evidence/timeline.txt file becomes the skeleton of your narrative.

    Phase 1: Recon and Foothold (target: ~60 minutes)

    The goal is any authenticated domain user credential. Three reasonable paths:

    1. LLMNR/NBT-NS poisoning on the workstation segment. The workstation segment has simulated user activity that performs mistyped lookups. Run Responder.
    2. ASREPRoast; if anonymous LDAP is enabled, enumerate users with DONT_REQ_PREAUTH; otherwise need authenticated LDAP first.
    3. Password spray; requires a user list, which means anonymous LDAP or LLMNR-captured credential first.

    Cracked credential -> Tier 2 flag at \\file01\Public\tier2_flag_<token>.txt (readable by any Domain User).

    Phase 2: Server-Tier Escalation (target: ~90 minutes)

    From a foothold credential, escalate to a server-admin or DBA account.

    1. Kerberoast the SQL service account on mssql01. The SQL account has SQL sysadmin role and can xp_cmdshell to local SYSTEM on mssql01.
    2. GenericAll / WriteDACL; BloodHound the domain from your foothold and look for ACL paths to a DBA group or directly to a privileged user.
    3. LAPS read; if j.chen (or your foothold) has LAPS read on mssql01, you have local admin directly.

    Tier 1 flag at \\mssql01\C$\tier1_flag_<token>.txt (readable by local Administrators on mssql01).

    Phase 3: Domain Admin (target: ~120 minutes)

    From server-admin/DBA, reach DA.

    1. xp_cmdshell on MSSQL -> local SYSTEM -> dump LSASS for cached domain admin credentials.
    2. ADCS ESC1 / ESC8 -> Administrator cert -> PKINIT -> krbtgt via DCSync -> golden ticket.
    3. Constrained delegation / RBCD -> impersonate Administrator -> read DC C$.

    Tier 0 flag at \\corp-dc01\C$\tier0_flag_<token>.txt is the final flag, in the form OCR{...}. Read the file and submit its contents verbatim.

    Hints (Use Sparingly)

    The lab unlocks hints at 60, 180, and 300 minutes. Use them only if you are stuck. Real engagements do not have hint timers.

    Common pitfalls in capstone runs

    • Skipping Phase 0: trying to reconstruct a chain at the end without timestamped evidence wastes 30+ minutes per phase. Append to evidence/timeline.txt as you go, not at the end.
    • Dumping everything at once: full secretsdump is slower and louder than -just-dc-user krbtgt. Dump only what you need until you have time to harvest the rest.
    • Ignoring the cleanup step: if you exercised WriteDACL or RBCD, the ACE/computer account is still there. Phase 0's evidence/timeline.txt should also list cleanup actions so you can verify everything was reverted before submitting.
    • Re-running without resetting Kerberos cache: klist between phases. Stale TGTs from one phase poison authentication attempts in the next.
    • Trying every technique in parallel: pick one path per phase. The graph in BloodHound usually shows one shortest path; walk it, then go back and document alternatives in the report.

    Key Takeaways

    • The chain matters more than any single technique.
    • BloodHound the domain from your foothold; the graph reveals paths you would not see manually.
    • Document each step as you go; reconstructing a chain from memory at the end is painful.
    • Cleanup matters: remove ACEs, group memberships, certs, and forged tickets when done.
    • The narrative is the deliverable Priya cares about. The flag proves you got there; the writeup proves you can teach the next consultant how.

    Cheat Sheet Recap

    The five operations below are the smallest possible toolkit for the capstone. Use this card as a backstop when you forget syntax under time pressure.

    Phase Goal Command
    Recon Anonymous LDAP probe ldapsearch -x -LLL -H ldap://<dc> -s base "(objectClass=*)" namingContexts
    Foothold LLMNR poison + capture sudo responder -I <iface> -wrf
    Recon (authed) BloodHound collect bloodhound-python -u <u> -p '<pw>' -d <domain> -ns <dc> -c All --zip
    Server tier Kerberoast GetUserSPNs.py "<domain>/<u>:<pw>" -dc-ip <dc> -request -outputfile tgs.hash
    Domain admin DCSync krbtgt secretsdump.py -just-dc-user krbtgt "<domain>/<u>:<pw>" -dc-ip <dc>

    Reflection Questions

    After submitting, answer these three questions in your notes:

    1. Which technique would you have prioritized differently in hindsight, and why?
    2. Which finding would you flag as Critical to the customer, and which would you flag as Informational?
    3. If Priya asked you to make the engagement harder for the next attacker, name the single highest-leverage remediation.

    There is no scoring API for the reflection. The point is to internalize the consultant mindset: the technical work is half; the analysis is the other half.
