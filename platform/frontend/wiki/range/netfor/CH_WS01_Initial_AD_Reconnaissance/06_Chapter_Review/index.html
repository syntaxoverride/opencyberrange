    Chapter WS01: Review

    What You Learned

    Over five labs, you performed a complete unauthenticated reconnaissance sweep against a Windows Server 2022 Domain Controller. Starting with nothing but a hostname (dc01), you built a detailed picture of the target: its open ports, DNS records, reverse DNS mappings, SMB shares, and LDAP directory structure. Every technique in this chapter works without credentials; the information was obtained purely through protocol-level queries that the DC responded to by design or by misconfiguration.

    The central lesson of this chapter is that Active Directory Domain Controllers are information-rich targets. Each protocol exposed by a DC reveals a different slice of the domain, and layering those slices together produces a complete map that feeds directly into the next phase of an engagement.

    Connect the Dots: What Comes Next

    Chapter WS01 covered unauthenticated reconnaissance; what you can learn about an AD environment with no credentials at all. The findings from this chapter provide the foundation for everything that follows.

    Chapter WS02 will introduce authenticated enumeration. With a set of valid domain credentials (obtained through password spraying, credential harvesting, or provided as part of the engagement scope), you can query LDAP for user accounts, group memberships, and computer objects. The base DN you extracted in Exercise WS-1.5 (DC=corp,DC=ocr-range,DC=lab) will be the starting point for those queries. The domain name confirmed through DNS and SMB will be required when constructing authenticated LDAP binds and Kerberos authentication requests.

    The progression from unauthenticated to authenticated reconnaissance mirrors the real-world attack lifecycle: gather what you can without credentials, use that information to target credential acquisition, then use credentials to enumerate the environment in depth.

    Self-Assessment Answer Key

    1. Which combination of open ports distinguishes a Domain Controller from a regular Windows member server?

    Ports 88 (Kerberos), 389 (LDAP), 636 (LDAPS), and 3268 (Global Catalog) are unique to Domain Controllers. Member servers do not run the Kerberos KDC or Global Catalog services. DNS (53) and SMB (445) can appear on member servers, but the full combination with Kerberos and Global Catalog is exclusive to DCs.

    2. What does the AXFR query type request from a DNS server?

    AXFR requests a full zone transfer; a complete copy of every DNS record in the specified zone. The mechanism exists so secondary DNS servers can replicate zone data from a primary server, but unrestricted AXFR allows any client to download the entire zone.

    3. What is the in-addr.arpa domain used for, and why are the IP address octets reversed?

    The in-addr.arpa domain is the DNS namespace for reverse lookups (IP-to-hostname mappings via PTR records). The octets are reversed so that the DNS delegation hierarchy (which reads right to left) aligns with the IP address hierarchy (which allocates from left to right), enabling reverse zones to be delegated along network boundaries.

    4. What two pieces of information does the SMB protocol negotiation reveal even when a null session has limited permissions?

    The server's NetBIOS hostname and the NetBIOS domain name. These values are part of the SMB protocol handshake and are transmitted before access control decisions are made.

    5. What is the Root DSE in LDAP, and what is the most important attribute it contains for an attacker?

    The Root DSE (rootDSE) is a special LDAP entry with an empty DN that describes the LDAP server's capabilities. The most important attribute for an attacker is defaultNamingContext, which provides the base DN needed to construct queries against the domain partition.

    6. What is the base DN for the corp.ocr-range.lab domain, and how is it derived from the DNS name?

    The base DN is DC=corp,DC=ocr-range,DC=lab. Active Directory derives the base DN by splitting the DNS domain name at each dot and prefixing each component with DC=.

    7. Name two mitigations that would prevent the techniques used in Exercises WS-1.2 (zone transfer) and WS-1.5 (anonymous LDAP beyond rootDSE).

    For zone transfers: configure the DNS server to restrict AXFR to authorized secondary DNS server IP addresses only. For anonymous LDAP: configure the Domain Controller to limit anonymous LDAP access to the rootDSE (the default on Windows Server 2003 and later, but verify the dsHeuristics attribute and the "Network access: Restrict anonymous access to Named Pipes and Shares" policy).

    8. Why do penetration testers cross-reference findings from multiple protocols (DNS, SMB, LDAP) rather than relying on a single source?

    Different protocols reveal different information, and some protocols may be restricted while others remain open. Cross-referencing confirms findings (the domain name from DNS, SMB, and LDAP should match) and fills gaps (DNS provides hostnames and IPs, SMB reveals share data, LDAP exposes directory structure). Relying on a single protocol risks missing information that another protocol would have disclosed.
