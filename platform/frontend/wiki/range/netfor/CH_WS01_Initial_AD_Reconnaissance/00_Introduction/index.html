    Chapter WS01: Initial AD Reconnaissance

    Why Reconnaissance Comes First

    Every engagement against a Windows enterprise network begins with the same question: what is running on the network, and what can an unauthenticated attacker learn? Active Directory (AD); Microsoft's directory service for managing users, computers, and policies across a domain; sits at the heart of nearly every corporate Windows environment. The Domain Controller (DC) that hosts AD exposes a distinctive set of network services, and each service can leak information about the domain before a single credential is ever obtained.

    Reconnaissance is the foundation that every later attack phase depends on. A thorough initial survey tells you the domain name, the naming structure, the hostnames of key servers, and sometimes even user accounts and share contents. Skipping reconnaissance or doing a shallow scan means missing paths that more careful attackers would find.

    The five exercises in this chapter walk through the standard unauthenticated enumeration sequence against a single Windows Server 2022 Domain Controller. You will move from a broad port scan to targeted queries against DNS (Domain Name System), SMB (Server Message Block), and LDAP (Lightweight Directory Access Protocol); the same progression a real penetration tester follows during the first hour on an internal network.

    What You Will Learn

    Active Directory reconnaissance is not a single tool or a single command. Each protocol exposed by a Domain Controller reveals a different slice of information, and a skilled operator layers those slices together to build a complete picture of the target environment.

    By the end of this chapter, you will be able to:

    • Identify a Domain Controller by its unique combination of open TCP ports
    • Perform forward and reverse DNS enumeration, including zone transfers
    • Extract the domain name, computer name, and available file shares through SMB
    • Query LDAP anonymously to retrieve the directory's base Distinguished Name (DN) and naming contexts
    • Explain why each protocol matters to both defenders and attackers
    • Combine findings from multiple protocols into a coherent reconnaissance summary

    Active Directory and the Domain Controller

    Active Directory organizes network resources; user accounts, computer accounts, groups, and policies; into a hierarchical database replicated across one or more Domain Controllers. A DC is a Windows Server that has been promoted to host a copy of the AD database (NTDS.DIT) and to authenticate users via Kerberos, the default authentication protocol in AD environments.

    Because a DC must serve so many roles, the server exposes a characteristic set of network ports. Recognizing the pattern of open ports is the fastest way to confirm that a target host is a Domain Controller rather than a member server or workstation.

    Understanding the relationship between these services helps explain why the DC is such a valuable reconnaissance target. DNS provides name resolution for the entire domain; every workstation queries the DC to find other hosts and services. Kerberos handles authentication by issuing tickets that prove a user's identity. LDAP exposes the directory itself, allowing clients to look up user attributes, group memberships, and organizational structure. SMB distributes Group Policy files and logon scripts from the SYSVOL share. Each service answers a different question, and together they form a complete picture of the domain.

    The key ports and their associated services are listed below.

    Port Protocol Service Role on a DC
    53 TCP/UDP DNS Name resolution for the domain
    88 TCP/UDP Kerberos Authentication
    135 TCP RPC Endpoint Mapper Remote procedure calls
    139 TCP NetBIOS Session Legacy name service
    389 TCP LDAP Directory queries
    445 TCP SMB File shares, policy distribution
    636 TCP LDAPS LDAP over TLS
    3268 TCP Global Catalog Forest-wide LDAP queries
    3389 TCP RDP Remote Desktop (if enabled)
    5985 TCP WinRM PowerShell Remoting (if enabled)

    The Reconnaissance Mindset

    Effective reconnaissance is methodical rather than random. An experienced penetration tester does not scan blindly and hope for results. Instead, each query is chosen based on what the previous query revealed. A port scan tells you which protocols are available. Seeing DNS open prompts you to try zone transfers. A zone transfer reveals reverse zones, which prompts reverse sweeps. Finding SMB open leads to share enumeration. Finding LDAP open leads to anonymous directory queries.

    Defenders benefit from understanding the same progression. Knowing what an attacker looks for at each stage lets a security team prioritize hardening: restrict zone transfers, disable anonymous SMB share access, limit LDAP anonymous binds, and monitor for sequential enumeration patterns in firewall and DNS logs.

    Throughout these exercises, treat note-taking as a core skill. Record every IP address, hostname, domain name, and service version you discover. The notes from Chapter WS01 become the input data for Chapter WS02's authenticated enumeration.

    Before You Start

    Confirm the following before beginning Exercise WS-1.1.

    • VPN connection to the Open Cyber Range is active
    • You can resolve dc01 from your Kali Linux attack box (run ping -c 1 dc01)
    • The tools nmap, dig, smbclient, and ldapsearch are installed (all are included in the default Kali image)
    • You have a terminal window open and a text file or note-taking application ready to record findings
    • You understand that all scanning is confined to the lab environment; never run these commands against systems you do not have authorization to test
