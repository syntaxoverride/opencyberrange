    Exercise MEG1.1: Network Discovery

    Before You Begin

    You should have read the Chapter 1 Introduction, which describes the Meridian Energy Group engagement and the DMZ architecture. Your VPN must be connected and your terminal open. The lab environment provides three target servers in the DMZ segment.

    Scenario

    Meridian Energy Group has authorized a full-scope penetration test following an industry advisory about energy sector attacks. You have VPN access to the DMZ segment containing the company's external-facing infrastructure. Your first objective is reconnaissance: map every accessible host, enumerate running services, and gather as much intelligence as possible before moving to active exploitation.

    Credentials:

    Username Password Context
    anonymous (empty) FTP anonymous access on the file server

    Targets:

    Hostname IP Offset Role
    www.meridian-energy.corp +10 Corporate website
    mail.meridian-energy.corp +11 Mail server
    files.meridian-energy.corp +12 File server (FTP)

    Your Objectives

    • Discover all live hosts in the DMZ subnet
    • Identify services and software versions on each host
    • Enumerate web directories on the corporate website
    • Access the file server via anonymous FTP
    • Extract sensitive files from backup directories
    • Find and submit the flag in OCR{...} format

    Difficulty: Beginner Estimated time: 30 minutes

    Background: Reconnaissance in a Corporate Environment

    Reconnaissance is the foundation of every penetration test. Before testing for vulnerabilities, you need a complete inventory of the target's attack surface. In a corporate DMZ, you will typically find web servers, mail servers, file transfer services, and sometimes legacy systems that administrators forgot to decommission.

    Energy sector companies often maintain file-sharing infrastructure for exchanging documents with contractors, regulators, and partner firms. These FTP servers frequently allow anonymous access to public directories, and misconfigured servers may expose internal documents, configuration backups, or credential files in those same shares.

    Reconnaissance Workflow

    flowchart LR
    A["Scan Subnet"] --> B["Identify Hosts"]
    B --> C["Enumerate Services"]
    C --> D["Web Directory Scanning"]
    C --> E["FTP Anonymous Access"]
    D --> F["Gather Intelligence"]
    E --> F
    1. Subnet scan - Discover every live host in the target range
    2. Service enumeration - Identify what each host is running and what versions
    3. Web content discovery - Find hidden directories, API endpoints, and sensitive pages
    4. File server access - Check for anonymous or misconfigured access
    5. Intelligence gathering - Collect employee names, email formats, configuration details

    Solution Walkthrough

    Independent Mode

    Want to try this on your own? You have everything you need above. Skip the walkthrough and come back if you get stuck.

    Step 1: Identify Your Network

    After connecting to the VPN, determine your assigned subnet.

    Kali - Check your VPN interface and IP address

    ip addr show tun0

    Look for the inet line on the tun0 interface. Your IP address will be something like 10.x.x.5/24. The first three octets define your subnet. The target servers are at offsets +10, +11, and +12 from the subnet base.

    Step 2: Discover Live Hosts

    Run a ping sweep across the subnet to find all active hosts.

    Kali - Ping sweep the DMZ subnet

    nmap -sn <your_subnet>/24

    The -sn flag performs a ping-only scan without port probing. You should see at least three hosts reported as up (the www, mail, and files servers). Record their IP addresses.

    If any hosts do not respond to ICMP, try a TCP-based discovery:

    Kali - TCP-based host discovery as fallback

    nmap -sn -PS80,21,22,25 <your_subnet>/24

    The -PS flag sends TCP SYN probes to the listed ports. Hosts that respond to any of these ports will be reported as up even if they block ICMP.

    Step 3: Service Version Scan

    Scan all three target hosts for open ports and service versions.

    Kali - Full service version scan of all three targets

    nmap -sV -p- <www_ip> <mail_ip> <files_ip>

    The -sV flag enables version detection and -p- scans all 65,535 TCP ports. For a faster initial pass, you can limit to common ports:

    Kali - Quick scan of common ports

    nmap -sV -p 21,22,25,80,110,143,443 <www_ip> <mail_ip> <files_ip>

    Review the output for each host. You should see:

    • www server (offset +10): HTTP on port 80 (possibly HTTPS on 443)
    • mail server (offset +11): SMTP (25), POP3 (110), IMAP (143)
    • files server (offset +12): FTP (21), SSH (22)

    Note the software names and version numbers. These details feed into vulnerability research in later phases.

    Step 4: Check robots.txt on the Web Server

    Web servers often use robots.txt to tell search engine crawlers which paths to avoid indexing. Penetration testers read this file because it reveals directories the organization wants to keep out of search results, which are often the most interesting targets.

    Kali - Fetch robots.txt from the corporate website

    curl -s http://<www_ip>/robots.txt

    Look for Disallow entries. Each disallowed path is a directory or page the organization does not want publicly indexed. Common findings include admin panels, internal status pages, backup directories, and API documentation.

    Step 5: Enumerate the Corporate Website

    Use gobuster to brute-force directories and files on the web server.

    Kali - Directory brute-force on the corporate website

    gobuster dir -u http://<www_ip>/ -w /usr/share/wordlists/dirb/common.txt -t 20
    Flag Meaning
    dir Directory/file brute-force mode
    -u Target URL
    -w Wordlist file path
    -t 20 Number of concurrent threads

    Review the results for any directories that return HTTP 200 or 301 status codes. Pay special attention to paths like /about/, /internal/, /api/, or /admin/.

    Step 6: Explore the Team Page

    Corporate websites often publish employee directories with names, titles, and email addresses. Look for an "About" or "Team" section.

    Kali - Fetch the team page for employee information

    curl -s http://<www_ip>/about/team

    Read the output carefully. Look for:

    • Employee names and job titles
    • Email address format (e.g., first.last@meridian-energy.corp or f.last@meridian-energy.corp)
    • Department information
    • Any references to internal systems or tools

    Record every name and email address you find. Employee names are critical for building username lists in later credential attacks. The email format tells you how to construct valid addresses for any employee.

    Step 7: Connect to the File Server via FTP

    The file server allows anonymous FTP access. Connect and explore the available directories.

    Kali - Connect to the FTP server with anonymous credentials

    ftp <files_ip>

    When prompted for a username, enter anonymous. When prompted for a password, press Enter (empty password). The server should grant access to the public file area.

    After logging in, list the available directories:

    Kali - List directories on the FTP server

    ls

    You should see directories such as /pub/ and /config-backups/. These are common directory names on corporate FTP servers. The /pub/ directory typically holds documents shared with external partners. The /config-backups/ directory is far more interesting from a security perspective.

    Step 8: Browse the Public Directory

    Kali - Navigate to the public directory and list contents

    cd pub
ls

    Review the files listed. You may find partner documents, regulatory filings, or technical specifications. While these may contain useful intelligence, the primary target is the backup directory.

    Step 9: Extract Configuration Backups

    Navigate to the config-backups directory and download everything.

    Kali - Navigate to config-backups and list files

    cd /config-backups
ls

    Look for configuration files, database dumps, or any file with extensions like .conf, .cfg, .bak, .sql, or .txt. Download suspicious files for analysis:

    Kali - Download a backup configuration file

    get <filename>

    After downloading, exit the FTP session:

    Kali - Exit the FTP session

    bye

    Step 10: Analyze the Backup Files

    Examine the downloaded files on your Kali machine.

    Kali - Read the contents of the downloaded backup file

    cat <filename>

    Look through the file contents for:

    • Database connection strings with embedded credentials
    • API keys or tokens
    • Internal hostnames and IP addresses
    • The flag in OCR{...} format

    The flag is embedded in one of the configuration backup files. Search for it directly if the file is large:

    Kali - Search for the flag pattern in downloaded files

    grep -r "OCR{" .

    The grep -r command recursively searches all files in the current directory for the flag pattern. Once you find it, submit the flag in the platform.

    Analysis Questions

    1. Why is anonymous FTP access on a corporate file server a significant security risk, even if the /pub/ directory contains only public documents?

    Reveal Answer

    Anonymous FTP access creates risk beyond the intended public directory. Administrators may accidentally place sensitive files in accessible paths, as demonstrated by the /config-backups/ directory in this exercise. FTP transmits all data (including credentials for authenticated sessions) in cleartext, making it vulnerable to network sniffing. The presence of an anonymous FTP server also signals to attackers that the organization may have weak access controls elsewhere. A secure alternative is SFTP with certificate-based authentication and strict directory permissions.

    2. What information from the employee team page could an attacker use in later phases of a penetration test?

    Reveal Answer

    Employee names and email addresses enable several attack techniques. The names can be converted into username lists for credential brute-forcing (e.g., k.mitchell, karen.mitchell, kmitchell). The email format reveals the naming convention used across the organization, allowing an attacker to generate valid addresses for any employee. Job titles identify high-value targets: IT administrators likely have privileged access, executives may have weaker security awareness, and HR staff often have access to sensitive personal data. Department information reveals the organizational structure, which helps craft convincing phishing emails.

    3. A configuration backup file on an FTP server contained database credentials. What defensive measures would prevent this exposure?

    Reveal Answer

    Multiple defensive layers should be applied. First, sensitive files like configuration backups should never be stored on servers accessible via anonymous FTP. Access controls should restrict backup directories to authenticated administrators only. Second, credentials should not be stored in plaintext configuration files. Environment variables, secrets management tools (HashiCorp Vault, AWS Secrets Manager), or encrypted configuration stores are safer alternatives. Third, automated scanning tools should check FTP shares for sensitive content on a regular schedule. Fourth, network segmentation should isolate backup infrastructure from DMZ servers entirely.

    Key Takeaways

    • Reconnaissance builds the foundation for every subsequent attack phase. The hosts, services, employee names, and files you discover here feed directly into exploitation attempts.
    • Anonymous FTP is a common misconfiguration in corporate environments. Always check for it during external assessments.
    • Configuration backup files are high-value targets. They frequently contain database credentials, API keys, and internal network details.
    • Employee directories on corporate websites are intelligence goldmines. Names, titles, and email formats enable credential attacks, social engineering, and targeted phishing.
    • Document everything as you go. A thorough penetration tester maintains detailed notes of every finding, even those that seem minor at first.
