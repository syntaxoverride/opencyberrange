    Challenge 12B: Encrypted Exfiltration

    Before You Begin

    Challenge 12B is an unguided reinforcement exercise that builds on Challenge 12 (Post-Exploitation Data Harvest). Complete that exercise first. Your VPN must be connected and your terminal ready.

    Scenario

    Obsidian Analytics, a data science consulting firm in Portland, Oregon, has been compromised. Your red team achieved root access on their primary server. The post-exploitation objective is to demonstrate the real-world impact of the compromise by locating and extracting data that has been concealed using multiple encoding and encryption techniques.

    Elise Nakamura (Incident Response Manager) set the rules for the assessment: "We intentionally hid data using three different methods; base64 encoding, GPG symmetric encryption, and hex encoding. If your team can find and decode all three, we know our detection capabilities need work."

    Three assessment tokens are hidden using different concealment techniques. You must locate each one, determine the encoding/encryption method, and decode them.

    Credentials: operator / 0bs1d14n_0ps# (has sudo access)

    Your Objectives

    • SSH to the target server with provided credentials
    • Search the filesystem for encoded or encrypted files
    • Identify the encoding/encryption method for each concealed file
    • Decode base64-encoded data
    • Locate the encryption passphrase and decrypt GPG-encrypted data
    • Decode hex-encoded data
    • Assemble and submit the flag

    Key Takeaways

    • Encoding is not encryption: base64 and hex are trivially reversible without a key. GPG symmetric encryption requires a passphrase but is only as strong as the passphrase itself.
    • Shell history files (.bash_history, .python_history, .mysql_history) frequently contain passwords, passphrases, and command-line credentials in plaintext.
    • Hidden files (dotfiles) are a common concealment technique; find / -name ".*" -type f reveals files that ls hides by default.
