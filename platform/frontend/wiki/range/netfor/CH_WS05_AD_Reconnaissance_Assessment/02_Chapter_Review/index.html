    Chapter WS05: Review

    Windows Server Track Complete

    Over five chapters and nineteen labs, you progressed from basic port scanning and DNS lookups to a full Active Directory (AD) reconnaissance assessment. Each chapter introduced a new discipline; initial discovery, directory enumeration, DNS infrastructure analysis, authenticated service analysis, and finally the capstone that combined all four. The Windows Server track has equipped you with a repeatable methodology for mapping AD environments using only standard reconnaissance tools.

    The progression followed a deliberate learning curve. Early labs provided exact commands and expected output. Later labs required you to select the right tool and construct queries based on your findings. The capstone assessment removed step-by-step guidance entirely, testing whether you could apply the full methodology independently.

    What You Learned at Each Level

    Level 1; Initial Reconnaissance (WS01) introduced the foundational tools and techniques. You learned to scan ports with Nmap, resolve hostnames with dig, perform reverse DNS (Domain Name System) lookups, list SMB (Server Message Block) shares anonymously, and query LDAP (Lightweight Directory Access Protocol) without credentials. Every technique in Levels 2 through 5 builds on the skills from Level 1.

    Level 2; LDAP Deep Dive (WS02) explored the AD directory structure in depth. You enumerated Organizational Units (OUs), discovered user accounts and their attributes, mapped group memberships, listed computer objects, and extracted password policy settings. Level 2 demonstrated that LDAP exposes the full directory tree to any user who can bind to the service.

    Level 3; DNS Infrastructure (WS03) moved beyond basic lookups into infrastructure-level DNS analysis. You queried SRV records to locate domain controllers and services, discovered conditional forwarders that reveal trust relationships, analyzed DHCP (Dynamic Host Configuration Protocol) scopes for network layout, and mapped the network topology from DNS data alone. Level 3 showed that DNS is not merely a name resolution service; it is an infrastructure map.

    Level 4; Authenticated Analysis (WS04) introduced credential-based techniques. You accessed SMB shares that require authentication, enumerated Group Policy Objects (GPOs) and their settings, discovered Service Principal Names (SPNs) that identify service accounts, and analyzed Access Control Lists (ACLs) to understand permission structures. Level 4 demonstrated the gap between anonymous and authenticated access.

    Level 5; Capstone Assessment (WS05) combined all four disciplines into a single assessment. You applied DNS, LDAP, SMB, and GPO techniques independently to locate flag parts scattered across different data sources. The capstone tested technical skill and methodology alike; the ability to plan, execute, and document a thorough assessment without step-by-step guidance.

    Comprehensive Command Reference

    The table below covers every key command used across the five chapters of the Windows Server track. Keep the reference available during future assessments and engagements.

    DNS Commands

    Command What It Does
    dig A <hostname> @<dns_server> Forward lookup; resolve hostname to IPv4 address
    dig -x <ip_address> @<dns_server> Reverse lookup; resolve IP address to hostname (PTR record)
    dig SRV _ldap._tcp.<domain> @<dns_server> Query SRV record for LDAP service locations
    dig SRV _kerberos._tcp.<domain> @<dns_server> Query SRV record for Kerberos KDC locations
    dig SRV _gc._tcp.<domain> @<dns_server> Query SRV record for Global Catalog servers
    dig TXT <hostname> @<dns_server> Query TXT records for metadata and verification strings
    dig AXFR <domain> @<dns_server> Attempt a full zone transfer
    nslookup -type=SRV _ldap._tcp.<domain> Alternative SRV lookup using nslookup

    LDAP Commands

    Command What It Does
    ldapsearch -x -H ldap://<host> -s base namingContexts Discover the base DN from the root DSE
    ldapsearch -x -H ldap://<host> -b <base_dn> "(objectClass=organizationalUnit)" dn Enumerate all OUs in the domain
    ldapsearch -x -H ldap://<host> -b <base_dn> "(objectClass=user)" sAMAccountName List all user account names
    ldapsearch -x -H ldap://<host> -b <base_dn> "(objectClass=group)" cn description List all groups with descriptions
    ldapsearch -x -H ldap://<host> -b <base_dn> "(objectClass=computer)" cn operatingSystem List all computer objects with OS info
    ldapsearch -x -H ldap://<host> -b <ou_dn> "(sAMAccountName=<user>)" "*" Retrieve all attributes for a specific user
    ldapsearch -x -H ldap://<host> -b <base_dn> "(objectClass=*)" pwdPolicySubentry Query password policy attributes

    SMB Commands

    Command What It Does
    smbclient -L //<host> -N List shares using a null session
    smbclient -L //<host> -U 'user%pass' List shares with authenticated credentials
    smbclient //<host>/<share> -N Connect to a share using a null session
    smbclient //<host>/<share> -U 'user%pass' Connect to a share with credentials
    smbclient //<host>/<share> -U 'user%pass' -c 'ls' List share contents non-interactively
    smbclient //<host>/<share> -U 'user%pass' -c 'get <file> -' Retrieve a file and print to stdout
    smbclient //<host>/SYSVOL -U 'user%pass' -c 'recurse ON; ls' Recursively list SYSVOL contents
    smbmap -H <host> Map anonymous share permissions
    smbmap -H <host> -u <user> -p <pass> Map authenticated share permissions

    nmap -sV -sC <target> Service version scan with default NSE scripts
    nmap -p 53,88,135,139,389,445,636,3268 <target> Scan common AD service ports
    enum4linux -a <target> Full SMB/RPC enumeration

    Self-Assessment Answer Key

    1. dig SRV _ldap._tcp.corp.ocr-range.lab @dc01: the SRV record type is specified after dig, and the service name follows the _service._protocol.domain convention.

    2. ldapsearch -x -H ldap://dc01 -b "DC=corp,DC=ocr-range,DC=lab" "(objectClass=organizationalUnit)" dn: the -x flag uses simple authentication (anonymous bind), -b sets the search base, and the filter matches only OU objects.

    3. A null session sends an empty username and empty password to the SMB server. A guest session authenticates as the built-in guest account. Both bypass normal credential requirements, but they rely on different server-side configurations; null sessions require anonymous access to be enabled, while guest sessions require the guest account to be active or the map to guest setting to redirect failed logins.

    4. ldapsearch -x -H ldap://dc01 -b "OU=Flags,DC=corp,DC=ocr-range,DC=lab" "(sAMAccountName=assess.flag)" info: the search base is narrowed to the Flags OU, the filter matches the specific user, and info limits the output to that attribute.

    5. The _kerberos._tcp SRV record identifies the hostname and port of the Kerberos Key Distribution Center (KDC) in the domain. The KDC handles authentication ticket requests for domain-joined systems. The record confirms that Kerberos authentication is active and reveals which server handles authentication; information that is valuable for both reconnaissance and later attack phases like Kerberoasting.

    6. smbclient //<host>/<share> -U 'user%pass' -c 'ls': the -c flag passes a command to smbclient for non-interactive execution. The ls command lists directory contents and smbclient exits after completing the command.

    7. SYSVOL is readable by all authenticated domain users because domain-joined computers need to download GPO settings and logon scripts during startup and login. The security risk is that any authenticated user; including compromised low-privilege accounts; can browse GPO templates, read logon scripts (which may contain hardcoded credentials), and examine policy settings that reveal the domain's security configuration.

    8. The info attribute stores freeform text and is readable by default by all authenticated users. Administrators sometimes use the field for internal notes, password hints, or configuration details without realizing that the content is visible to every domain user. The attribute is a security concern because no default ACL restricts read access, making it a common source of information disclosure in AD environments.

    9. Three useful DNS record types for AD reconnaissance: (1) A records map hostnames to IP addresses, revealing the network location of servers. (2) SRV records identify specific services and the servers hosting them, exposing domain controllers, KDCs, and Global Catalog servers. (3) TXT records contain freeform text strings, sometimes holding SPF configurations, domain verification tokens, or custom metadata that reveals organizational details.

    10. A complete AD reconnaissance methodology: (1) DNS Reconnaissance using dig: discover hostnames, IP addresses, SRV records, and service locations. (2) LDAP Enumeration using ldapsearch: map the directory tree including OUs, users, groups, computers, and attributes. (3) SMB Analysis using smbclient and smbmap: test anonymous and authenticated share access, retrieve files, and map permissions. (4) GPO Review using smbclient against SYSVOL; examine group policy configurations, scripts, and security settings.

    What Comes Next

    The Windows Server track has given you a complete methodology for AD reconnaissance. The skills you built translate directly into several professional paths and certification objectives.

    Real-World Applications

    Penetration Testing Engagements follow the same methodology you practiced in the capstone assessment. Professional pentesters begin every internal engagement with DNS reconnaissance, LDAP enumeration, and SMB analysis before attempting exploitation. The tools and techniques from the Windows Server track; dig, ldapsearch, smbclient, smbmap: appear in virtually every internal network assessment.

    Security Auditing and Compliance requires the same enumeration techniques applied defensively. Security teams use LDAP queries to audit user attributes for sensitive data, SMB permission mapping to verify share access controls, and GPO review to confirm that security policies are applied correctly. The difference between an attacker and an auditor is intent; the techniques are identical.

    Incident Response benefits from rapid AD enumeration during containment. When a domain account is compromised, responders need to quickly determine what the account can access; which shares, which systems, which group memberships. The LDAP and SMB techniques from the track enable fast scoping of a compromised account's reach.

    Further Study

    Active Directory attack paths extend beyond reconnaissance into exploitation techniques like Kerberoasting, AS-REP roasting, delegation abuse, and credential relay attacks. The SPN discovery skills from WS04 provide the foundation for Kerberoasting; the next logical step after reconnaissance.

    BloodHound and SharpHound automate AD relationship mapping by collecting user, group, computer, and ACL data into a graph database. The manual enumeration techniques from the track help you understand what BloodHound collects and how to interpret its output.

    PowerShell-based AD enumeration using modules like ActiveDirectory and PowerView provides Windows-native alternatives to the Linux tools used in the track. Many professional engagements require both Linux and Windows tooling, and understanding both approaches makes you effective in any environment.

    Cloud and hybrid environments extend AD into Azure AD (now Entra ID), where directory enumeration techniques adapt to REST APIs and OAuth tokens rather than LDAP and SMB. The conceptual framework; enumerate users, groups, permissions, and policies; remains the same even when the protocols change.
